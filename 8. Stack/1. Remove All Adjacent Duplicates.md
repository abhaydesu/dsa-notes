## Problem: Remove All Adjacent Duplicates in String (LeetCode 1047)

**Problem Statement:** You are given a string `s` consisting of lowercase English letters. A **duplicate removal** consists of choosing two adjacent and equal letters and removing them. We repeatedly make duplicate removals on `s` until we no longer can. Return the final string after all such duplicate removals have been made.

**Example:**

- `Input: s = "abbaca"`
- `Output: "ca"`
- _Explanation:_
    1. Remove `bb` $\rightarrow$ String becomes `"aaca"`.
    2. Now, the two `a`s are adjacent. Remove `aa` $\rightarrow$ String becomes `"ca"`.
    3. No more adjacent duplicates exist.

### Why does a simple `for` loop fail?

If you just use a `for` loop and check `if s[i] == s[i-1]`, it fails because of the cascading nature of the deletions.

When you delete `bb` in `"abbaca"`, the character `a` at index 0 and the character `a` at index 3 suddenly become adjacent. Your standard `for` loop pointer `i` has already moved past index 0. It has no way of knowing that a gap opened up behind it and that it needs to re-evaluate previously seen characters against current characters.

## The Stack Intuition (The "Pocket" Analogy)

You are evaluating items (characters) one by one from left to right.

Imagine you have a **pocket** (the Stack).

- You look at a character. You must compare it to the character sitting at the very top of your pocket.
- **Why?** Because the character at the top of your pocket is the _last character you decided to keep_. It doesn't matter how many characters you skipped, deleted, or threw away previously; the only thing that matters is what is currently at the top of the pocket.

### The Decision Matrix for Every Item

For every incoming character, you must make two strict decisions:

1. **Does this item force me to throw away items currently in my pocket?**
    - _Condition:_ If the incoming item matches the item at the top of the pocket, they form an adjacent duplicate pair.
    - _Action:_ You must throw away the item at the top of your pocket (`pop()`).
2. **Do I keep this incoming item and put it in my pocket?**
    - _Condition A:_ If the incoming item triggered a deletion (it matched the top of the pocket), both items are destroyed. You **do not** keep the incoming item.
    - _Condition B:_ If the incoming item did _not_ match, or the pocket is empty, you keep it. You put it in your pocket (`push()`).

## Pseudo-code: Remove Adjacent Duplicates

```cpp
function removeDuplicates(s):
    n = length of s
    st = empty Stack of Characters
    
    // Process items Left to Right
    for i = 0 to n - 1:
        current_char = s[i]
        
        // Edge Case: If the stack is completely empty, 
        // there is nothing to compare against. Just keep the item.
        if st is empty:
            st.push(current_char)
            continue
            
        // DECISION 1: Does this item force me to throw away the top item?
        if st.top() == current_char:
            // Yes. They are a pair. Throw the top item away.
            st.pop()
            
            // DECISION 2a: Do I keep the incoming item?
            // No. It was destroyed in the pairing. Move to the next character.
            continue
            
        // DECISION 2b: Do I keep the incoming item?
        // If we reach here, it didn't match the top. Keep it.
        st.push(current_char)
        
    // Build the final string from the remaining items in the stack
    result = ""
    while st is not empty:
        result = result + st.top()
        st.pop()
        
    // CRITICAL: The stack yields items in LIFO order (reversed). 
    // We must reverse the result string to restore original order.
    return reverse(result)
```

## Complexity Analysis

- **Time Complexity:** $O(N)$. We iterate through the string exactly once. Each character is pushed onto the stack at most once and popped at most once. Building and reversing the final string takes another $O(N)$ operations. Overall, it is strictly linear time.
- **Space Complexity:** $O(N)$. In the worst-case scenario (e.g., `"abcdef"` where there are no duplicates), every character is pushed onto the stack, requiring $O(N)$ auxiliary space.

## Active Recall

**Q: Why does a standard Array traversal (`i` and `i-1` checking) fail for the "Remove Adjacent Duplicates" problem?**

**A:** Standard traversal assumes the physical neighbors in the array remain constant. When an adjacent pair is deleted, characters that were previously separated by the deleted pair instantly become adjacent. A standard loop pointer moving strictly forward cannot dynamically look backwards to re-evaluate elements that have suddenly become neighbors.

**Q: Conceptually, what does the element at the `top()` of the stack represent in this problem?**

**A:** It represents the **"Most Recently Kept Item"**. It is the last valid character that survived all previous deletion checks and is waiting to be compared against the next incoming character.

**Q: When an incoming character matches the character at the top of the stack, why do we `pop()` the stack and _not_ `push()` the incoming character?**

**A:** The problem requires removing adjacent duplicates in _pairs_. When a match is found, the character inside the stack and the incoming character annihilate each other. Popping removes the first half of the pair from our "kept" items, and choosing _not_ to push destroys the second half (the incoming character).

**Q: Why must you reverse the string built from popping the final stack?**

**A:** Stacks operate on a Last-In-First-Out (LIFO) principle. The character sitting at the `top()` of the stack was the _last_ character of the final string to be processed. Popping the stack retrieves the string backwards, so it must be reversed to restore the correct chronological order.
