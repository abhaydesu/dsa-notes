> This lecture continues the exploration of the **Two-Pointer technique**. The primary problem discussed is "Squares of a Sorted Array" (LeetCode #977). The instructor explains how a seemingly simple array problem can be broken down into merging two sorted arrays to achieve an optimal $O(N)$ time complexity, completely bypassing the need for a sorting function.

## Problem Statement

You are given an integer array sorted in non-decreasing order. Your task is to:

1. Square each number in the array.
    
2. Return a new array containing the squares of the numbers, also sorted in non-decreasing order.
    

**Example:**

- **Input:** `nums = [-4, -1, 0, 3, 10]`
    
- **Expected Output:** `[0, 1, 9, 16, 100]`
    

## Approach 1: Brute Force (Square and Sort)

The most intuitive approach is to perform exactly what the problem description states.

### Logic

1. Iterate through the array and square every single element in-place (or into a new array).
    
2. Because squaring negative numbers can result in large positive numbers (e.g., $(-4)^2 = 16$), the array will lose its sorted order.
    
3. Use an inbuilt sorting function to sort the newly squared array.
    

### Pseudo-code: Brute Force

Plaintext

```
function sortedSquaresBruteForce(arr):
    n = length of arr
    
    // Step 1: Square every element
    for i = 0 to n - 1:
        arr[i] = arr[i] * arr[i]
        
    // Step 2: Sort the array
    sort(arr)
    
    return arr
```

### Complexity Analysis

- **Time Complexity:** $O(N \log N)$. Squaring the array takes $O(N)$, and sorting takes $O(N \log N)$. The maximum of the two is $O(N \log N)$.
    
- **Space Complexity:** $O(1)$ or $O(N)$ depending on whether the sorting algorithm is in-place and if a new array is created.
    

_Note: While acceptable for a basic solution, interviewers will ask for an $O(N)$ follow-up solution._

## Foundational Concept: Merge Two Sorted Arrays

To solve this problem optimally in $O(N)$ time, the instructor introduces a prerequisite concept: **Merging two sorted arrays**.

If you have two arrays (e.g., `A = [1, 3, 5]` and `B = [2, 4, 6]`), how do you combine them into a single sorted array `[1, 2, 3, 4, 5, 6]` without using a sort function?

### Logic (Two Pointers)

1. Place a pointer `i` at the start of array `A` and pointer `j` at the start of array `B`.
    
2. Compare `A[i]` and `B[j]`.
    
3. Take the smaller of the two elements, push it into a new Result array, and move the pointer of the array from which the element was taken.
    
4. Continue until one array is completely exhausted.
    
5. Append any remaining elements from the non-exhausted array to the Result array.
    

### Pseudo-code: Merge Two Sorted Arrays

Plaintext

```
function mergeSortedArrays(A, B):
    n = length of A
    m = length of B
    result = array of size (n + m)
    
    i = 0, j = 0, index = 0
    
    // Compare elements while both arrays have items
    while i < n and j < m:
        if A[i] <= B[j]:
            result[index] = A[i]
            i = i + 1
        else:
            result[index] = B[j]
            j = j + 1
        index = index + 1
        
    // Handle remaining elements in A (if any)
    while i < n:
        result[index] = A[i]
        i = i + 1
        index = index + 1
        
    // Handle remaining elements in B (if any)
    while j < m:
        result[index] = B[j]
        j = j + 1
        index = index + 1
        
    return result
```

- **Time Complexity for Merging:** $O(N + M)$, which is strictly linear.
    

## Approach 2: Optimal Solution (Two Pointers)

Now, applying the merge concept to the "Squares of a Sorted Array" problem.

### Core Observation

When you split the original array into negative numbers and positive numbers:

- Squaring the **positive** numbers yields an array that is **already sorted in ascending order**.
    
- Squaring the **negative** numbers yields an array that is **sorted in descending order** (because the largest negative number becomes the smallest positive square, and the smallest negative number becomes the largest positive square).
    

### Logic

1. Split the original array into a `negative_arr` and a `positive_arr`.
    
2. Square the elements in both arrays.
    
3. **Reverse** the `negative_arr` so that it is now in ascending order.
    
4. You now have two distinct, sorted arrays. Merge them using the Two-Pointer technique described above.
    

_(External Note: An alternative $O(N)$ approach compares elements from the very beginning and very end of the original array, filling the result array backwards. The instructor's method of splitting and merging is conceptually easier to connect with the "Merge Sorted Arrays" pattern.)_

### Pseudo-code: Optimal Two-Pointer

Plaintext

```
function sortedSquaresOptimal(arr):
    n = length of arr
    negative_arr = empty list
    positive_arr = empty list
    
    // Step 1: Split negative and positive elements
    for i = 0 to n - 1:
        if arr[i] < 0:
            negative_arr.append(arr[i])
        else:
            positive_arr.append(arr[i])
            
    // Edge case: All positives
    if length of negative_arr == 0:
        for i = 0 to n - 1:
            arr[i] = arr[i] * arr[i]
        return arr
        
    // Edge case: All negatives
    if length of positive_arr == 0:
        for i = 0 to n - 1:
            arr[i] = arr[i] * arr[i]
        reverse(arr)
        return arr
        
    // Step 2: Square both lists
    for i = 0 to length of negative_arr - 1:
        negative_arr[i] = negative_arr[i] * negative_arr[i]
        
    for i = 0 to length of positive_arr - 1:
        positive_arr[i] = positive_arr[i] * positive_arr[i]
        
    // Step 3: Reverse the negative array so it is ascending
    reverse(negative_arr)
    
    // Step 4: Merge the two sorted arrays
    return mergeSortedArrays(negative_arr, positive_arr)
```

### Complexity Analysis

- **Time Complexity:** $O(N)$. Splitting, squaring, reversing, and merging all require independent linear passes. The maximum complexity is $O(N)$.
    
- **Space Complexity:** $O(N)$. We create auxiliary arrays for the negatives, positives, and the final merged result.
    

## Active Recall

**Q: Why does the brute force approach for "Squares of a Sorted Array" result in an $O(N \log N)$ time complexity?**

**A:** The brute force approach squares the elements in $O(N)$ time but relies on an external sorting function to reorder the array, which takes $O(N \log N)$ time. The maximum of these independent operations dictates the overall complexity.

**Q: What happens to the sorted order of an array of strictly negative numbers (e.g., `[-4, -3, -2]`) when each element is squared?**

**A:** Squaring them yields `[16, 9, 4]`. The resulting values are sorted in descending (reverse) order.

**Q: In the optimal $O(N)$ approach, how do we transform the original problem into a "Merge Two Sorted Arrays" problem?**

**A:** We separate the negative and positive numbers into two lists. We square both lists, reverse the list of squared negative numbers (to make it ascending), and then use the Two-Pointer technique to merge the two now-ascending sorted lists into a single result array.

**Q: In the "Merge Two Sorted Arrays" algorithm, what happens when one pointer reaches the end of its array before the other pointer does?**

**A:** The main comparison loop terminates. You must then use a secondary loop to append all remaining elements from the non-exhausted array directly into the result array, as they are already sorted and strictly greater than the elements merged so far.
