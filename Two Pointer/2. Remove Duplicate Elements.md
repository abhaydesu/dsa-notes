## Problem Statement

You are given an integer array sorted in non-decreasing order. Your task is to:

1. **Remove the duplicates in-place** so that each unique element appears only once.
2. Keep the **relative order** of the elements identical.
3. Return the total number of unique elements.
4. **Constraint:** You must achieve this with $O(1)$ extra space (in-place modification).

**Example:**

- **Input:** `arr = [1, 1, 2, 2, 3, 3]`
- **Required Array State:** `[1, 2, 3, _, _, _]` (The elements after the unique elements do not matter).
- **Return Value:** `3` (Since there are three unique elements).

## Pattern Identification: Why Two Pointers?

Before jumping into the solution, the instructor uses a logical checklist to identify which pattern fits the problem.

1. **Data Structure:** Array.
2. **State:** The array is **Sorted**. _(External Note: Sorting groups duplicates consecutively, meaning `arr[i]` will only be a duplicate if it equals `arr[i-1]`.)_
3. **Goal:** Remove duplicates / Rearrange elements.
4. **Constraint:** $O(1)$ Space (In-place modification).

When you see a combination of **Array + Sorted + In-Place Modification**, it is an 80% to 90% guarantee that the **Two-Pointer Technique** is the optimal approach.

## Approach 1: Brute Force (Using Extra Space)

While the problem strictly asks for an in-place solution, it is always best practice in interviews to explain the brute force method first.

### Logic (External Knowledge Integration)

Since we need to filter unique elements, the easiest data structure to use is a **Set** (or grouping items in separate auxiliary arrays, as the instructor's analogy implies).

1. Iterate through the array and place all elements into an ordered Set (which naturally rejects duplicates).
2. Iterate through the Set and overwrite the beginning of the original array with the unique values.

### Pseudo-code: Brute Force

```cpp
int removeDuplicatesBruteForce(vector<int>& arr) {
    int n = arr.size();

    if (n == 0) {
        return 0;
    }

    // Step 1: Store unique elements in an ordered set
    set<int> uniqueElements;

    for (int i = 0; i < n; i++) {
        uniqueElements.insert(arr[i]);
    }

    // Step 2: Copy unique elements back to the original array
    int index = 0;

    for (int element : uniqueElements) {
        arr[index] = element;
        index++;
    }

    // Returns the number of unique elements
    return index;
}
```

- **Time Complexity:** $O(N \log N)$ if using a standard set (due to insertion time), or $O(N)$ with a Hash Set.
- **Space Complexity:** $O(N)$ to store the unique elements in the Set data structure. (Fails the $O(1)$ space requirement).

## Approach 2: Optimal Solution - Two Pointers Technique

To solve this without extra space, we utilize two pointers. The instructor explains this beautifully using a real-world analogy.

### The "CM and Officer" Analogy

Imagine you are the Chief Minister (CM) allocating houses to different communities, but you only have a limited number of "premium" houses at the start of the row. You instruct an Officer to guard the houses that have already been allocated.

- **Pointer 1 (`Officer` / Slow Pointer):** Points to the last index where a unique element was successfully placed.
- **Pointer 2 (`CM` / Fast Pointer):** Scans through the array searching for the _next_ unique element.

### Step-by-Step Logic

1. **The First Element is Always Unique:** The element at `index 0` is naturally the first of its kind. So, we place the `Officer` at `index 0` (house allocated).
2. **Scan the Array:** The `CM` starts checking from `index 1` onwards.
3. **Check for Duplicates:** Because the array is _sorted_, duplicates always sit right next to each other.
    - **Rule:** If `arr[CM] == arr[CM - 1]`, the current element is a duplicate. The `CM` ignores it and moves to the next element.
4. **Allocate House to Unique Element:**
    - If `arr[CM] != arr[CM - 1]`, a new unique element has been found.
    - Place this new unique element in the empty slot right after the Officer (`Officer + 1`).
    - Move the Officer up by one space.
    - Increment the total count of unique elements found so far.

### Pseudo-code: Optimal Two-Pointer

```cpp
int removeDuplicatesOptimal(vector<int>& arr) {
    int n = arr.size();

    if (n == 0) {
        return 0;
    }

    int officer = 0;      // Slow pointer: tracks placement of unique elements
    int uniqueCount = 1;  // The first element is always unique
    int cm = 1;           // Fast pointer: scans for new unique elements

    while (cm < n) {
        // If current element matches the previous one, it's a duplicate
        if (arr[cm] == arr[cm - 1]) {
            cm++;
            continue;
        }

        // Found a unique element; place it after the officer
        arr[officer + 1] = arr[cm];

        officer++;      // Move officer to the newly filled position
        uniqueCount++;  // Increment the count of unique elements
        cm++;           // Continue scanning
    }

    // Returns the number of unique elements
    return uniqueCount;
}
```
## Complexity Analysis

|**Approach**|**Time Complexity**|**Space Complexity**|**Notes**|
|---|---|---|---|
|**Brute Force**|$O(N)$ or $O(N \log N)$|$O(N)$|Requires a Hash Set or secondary array, failing constraints.|
|**Two Pointer**|$O(N)$|$O(1)$|Optimal. A single pass is made through the array, editing in-place.|

## Active Recall

**Q: What are the three key indicators in a problem description that strongly suggest using a Two-Pointer technique?**
**A:** The problem involves an Array, the array is Sorted, and there's a constraint to modify it in-place ($O(1)$ extra space).

**Q: In the optimal Two-Pointer approach for removing duplicates, what is the core logic for identifying a duplicate?**
**A:** Because the array is sorted, any element `arr[i]` that is identical to its immediate predecessor `arr[i - 1]` is a duplicate.

**Q: In the Two-Pointer setup, what do the "Slow Pointer" (Officer) and "Fast Pointer" (CM) represent?**
**A:** The Slow Pointer marks the index of the last confirmed unique element that has been correctly placed. The Fast Pointer scans ahead through the array to find the next unique element.

**Q: How do you determine the overall time complexity of an algorithm that performs multiple independent steps sequentially (e.g., $O(N \log N)$ then $O(N)$ then $O(N^2)$)?**
**A:** You take the maximum complexity among the independent steps, rather than summing them. In the given example, the overall time complexity would be $O(N^2)$.
