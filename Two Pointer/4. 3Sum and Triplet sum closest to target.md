## Problem 1: Triplet Sum to Zero (3Sum)

You are given an integer array. You need to find all **unique** triplets (three numbers) `[a, b, c]` such that their sum is exactly `0`.

**Conditions:**

- $a + b + c = 0$
    
- The output must not contain duplicate triplets (e.g., `[-1, 0, 1]` and `[0, 1, -1]` are considered the same).
    

### 🔍 Pattern Identification: Why Two Pointers?

- **Data Structure:** Array.
    
- **Goal:** Find more than one thing (a triplet/pair).
    
- **State:** While not initially sorted, sorting it makes it trivial to navigate combinations using pointers and easily skip duplicates.
    

### Logic (From Brute Force to Optimal)

1. **Brute Force:** Use three nested loops (`i`, `j`, `k`) to check every combination. Time complexity: $O(N^3)$.
    
2. **Optimization (The "Two Sum" Connection):**
    
    If we fix one number `a` (using loop `i`), we are essentially looking for two other numbers `b` and `c` such that:
    
    $b + c = -a$
    
    This transforms the "3Sum" problem into a **Two Sum** problem for the remaining array!
    

### Core Algorithm (Optimal Two-Pointer)

1. **Sort the array.** (Crucial for the Two-Pointer technique and duplicate skipping).
    
2. Loop `i` through the array from `0` to `n-3` (we stop at `n-3` because we need at least two more elements for the `left` and `right` pointers).
    
3. **Skip Duplicates for `i`:** If `arr[i] == arr[i-1]`, skip this iteration to avoid duplicate triplets.
    
4. Set up Two Pointers:
    
    - `left = i + 1`
        
    - `right = n - 1`
        
    - Target for Two Sum = `-arr[i]`
        
5. **Two Sum Logic inside the loop:**
    
    - If `arr[left] + arr[right] == Target`:
        
        - Store the triplet.
            
        - Increment `left` and decrement `right`.
            
        - **Skip Duplicates for `left` and `right`:** Keep moving `left` forward if `arr[left] == arr[left-1]`. Keep moving `right` backward if `arr[right] == arr[right+1]`.
            
    - If the sum is `< Target`: Increment `left`.
        
    - If the sum is `> Target`: Decrement `right`.
        

### Pseudo-code: 3Sum

Plaintext

```
function threeSum(arr):
    n = length of arr
    result = empty list
    
    sort(arr)
    
    for i = 0 to n - 3:
        // Skip duplicates for the first element
        if i > 0 and arr[i] == arr[i - 1]:
            continue
            
        target = -arr[i]
        left = i + 1
        right = n - 1
        
        while left < right:
            current_sum = arr[left] + arr[right]
            
            if current_sum == target:
                result.append([arr[i], arr[left], arr[right]])
                left = left + 1
                right = right - 1
                
                // Skip duplicates for the left pointer
                while left < right and arr[left] == arr[left - 1]:
                    left = left + 1
                    
                // Skip duplicates for the right pointer
                while left < right and arr[right] == arr[right + 1]:
                    right = right - 1
                    
            else if current_sum < target:
                left = left + 1
            else:
                right = right - 1
                
    return result
```

### Complexity Analysis

- **Time Complexity:** $O(N^2)$. Sorting takes $O(N \log N)$. The outer loop runs $O(N)$ times, and the inner Two-Pointer loop takes $O(N)$ time per iteration. The maximum of these is $O(N^2)$.
    
- **Space Complexity:** $O(1)$ auxiliary space (ignoring the space required for the output array).
## Problem 2: Triplet Sum Closest to Target (3Sum Closest)

Given an integer array and a `target`, find three integers in the array such that their sum is closest to the `target`. Return the sum of the three integers.

_(Note: The problem assumes there will be exactly one unique closest solution, so duplicate handling is not required)._

### Logic

The core logic is identical to standard 3Sum. We loop through the array, fix `i`, and use Two Pointers (`left` and `right`) to evaluate the sum.

The only difference is that instead of only caring about exact matches, we constantly measure the **Absolute Difference** between our `current_sum` and the `target`. We keep track of the smallest difference we have seen so far and the sum that produced it.

1. Track `min_diff` (initialized to infinity) and `closest_sum`.
    
2. Inside the Two-Pointer loop, calculate `current_sum = arr[i] + arr[left] + arr[right]`.
    
3. Calculate `diff = absolute(current_sum - target)`.
    
4. If `diff < min_diff`, update `min_diff` and `closest_sum`.
    
5. If `current_sum == target`, the best possible difference is 0, so just return `current_sum` immediately.
    
6. Advance pointers exactly like standard 3Sum based on whether `current_sum` is greater or smaller than `target`.
    

### Pseudo-code: 3Sum Closest

Plaintext

```
function threeSumClosest(arr, target):
    n = length of arr
    sort(arr)
    
    min_diff = infinity
    closest_sum = 0
    
    for i = 0 to n - 3:
        left = i + 1
        right = n - 1
        
        while left < right:
            current_sum = arr[i] + arr[left] + arr[right]
            diff = absolute(current_sum - target)
            
            // Record the closest sum found so far
            if diff < min_diff:
                min_diff = diff
                closest_sum = current_sum
                
            // Evaluate Two Pointer movement
            if current_sum == target:
                return current_sum // Best possible answer
            else if current_sum < target:
                left = left + 1
            else:
                right = right - 1
                
    return closest_sum
```

### Complexity Analysis

- **Time Complexity:** $O(N^2)$. Same as standard 3Sum.
    
- **Space Complexity:** $O(1)$.
    

## Active Recall

**Q: How does the "3Sum" problem logically reduce to the "Two Sum" problem?**

**A:** By fixing one element `a` using a loop, finding the remaining two elements `b` and `c` becomes a Two Sum problem where the target sum is simply `-a`.

**Q: In the 3Sum optimal approach, why must the array be sorted first?**

**A:** Sorting is required for two reasons: 1) It allows the use of the Two-Pointer technique (moving left if the sum is too small, moving right if too large). 2) It naturally groups identical numbers together, making it trivial to skip duplicate values and ensure unique triplet combinations.

**Q: If `arr[left] + arr[right] == target` in the 3Sum problem, why is it mandatory to increment `left` AND decrement `right`?**

**A:** If you only move one pointer, say `left`, the new `left` value would have to combine with the same `right` value to equal the target. This would mean the new `left` value is identical to the old `left` value, creating a duplicate triplet. Moving both forces the search for an entirely new valid pair.

**Q: In the 3Sum Closest problem, how is the "closest" sum mathematically determined?**

**A:** By calculating the absolute difference between the current sum of the three pointers and the target (`abs(current_sum - target)`). The sum that produces the smallest absolute difference is the closest.
