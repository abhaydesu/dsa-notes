## Problem 1: Triplets with Smaller Sum

You are given an array of distinct integers and a target sum. You need to find the **number of triplets** $(i, j, k)$ such that $i < j < k$ and `arr[i] + arr[j] + arr[k] < target`.

**Example:**

- **Input:** `arr = [-2, 0, 1, 3]`, `target = 2`
    
- **Output:** `2` (Triplets are `[-2, 0, 1]` and `[-2, 0, 3]`)
    

### Logic and Modification of 3Sum

Since this is a triplet sum problem, we use the same base structure as the standard 3Sum:

1. Sort the array.
    
2. Iterate `i` from `0` to `n-2`.
    
3. Fix `left = i + 1` and `right = n - 1`.
    

**The Twist:**

Instead of checking for `sum == target`, we care about `sum < target`.

- If `sum >= target`: The sum is too big (or equal, which we don't want). Since the array is sorted, we must decrement `right` to reduce the sum.
    
- If `sum < target`: We found a valid triplet (`arr[i]`, `arr[left]`, `arr[right]`).
    

**Crucial Observation (Counting logic):**

If `arr[i] + arr[left] + arr[right] < target`, then substituting `arr[right]` with _any_ element between `left` and `right` will also result in a sum strictly less than the target (because the array is sorted, so all elements to the left of `right` are smaller).

Therefore, we don't just increment our count by 1. We increment our count by `right - left`. After adding this to our answer, we increment `left` to check the next set of combinations.

### Pseudo-code: Triplets with Smaller Sum

Plaintext

```
function tripletSmallerSum(arr, target):
    n = length of arr
    sort(arr)
    
    count = 0
    
    for i = 0 to n - 2:
        left = i + 1
        right = n - 1
        
        while left < right:
            current_sum = arr[i] + arr[left] + arr[right]
            
            if current_sum >= target:
                // Sum is too large or equal, move right pointer leftwards
                right = right - 1
            else:
                // If current_sum is less than target, then all elements between 
                // left and right will also form a valid triplet with arr[i] and arr[left]
                count = count + (right - left)
                left = left + 1
                
    return count
```

### Complexity Analysis

- **Time Complexity:** $O(N^2)$. The outer loop runs $O(N)$ times, and the inner `while` loop runs $O(N)$ times. Sorting takes $O(N \log N)$, so the dominant term is $O(N^2)$.
    
- **Space Complexity:** $O(1)$ auxiliary space (not counting the space used by the sorting algorithm).
    

## Problem 2: Dutch National Flag (Sort Colors)

You are given an array containing exactly three types of elements: `0`, `1`, and `2`. You need to rearrange the array in-place so that all `0`s come first, followed by all `1`s, and then all `2`s. **Constraint: You cannot use a sorting function, and ideally it should be done in a single pass.**

**Example:**

- **Input:** `arr = [2, 0, 2, 1, 1, 0]`
    
- **Expected Output:** `[0, 0, 1, 1, 2, 2]`
    

### Approach 1: Frequency Array (Two Passes)

1. **Pass 1:** Traverse the array and count the occurrences of `0`, `1`, and `2` into three variables.
    
2. **Pass 2:** Overwrite the original array. Write `0`s for the count of zeroes, then `1`s, then `2`s.
    

- **Time:** $O(N)$ (but requires 2 passes).
    
- **Space:** $O(1)$.
    
    _This is highly optimal, but interviewers will often restrict you to a strictly **single-pass** solution._
    

### Approach 2: Optimal Single Pass (Dutch National Flag Algorithm)

We maintain three pointers: `low`, `mid`, and `high`. These pointers divide the array into four conceptual regions:

1. `0` to `low - 1`: Sorted `0`s.
    
2. `low` to `mid - 1`: Sorted `1`s.
    
3. `mid` to `high`: **Unsorted/Problematic area.**
    
4. `high + 1` to `n - 1`: Sorted `2`s.
    

**The "Teacher" Analogy:**

Imagine you are a teacher organizing students.

- **0 (Tops/Winners):** Send them to the front. Swap `arr[mid]` with `arr[low]`. Since we know what comes from `low` is at worst a `1`, we can safely increment both `mid` and `low`.
    
- **1 (Average):** They are exactly where they belong (in the middle). Just increment `mid`.
    
- **2 (Failures/Bottom):** Send them to the back. Swap `arr[mid]` with `arr[high]`. Decrement `high`. **Crucial step:** Do _not_ increment `mid` here, because the element swapped from `high` into `mid` is completely unchecked (it could be a `0`, `1`, or `2`), so it must be evaluated on the next iteration.
    

### Pseudo-code: Dutch National Flag

Plaintext

```
function sortColors(arr):
    n = length of arr
    low = 0
    mid = 0
    high = n - 1
    
    // Process until the unsorted region is completely consumed
    while mid <= high:
        if arr[mid] == 0:
            // Send 0 to the front
            swap(arr[mid], arr[low])
            low = low + 1
            mid = mid + 1
            
        else if arr[mid] == 1:
            // 1 is in the correct middle region
            mid = mid + 1
            
        else if arr[mid] == 2:
            // Send 2 to the back
            swap(arr[mid], arr[high])
            high = high - 1
            // Do NOT increment mid here! The swapped element needs evaluation.
```

### Complexity Analysis

- **Time Complexity:** $O(N)$. We traverse the array exactly once. The `mid` pointer only moves forward (or evaluates a swapped element), so every operation reduces the unsorted region `mid` to `high`.
    
- **Space Complexity:** $O(1)$. The rearrangement happens entirely in-place.
    

## Active Recall

**Q: In the "Triplets with Smaller Sum" problem, when `current_sum < target`, why do we add `(right - left)` to the count instead of just `1`?**

**A:** Because the array is sorted. If `arr[i] + arr[left] + arr[right] < target`, it logically guarantees that substituting `arr[right]` with any element sitting between `left` and `right` will also produce a valid sum smaller than the target. Thus, there are `(right - left)` valid triplets for that specific `arr[i]` and `arr[left]`.

**Q: In the optimal single-pass Dutch National Flag algorithm, what do the regions `[0 ... low-1]` and `[high+1 ... n-1]` represent?**

**A:** The region `[0 ... low-1]` strictly contains all the `0`s placed correctly so far. The region `[high+1 ... n-1]` strictly contains all the `2`s placed correctly so far.

**Q: Why don't we increment the `mid` pointer after swapping `arr[mid]` with `arr[high]` when `arr[mid] == 2`?**

**A:** Because the element that just came from the `high` index into the `mid` index is completely unknown (it was part of the unsorted problem area). It could be a `0`, `1`, or `2`. If we incremented `mid`, we would skip evaluating this new element.

**Q: Why _is_ it safe to increment `mid` when swapping `arr[mid]` with `arr[low]` (when `arr[mid] == 0`)?**

**A:** By the definition of our regions, any element sitting at the `low` pointer is either a `1` (if `low` and `mid` have diverged) or a `0` (if `low` and `mid` are still pointing to the same index). In either case, swapping it into `mid` places a safe, evaluated `1` (or self-swaps a `0`), meaning `mid` can safely move forward without re-evaluating.
