## Concept: Slow & Fast Pointers Beyond Linked Lists

While traditionally taught with Linked Lists, the Slow & Fast Pointer pattern is fundamentally about **Cycle Detection**. A cycle can exist in any data structure or sequence where:

1. You move from one state (node/index/number) to a definitive next state.
2. The sequence of states is infinite and bound by a finite number of possible states (meaning it _must_ eventually loop back on itself).

##  Problem 1: Find the Duplicate Number

**Problem Statement:** Given an array of integers `nums` containing $n + 1$ integers where each integer is in the range $[1, n]$ inclusive. There is exactly **one** repeated number in `nums`. Return this repeated number.

_Constraint:_ You must solve the problem without modifying the array `nums` and uses only constant $O(1)$ extra space. (LeetCode 287)

###  Intuition & Logic

If an array has 5 boxes ($N=5$) and can only contain the numbers 1 through 4, the Pigeonhole Principle dictates that at least one number _must_ be repeated.

**Conceptualizing the Array as a Graph/Linked List:**

Instead of looking at the array sequentially, imagine the `indices` as nodes, and the `values` inside the array as the pointers (`next`) telling you where to go next.

- Start at index `0`. The value is `nums[0]`.
- Go to index `nums[0]`. The value there is `nums[nums[0]]`.
- Go to that index... and so on.

**Why does a cycle form?**

Since there is a duplicate number, say `x`, there are multiple indices in the array that contain the value `x`.

When mapping this out, multiple paths will point to the index `x`. The moment multiple paths point to the same node, it creates a loop/cycle. The node with multiple incoming arrows (the start of the cycle) is exactly the duplicate number!

### Pseudo-code: Find the Duplicate Number

This is identical to the Linked List cycle starting point algorithm, but `slow = slow.next` becomes `slow = nums[slow]`.
```cpp
function findDuplicate(nums):
    // Step 1: Initialize slow and fast pointers to the "head" (index 0)
    slow = 0
    fast = 0
    
    // Step 2: Detect Cycle
    // (No need to check for nulls, the problem guarantees a cycle exists)
    while true:
        slow = nums[slow]          // Move 1 step
        fast = nums[nums[fast]]    // Move 2 steps
        
        if slow == fast:
            break // Collision point found inside the cycle
            
    // Step 3: Find the starting point of the cycle (the duplicate number)
    slow = 0 // Reset slow to the start
    
    // Move both at the same speed until they meet
    while slow != fast:
        slow = nums[slow]
        fast = nums[fast]
        
    return slow // The meeting point is the duplicate number
```

## Problem 2: Happy Number

**Problem Statement:** Write an algorithm to determine if a number `n` is "happy".

A happy number is a number defined by the following process:

1. Starting with any positive integer, replace the number by the sum of the squares of its digits.
2. Repeat the process until the number equals 1 (where it will stay), or it **loops endlessly in a cycle** which does not include 1.
3. Those numbers for which this process ends in 1 are happy. Return true if `n` is a happy number, and false if not. (LeetCode 202)

### Intuition & Logic

The problem explicitly mentions "loops endlessly in a cycle." This is a massive neon sign indicating the Slow & Fast Pointer pattern.

In this scenario:

- The "node" is the current number.
- The "next" pointer is a helper function that calculates the sum of the squares of the digits.

If a number is "Happy", the sequence will reach `1` and stay `1` forever.

If a number is not "Happy", the sequence will enter a cycle of numbers and loop infinitely. We use the Tortoise and Hare approach to detect if the sequence gets trapped in a cycle before hitting `1`.

### Pseudo-code: Happy Number
```cpp
// Helper function to act as the ".next" operation
function sumOfSquareDigits(n):
    sum = 0
    while n > 0:
        digit = n % 10
        sum = sum + (digit * digit)
        n = n / 10
    return sum

function isHappy(n):
    slow = n
    fast = n
    
    // Step 1: Detect cycle or end
    while fast != 1 and sumOfSquareDigits(fast) != 1:
        // Move slow 1 step
        slow = sumOfSquareDigits(slow)
        
        // Move fast 2 steps
        fast = sumOfSquareDigits(fast)
        fast = sumOfSquareDigits(fast)
        
        // Step 2: Check for collision
        if slow == fast:
            // If they collide and it's not at 1, we are stuck in a non-happy cycle
            if slow != 1:
                return false
                
    // If the loop breaks because fast == 1, it's a happy number
    return true
```

## Active Recall

**Q: How do you translate the concept of `node.next` from a Linked List into an Array representation for cycle detection?**

**A:** In an array, the "index" acts as the current node, and the "value" at that index `arr[i]` acts as the pointer to the next node. Therefore, moving one step is `i = arr[i]`, and moving two steps is `i = arr[arr[i]]`.

**Q: In the "Find the Duplicate Number" problem, why are we guaranteed that a cycle exists and that we don't need to check for out-of-bounds errors?**

**A:** The problem constraints state that the array is of size $n+1$ and contains values exclusively from $1$ to $n$. Because the values are strictly less than the array bounds, treating a value as an index will never result in an out-of-bounds error. Furthermore, by the Pigeonhole Principle, at least one value must repeat, meaning two different indices will point to the same destination index, forming an inescapable cycle.

**Q: What acts as the "next" pointer in the mathematical "Happy Number" sequence?**

**A:** A helper function that takes the current number, splits it into digits, squares each digit, and returns the sum of those squares.

**Q: In the Happy Number problem, if a number is truly "happy" and eventually reaches 1, why won't the slow and fast pointers falsely detect a cycle and return `false`?**

**A:** Because $1^2 = 1$. Once the sequence hits 1, it stays at 1 infinitely. Eventually, both the slow and fast pointers will arrive at 1. The `while` loop condition (`fast != 1`) will break, and the function will correctly return `true` before evaluating the `slow == fast` collision check inside the loop.
