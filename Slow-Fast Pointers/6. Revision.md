> This lecture provides a rapid, comprehensive revision of the Slow & Fast Pointer pattern. The instructor reiterates that this pattern transcends Linked Lists and can be applied to Arrays and individual numbers. The revision solidifies the three core scenarios where this pattern is the guaranteed solution: finding a cycle, finding the start of a cycle, and finding the middle of a data structure.

## Pattern Identification Flowchart

Unlike other patterns (e.g., Sliding Window) where the data structure is a primary clue, the Slow & Fast Pointer pattern is identified almost exclusively by the **problem's goal**.

**The Data Structure does not matter.** It could be:

- Linked List
- Array (using indices as pointers to values)
- Single Number (e.g., repeating mathematical operations on its digits)

**If the problem asks you to do any of the following, use the Slow & Fast Pointer Pattern (100% Guarantee):**

1. **Find a Cycle:** Detect if a loop, cycle, or repetitive behavior exists (True/False).
2. **Find the Start of a Cycle:** If a cycle exists, identify the exact entry point or the element causing the repetition (e.g., "Find the Duplicate Number").
3. **Find the Middle:** Find the exact middle node/element of a linear structure in a single pass.

## Template 1: Detect a Cycle & Find its Start

This is the universal template for cycle detection. It works for Linked Lists, Arrays, and Numbers; you just have to adapt what "moving one step" means based on the data structure.

### Universal Steps:

1. Initialize both `slow` and `fast` pointers at the `start` of the structure (e.g., `head` for Linked List, index `0` for Arrays).
2. Create a `while` loop that runs until `fast` reaches an "end" state (e.g., `null`, out of bounds, or a target number like `1` in Happy Number).
3. Move `slow` forward by **1 step**.
4. Move `fast` forward by **2 steps**.
5. Check for intersection (`slow == fast`). If they meet, a cycle exists.
6. _(Optional)_ To find the starting point: Reset `slow` to the `start`. Leave `fast` where it is. Move both pointers by **1 step** at a time. The exact point they collide again is the start of the cycle.

### Pseudo-code (Generalized)
```cpp
function detectCycleAndStart(start_node):
    slow = start_node
    fast = start_node
    has_cycle = false
    
    // 1. Detect Cycle
    // The condition depends on the data structure (e.g., fast != null)
    while fast_has_not_reached_end(fast):
        slow = move_one_step(slow)
        fast = move_two_steps(fast)
        
        if slow == fast:
            has_cycle = true
            break
            
    if has_cycle == false:
        return false // Or null/none depending on what's asked
        
    // 2. Find the Starting Point
    slow = start_node // Reset slow to the beginning
    
    // Move both at the same speed (1 step)
    while slow != fast:
        slow = move_one_step(slow)
        fast = move_one_step(fast)
        
    return slow // The collision point is the start of the cycle
```

## Template 2: Find the Middle

This template is almost exclusively used for Linked Lists to avoid traversing the list twice (once to count, once to find the middle).

### Universal Steps:

1. Initialize both `slow` and `fast` pointers at the `start` (`head`).
2. Create a `while` loop checking that `fast` and `fast.next` are not at the end (`null`).
3. Move `slow` forward by **1 step**.
4. Move `fast` forward by **2 steps**.
5. When the loop breaks (because `fast` reached the end), the `slow` pointer is sitting exactly on the middle node.

### Pseudo-code
```cpp
function findMiddle(head):
    slow = head
    fast = head
    
    // Loop until fast hits the end of the list
    while fast != null and fast.next != null:
        slow = slow.next          // 1 step
        fast = fast.next.next     // 2 steps
        
    // When fast finishes the race, slow is halfway there
    return slow
```

## Active Recall

Q: Why does the "Slow & Fast Pointer" pattern apply to Arrays and Mathematical sequences, and not just Linked Lists? 
**A:** Because a "cycle" is just a sequence of states that eventually loops back on itself. In an Array, indices act as states and values act as pointers. In math, the current number is the state, and the mathematical operation is the pointer to the next state.

Q: If you want to adapt the Cycle Detection template for an Array to find a duplicate number, what does `move_one_step(slow)` translate to in code? 
A: `slow = array[slow]`. The value at the current index tells you which index to visit next.

Q: Once `slow == fast` inside a cycle, why does resetting `slow` to the start and moving both pointers at 1-step speeds guarantee they will meet at the cycle's starting point? 
A: Mathematically, the distance from the `start` to the `entry point` of the cycle is identical to the distance from the `collision point` to the `entry point` (moving forward through the cycle). Since the distances are identical, moving them at the same speed guarantees they arrive at the entry point simultaneously.

Q: In the `findMiddle` algorithm, why is it necessary to check both `fast != null` AND `fast.next != null` in the `while` loop condition? 
A: Because the `fast` pointer moves two steps at a time (`fast.next.next`). If `fast.next` is null, attempting to access `.next` on it will cause a Null Reference Exception and crash the program.
