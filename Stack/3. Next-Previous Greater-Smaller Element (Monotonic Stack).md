> This lecture introduces the **Monotonic Stack** pattern, one of the most powerful and frequently tested concepts in DSA interviews. The instructor demystifies the four classic variations (Previous Greater, Previous Smaller, Next Greater, Next Smaller) by demonstrating that they are all fundamentally the exact same algorithm. The core intuition revolves around finding the "most recent" element that satisfies a condition and permanently discarding (popping) elements that will never be needed again.

## Pattern Identification: When to use a Monotonic Stack?

You should immediately think of a Monotonic Stack when a problem asks you to find the **Most Recent** element that meets a specific relative condition (e.g., Greater or Smaller) for _every_ element in an array.

**Keywords / Indicators:**

- "Next Greater Element"
- "Next Smaller Element"
- "Previous Greater Element"
- "Previous Smaller Element"
- "Days until a warmer temperature" (e.g., LeetCode 739: Daily Temperatures)
- "Stock Spans"

### Why does a Brute Force loop fail the interview?

A brute force approach requires a nested loop: for every element `i`, you loop backwards (or forwards) from `i-1` to `0` to find the target element. This results in $O(N^2)$ time complexity.

A Monotonic Stack achieves the exact same result in **$O(N)$ time** by recognizing that certain elements are "useless" and can be permanently discarded from memory.

## The Intuition (The "Stone" Analogy)

Imagine you are walking along a path picking up stones (elements from the array) and putting them in your pocket (the Stack).

Your goal: For the current stone you are holding, you want to look into your pocket and find the **most recently picked stone** that is strictly **LARGER** than your current stone.

**The Strategy at each step:**

1. **Throw away the "bad" stones:** Look at the stone at the top of your pocket. Is it smaller than or equal to your current stone? If yes, throw it away (`pop`).
    - _Why throw it away?_ Because if a stone in your pocket is smaller than your current stone, any future stone walking down the path that needs a "large" stone will prefer your current stone over the small one in your pocket. The small stone is completely overshadowed and will **never be the answer for any future stone.** It is useless.
        
2. **Find your answer:** Keep throwing away bad stones until you either find a stone that is larger than yours, or your pocket is completely empty.
    - If your pocket is empty, there is no larger stone. Your answer is `-1`.
    - If you stop throwing stones, the one sitting at the top is your answer.
        
3. **Put your current stone in the pocket:** Before moving to the next stone on the path, put your current stone into your pocket (`push`). It might be the answer for a future stone!

_(Note: Because we are continuously throwing away smaller stones, the stones remaining in the pocket will always be naturally sorted from largest at the bottom to smallest at the top. This strictly maintaining of order is why it's called a **Monotonic** Stack)._

## The Universal Pseudo-code

All four variations (Previous/Next, Greater/Smaller) use this exact same blueprint. You only need to change two things:

1. **The Loop Direction:**
    - _Previous:_ Loop Left-to-Right (`0` to `n-1`).
    - _Next:_ Loop Right-to-Left (`n-1` to `0`).
        
2. **The `while` loop pop condition ("What is a bad stone?"):**
    - _Greater problems:_ Pop if `top <= current`.
    - _Smaller problems:_ Pop if `top >= current`.

### Variation 1: Previous Greater Element

- **Direction:** Left to Right
- **Pop Condition:** `top <= current`

```cpp
function previousGreaterElement(arr):
    n = length of arr
    res = array of size n initialized to -1
    st = empty Stack
    
    // Seed the first element
    res[0] = -1
    st.push(arr[0])
    
    // Iterate Left to Right
    for i = 1 to n - 1:
        // Step 1: Throw away "bad" stones
        while st is not empty and st.top() <= arr[i]:
            st.pop()
            
        // Step 2: Record the answer
        if st is empty:
            res[i] = -1
        else:
            res[i] = st.top()
            
        // Step 3: Put current stone in the pocket
        st.push(arr[i])
        
    return res
```

### Variation 2: Next Greater Element

- **Direction:** Right to Left
- **Pop Condition:** `top <= current`

```cpp
function nextGreaterElement(arr):
    n = length of arr
    res = array of size n initialized to -1
    st = empty Stack
    
    // Seed the last element
    res[n-1] = -1
    st.push(arr[n-1])
    
    // Iterate Right to Left
    for i = n - 2 down to 0:
        // Step 1: Throw away "bad" stones
        while st is not empty and st.top() <= arr[i]:
            st.pop()
            
        // Step 2: Record the answer
        if st is empty:
            res[i] = -1
        else:
            res[i] = st.top()
            
        // Step 3: Put current stone in the pocket
        st.push(arr[i])
        
    return res
```

## Complexity Analysis

- **Time Complexity:** $O(N)$. Even though there is a `while` loop inside a `for` loop, do not be fooled into thinking it is $O(N^2)$. Every element from the array is pushed onto the stack exactly once, and popped from the stack at most once. Therefore, the inner `while` loop runs a total of $N$ times across the entire execution of the program.
- **Space Complexity:** $O(N)$. In the worst-case scenario (e.g., finding the Previous Greater element in a strictly decreasing array like `[5, 4, 3, 2, 1]`), no elements are ever popped, and all $N$ elements are pushed onto the stack.

## Active Recall

**Q: In the "Previous Greater Element" problem, if the element at the top of the stack is smaller than the current element, why is it safe to permanently `pop()` it and throw it away?**

**A:** If a previously seen element is smaller than the current element, it can never be the "Previous Greater" answer for any future element. Any future element looking backwards for a greater value will encounter our current (larger) element first. The smaller, older element is completely overshadowed and useless.

**Q: How do you mathematically change the algorithm from finding "Greater" elements to finding "Smaller" elements?**

**A:** You simply flip the comparison operator inside the `while` loop. Instead of throwing away elements that are smaller (`top <= current`), you throw away elements that are larger (`top >= current`), effectively maintaining a stack of strictly increasing values.

**Q: Why does finding the "Next" element require looping through the array backwards (from right to left)?**

**A:** A stack inherently gives you access to the "most recently processed" items. If you want to find the next element (an element to the right of your current position), you must have already processed and stacked the elements to your right. Looping backwards ensures that the elements in your stack represent the future of your current position.

**Q: Is the Time Complexity of a Monotonic Stack $O(N)$ or $O(N^2)$, and why?**

**A:** It is strictly $O(N)$. While there is a nested `while` loop, the crucial detail is that an element can only be `popped` from the stack one single time. Across the entire `for` loop, the `pop` operation will execute a maximum of $N$ times total, making the amortized cost $O(1)$ per element.
