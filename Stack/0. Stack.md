## Concept: What is a Stack?

A Stack is a linear data structure that operates on the **LIFO (Last In, First Out)** or **FILO (First In, Last Out)** principle.

### The Mental Model: The Box

Imagine a tall, narrow box with only one opening at the very top.

- If you put a book inside, it falls to the bottom.
- If you put a second book inside, it rests on top of the first book.
- If you want to take the first book out, you _cannot_ reach through the sides or bottom. You **must** remove the second book first.

**Core Property:** Whatever goes in _last_ is the only thing you can access or remove _first_.

**Core Transformation:** If you take an ordered sequence (like `1, 2, 3, 4`), push it entirely into a stack, and then pop it entirely out, the sequence will be completely reversed (`4, 3, 2, 1`).

## Basic Stack Operations

Because you can only interact with the top of the box, a Stack has very limited operations. This makes it easy to code but requires clever logic to use effectively.

1. **`push(item)`**: Inserts an element at the very top of the stack.
2. **`pop()`**: Removes the element currently at the very top of the stack. _(Does not return the value, just deletes it)._
3. **`top()` or `peek()`**: Looks at the element currently at the top of the stack and returns its value without removing it.
4. **`size()`**: Returns the number of elements currently inside the stack.
5. **`empty()`**: Returns `true` if the stack has 0 elements, `false` otherwise.

_Note: A stack is strictly typed. A single stack can only hold integers, OR characters, OR custom objects, but not a mix._

##  Pattern Identification: When to Use a Stack?

Identifying a stack problem is the hardest part of this pattern. Unlike Sliding Window or Prefix Sum, the clues are behavioral rather than structural.

**Look for these scenarios and keywords:**

1. **"Most Recent" Rule:** You are processing items from left to right, but your current decision depends heavily on the **most recently seen** elements. (The top of the stack perfectly represents the most recent item).
2. **Matching / Pairing:** Problems that ask you to match pairs (e.g., Valid Parentheses `()`, `{}`).
3. **Canceling / Cleaning:** Problems where adjacent elements destroy or cancel each other out (e.g., removing adjacent duplicate letters like `abbc` $\rightarrow$ `ac`).
4. **Reversing:** Whenever you need to fundamentally reverse the order of operations, paths, or strings.

##  The Three Types of Stack Patterns

Stack problems generally fall into three distinct sub-patterns:

1. **Simple Stack:** Basic push/pop logic based on direct matching or canceling (e.g., String reversal, Valid Parentheses).
2. **Monotonic Stack:** The stack strictly maintains a sorted order (either strictly increasing or strictly decreasing). Used heavily for "Next Greater Element" or "Previous Smaller Element" problems.
3. **Greedy Stack:** Similar to Monotonic, but instead of sorting by numeric value, the stack maintains an order based on a specific problem condition, priority, or greedy choice (often seen in operating system process scheduling or complex string building).

## The Universal Stack Template

Every stack problem requires you to loop through the items (Left to Right) and make three fundamental decisions for _every single item_:
```cpp
function universalStackPattern(items):
    stack = empty Stack
    
    // Process items Left to Right
    for item in items:
        
        // DECISION 1: When and what to POP?
        // Does this current item invalidate, match, or cancel previous items?
        while stack is not empty AND should_pop_condition(item, stack.top()):
            stack.pop()
            
        // DECISION 2: When to PUSH?
        // Does this current item need to be saved for future items to look at?
        if should_push_condition(item):
            stack.push(item)
            
    // DECISION 3: Format the Result
    // The stack now contains the final processed state. Extract it.
    result = empty structure
    while stack is not empty:
        result.add(stack.top())
        stack.pop()
        
    // (Remember: Extracting from the stack yields the reverse order!)
    return result
```

## Example: Reverse a String using a Stack

While you can reverse a string using Two Pointers, doing it with a Stack perfectly demonstrates the LIFO principle.
### Pseudo-code
```cpp
function reverseString(str):
    n = length of str
    st = empty Stack of Characters
    
    // Step 1: Push all characters into the stack
    for i = 0 to n - 1:
        st.push(str[i])
        
    // Step 2: Pop them out to build the reversed string
    reversed_str = ""
    
    while not st.empty():
        // Look at the top character
        c = st.top()
        // Add it to our result
        reversed_str = reversed_str + c
        // Remove it from the stack
        st.pop()
        
    return reversed_str
```

## Active Recall

**Q: Why does pushing an entire sequence into a stack and then popping it all out naturally reverse the sequence?**

**A:** Because a stack operates on the Last-In-First-Out (LIFO) principle. The first item pushed in falls to the bottom, and the last item pushed in rests at the top. When you begin popping items out, you are forced to remove the top item first, meaning the last item inserted is the first one retrieved.

**Q: In C++ (and many other languages), what is the functional difference between the `pop()` and `top()` (or `peek()`) methods?**

**A:** `top()` returns the value of the element currently at the top of the stack but leaves the element inside the stack. `pop()` deletes the element from the top of the stack entirely but does _not_ return its value.

**Q: What is the defining characteristic of a "Monotonic Stack" compared to a simple stack?**

**A:** A Monotonic Stack strictly maintains its elements in a sorted order (either entirely increasing or entirely decreasing) from bottom to top. It enforces this by popping off any elements that would violate the sorted order before pushing a new element.

**Q: In the Universal Stack Template, why is the popping logic usually written as a `while` loop rather than a simple `if` statement?**

**A:** Because a single incoming item might invalidate, cancel, or match multiple items currently sitting in the stack. A `while` loop allows the current item to continuously pop elements off the stack until the top of the stack finally satisfies the required condition.
