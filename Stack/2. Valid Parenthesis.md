## Problem: Valid Parentheses (LeetCode 20)

**Problem Statement:** Given a string `s` containing just the characters `'('`, `')'`, `'{'`, `'}'`, `'['` and `']'`, determine if the input string is valid.

An input string is valid if:

1. Open brackets must be closed by the same type of brackets.
2. Open brackets must be closed in the correct order.
3. Every close bracket has a corresponding open bracket of the same type.

### Why does a simple `for` loop fail?

If the string only contained adjacent pairs like `()[]{}` or `()`, checking `s[i]` and `s[i+1]` would work.

However, parentheses can be **nested**: `({[]})`.

In a nested structure, an opening bracket at index `0` might not be closed until index `100`. A simple linear scan looking ahead or behind by 1 index cannot resolve deep nesting.

## The Stack Intuition (The Compiler Analogy)

How does a C++ or Java compiler know that you closed a `for` loop correctly inside an `if` statement, which is inside a `function`?

1. The compiler reads your code top-to-bottom (Left-to-Right).
2. When it sees an opening bracket `{` (e.g., for a function), it says: _"I need to close this eventually. Let me put it in my pocket."_
3. Then it sees another `{` (e.g., for an `if` statement). It puts that in its pocket too.
4. Then it sees a closing bracket `}`.
5. **The Critical Question:** Which opening bracket does this closing bracket belong to?
    - It _must_ belong to the **most recently opened** block. You cannot close the `function` before you close the `if` statement inside it.
6. The compiler reaches into its pocket and pulls out the item sitting at the very top (the most recent one). If they match, the `if` statement is successfully closed, and the compiler removes that bracket from its pocket.

### The Decision Matrix for Every Bracket

As we scan the string from left to right, we treat every character as an item and make decisions:

- **Is it an Opening Bracket? `(`, `{`, `[`**
    - _Action:_ Put it in the pocket (`push()`). We don't know when it will close, but we need to remember it.
- **Is it a Closing Bracket? `)`, `}`, `]`**
    - _Action:_ We need to match it. But against what? Against the **most recently kept** opening bracket.
    - _Check 1:_ Is the pocket empty? If so, we have a closing bracket with no opening bracket. **Return False.**
    - _Check 2:_ Does the bracket at the `top()` of the pocket match the _type_ of our current closing bracket?
        - If **Yes**: They form a valid pair. Throw the top bracket away (`pop()`) because it is now resolved.
        - If **No**: We have a mismatch (e.g., we opened a `{` but are trying to close a `]`). **Return False.**

## Pseudo-code: Valid Parentheses

```cpp
function isValid(s):
    n = length of s
    st = empty Stack of Characters
    
    for i = 0 to n - 1:
        current_char = s[i]
        
        // DECISION 1: Is it an opening bracket?
        if current_char == '(' or current_char == '{' or current_char == '[':
            // Push it to the stack to remember it
            st.push(current_char)
            continue
            
        // DECISION 2: It is a closing bracket. Can we match it?
        
        // Edge Case: If stack is empty, there is no open bracket to match
        if st is empty:
            return false
            
        top_char = st.top()
        
        // Check for matching types
        if current_char == ')' and top_char == '(':
            st.pop()
        else if current_char == '}' and top_char == '{':
            st.pop()
        else if current_char == ']' and top_char == '[':
            st.pop()
        else:
            // Type mismatch (e.g., trying to close '[' with '}')
            return false
            
    // DECISION 3: Are there any unresolved opening brackets left?
    // If the stack is NOT empty at the end, it means we opened brackets 
    // that were never closed (e.g., "((()").
    if st is not empty:
        return false
        
    // Everything matched perfectly
    return true
```

## Complexity Analysis

- **Time Complexity:** $O(N)$. We traverse the string of length $N$ exactly once. Pushing, popping, and peeking at the top of the stack all take $O(1)$ constant time.
- **Space Complexity:** $O(N)$. In the worst-case scenario (e.g., `"(((((("`), the string consists entirely of opening brackets. Every single character will be pushed onto the stack, requiring $O(N)$ auxiliary space.

## Active Recall

**Q: Why does the "Valid Parentheses" problem require a Stack instead of simple pointers or counters?**

**A:** Because parentheses can be nested indefinitely. A closing bracket must always resolve the _most recently opened_ and _unresolved_ bracket. The Last-In-First-Out (LIFO) nature of a Stack perfectly models this exact requirement of fetching the most recently stored item.

**Q: If you encounter a closing bracket (e.g., `}`) and your stack is completely empty, what does this indicate about the string?**

**A:** It indicates the string is invalid. It means you are trying to close a block or scope that was never opened in the first place (e.g., `s = "()}"`).

**Q: Why must we check `if (!st.empty())` after the entire `for` loop has finished executing?**

**A:** Because it is possible for a string to have an excess of opening brackets (e.g., `s = "((()"`). The loop will execute perfectly, matching the inner brackets, but unresolved opening brackets will remain trapped in the stack. If the stack is not completely empty at the end, the string is invalid.

**Q: When a closing bracket successfully matches the opening bracket at the `top()` of the stack, why do we `pop()` the stack?**

**A:** Popping removes the resolved opening bracket from our "unresolved" history. This exposes the _next_ most recently opened bracket so that it can correctly be matched against the next incoming closing bracket.
