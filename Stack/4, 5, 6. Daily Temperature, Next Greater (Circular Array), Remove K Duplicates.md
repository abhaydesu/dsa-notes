### Lecture Context

This lecture consolidates the Stack and Monotonic Stack patterns by solving three classic, highly-tested interview questions that cover 80-90% of stack interview scenarios. The instructor bridges the gap between basic theoretical concepts (like Next Greater Element) and real-world variations: story-based problems, circular arrays, and frequency-based sequential deletions.

### Pattern Identification: When to use these Stack Variations?

You should immediately think of these specific stack modifications when a problem asks you to:

1. Find the **"distance"** or **"time"** until a relative condition is met (e.g., days until warmer weather).
    
2. Process elements with a **"wrap-around"** or circular requirement.
    
3. Continually collapse or remove adjacent elements based on a **specific count threshold $K$**.
    

**Keywords / Indicators:**

- "How many days until..." (e.g., LeetCode 739: Daily Temperatures)
    
- "Next Greater Element in a Circular Array" (e.g., LeetCode 503)
    
- "Remove $K$ adjacent duplicates in a string" (e.g., LeetCode 1209)
    

### Why does a Brute Force loop fail the interview?

- **For Next Greater Distance:** A nested loop requires searching ahead for every day, resulting in $O(N^2)$ time.
    
- **For Circular Arrays:** Using a nested loop with modulo arithmetic to simulate wrapping around still requires iterating through the rest of the array for every single element, leading to $O(N^2)$.
    
- **For String Deletions:** Repeatedly scanning the string, deleting a match, and starting the scan over from the beginning takes $O(N^2)$ or worse.
    
    Using a Stack reduces all these problems to a single pass (or simulated double pass), yielding an elegant $O(N)$ solution.
    

### The Intuition (The Three Core Strategies)

**Strategy 1: Distance via Indices (Daily Temperatures)**

When a problem asks "how many days until it gets warmer", finding the _value_ of the Next Greater Element isn't enough; you need its _position_.

- **The Fix:** Instead of pushing the array values (the stones) onto your pocket/stack, push their **indices** (the location of the stones).
- When you check if a past day is "bad" (cooler), you use `arr[stack.top()] <= arr[i]`.
- When you find the answer, the distance is simply the difference between the indices: `stack.top() - i`.

**Strategy 2: Pre-loading for Circular Arrays**

In a standard Next Greater problem, the last element has no elements to its right, so its answer is automatically `-1`. In a circular array, the last element needs a "chance" to look at the beginning of the array.

- **The Fix (Pre-loading):** Before you even start your main Right-to-Left loop, iterate through the array once and push the elements into the stack.
    
- By "pre-loading" the stack, when you start your actual loop at the last index, the stack is already populated with the elements from the front of the array. You have perfectly simulated a wrap-around without physically duplicating the array in memory.
    

**Strategy 3: Stack of Pairs for K-Deletions**

If you need to delete exactly $K$ adjacent identical characters, pushing individual characters into a stack makes it impossible to efficiently know how many identical characters are currently grouped together.

- **The Fix:** Store a pair `(character, frequency)` in the stack.
    
- **If the current character doesn't match the top:** Push `(char, 1)`.
    
- **If it matches:** Look at the top's frequency.
    
    - If `freq < K - 1`: Increment the frequency.
        
    - If `freq == K - 1`: Adding your current character hits exactly $K$. You simply completely `pop()` the top pair. Instantly, all $K$ elements are deleted without needing a while loop!
        

### The Universal Pseudo-code Variations

**Variation 1: Next Greater Distance (Daily Temperatures)**

- **Concept:** Push indices, calculate index differences.
```cpp
function dailyTemperatures(arr):
    n = length of arr
    res = array of size n initialized to 0
    st = empty Stack
    
    // Seed the last element's INDEX
    st.push(n - 1) 
    
    // Iterate Right to Left
    for i = n - 2 down to 0:
        // Pop cooler or equal days using indices
        while st is not empty and arr[st.top()] <= arr[i]:
            st.pop()
            
        // Record the answer as distance
        if st is not empty:
            res[i] = st.top() - i 
            
        // Push current INDEX
        st.push(i) 
        
    return res
```

**Variation 2: Stack of Pairs (Remove K Duplicates)**

- **Concept:** Group sequential identical elements into a frequency pair.
```cpp
function removeKDuplicates(s, k):
    st = empty Stack of Pairs (char, count)
    
    for char in s:
        // If stack is empty or letters don't match, push new pair
        if st is empty or st.top().char != char:
            st.push((char, 1))
        else:
            // If they match, check frequency
            if st.top().count < k - 1:
                st.top().count += 1
            else:
                // We reached k elements, destroy them in one fell swoop!
                st.pop()
                
    // Reconstruct the remaining string
    res = ""
    while st is not empty:
        pair = st.pop()
        append pair.char to res exactly pair.count times
        
    return reverse(res)
```

### Complexity Analysis

- **Time Complexity:** $O(N)$. Across all three variations, every element (or character) is pushed onto the stack exactly once and popped at most once. Even when calculating frequencies or pre-loading arrays, the amortized cost remains $O(1)$ per element.
    
- **Space Complexity:** $O(N)$. In the worst-case scenario (e.g., strictly decreasing temperatures, or a string with no repeating characters), all elements end up stored simultaneously inside the stack.
    

### Active Recall

**Q: Why do we store indices instead of values in the stack for the Daily Temperatures problem?**

A: Because the problem asks for the _number of days_ until a warmer temperature, not the temperature itself. Storing indices allows us to compute the distance (`stack.top() - i`) while still accessing the temperature value via `arr[stack.top()]`.

**Q: In a circular array, why does the normal Next Greater Element algorithm fail for the last element?**

A: In a normal algorithm, the stack starts empty for the rightmost element because there is nothing to its right (the search space is empty). In a circular array, the rightmost element's search space actually wraps around to include the entire beginning of the array.

**Q: How does "pre-loading" solve the circular array problem?**

A: By pushing elements from the array into the stack _before_ the main loop begins, we ensure that when the algorithm evaluates the last element, the stack is already populated with the elements from the front of the array. This effectively simulates a wrap-around environment without expanding the array itself.

**Q: In the "Remove K Duplicates" problem, why do we use a stack of `(character, frequency)` pairs instead of just pushing characters?**

A: If we only pushed characters, checking if we have $K$ consecutive identical characters would require popping and counting elements one by one, destroying the $O(N)$ efficiency. A pair tracks the consecutive count instantly in $O(1)$ time, allowing us to drop exactly $K$ items in a single pop operation.
