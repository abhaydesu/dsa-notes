## Problem: Search a 2D Matrix (LeetCode 74)

**Problem Statement:** You are given an `m x n` integer matrix `matrix` with the following two properties:

1. Each row is sorted in non-decreasing order.
    
2. The first integer of each row is greater than the last integer of the previous row.
    

Given an integer `target`, return `true` if `target` is in `matrix` or `false` otherwise.

_You must write a solution in $O(\log(m \cdot n))$ time complexity._

**Example:**

- `matrix = [[1,3,5,7], [10,11,16,20], [23,30,34,60]]`
    
- `target = 3`
    
- **Output:** `true`
    

## Approach 1: Two Binary Searches (Row Elimination)

Because the matrix is perfectly sorted, the numbers flow continuously from row to row.

### Step 1: Find the Correct Row

Instead of checking every row, we can use binary search on the **first column** of the matrix to determine which row the target _might_ belong to.

- The first element of any row `i` is `matrix[i][0]`.
    
- We want to find the **last row** where `matrix[i][0] <= target`.
    
    _(If `matrix[i][0] > target`, the target cannot possibly be in that row, nor in any row below it)._
    
- This forms a monotonic state space: `[Yes, Yes, Yes, No, No]`. We search for the Last Occurrence of `Yes`.
    

### Step 2: Search the Specific Row

Once we find the valid row index (e.g., `row = 2`), we isolate that specific row `matrix[2]`, which is simply a sorted 1D array.

- Perform a standard binary search on `matrix[2]` to find if the target exists.
    

_Time Complexity:_ $O(\log M + \log N)$. Perfectly valid, but requires writing two separate binary search loops.

## Approach 2: The Optimal 1D Flattening Trick

If you were to read the matrix row by row and write the numbers in a single line, it would form one continuous, perfectly sorted 1D array.

- **Logical 1D Array:** `[1, 3, 5, 7, 10, 11, 16, 20, 23, ...]`
    

We want to perform a binary search on this logical 1D array, but copying the matrix into an actual 1D array wastes $O(M \cdot N)$ space and time.

**The Magic Math:**

We can "pretend" the 1D array exists.

- Total elements = $M \cdot N$. Let's define the 1D index space from `0` to `(M * N) - 1`.
    
- If we guess a 1D index (e.g., `guess = 9`), how do we know where it lives in the actual 2D matrix?
    

Let `columns` be the total number of columns in the matrix ($N$).

- **Row Index:** `row = guess / columns`
    
- **Column Index:** `col = guess % columns`
    

_(Example: `guess = 9`, `columns = 4`. Row = `9/4 = 2`. Col = `9%4 = 1`. The element is at `matrix[2][1]`)._

Using this mathematical translation, we can write a single, standard binary search loop!

## Pseudo-code: Optimal 1D Binary Search


```cpp
function searchMatrix(matrix, target):
    if matrix is empty: return false
    
    rows = length of matrix
    cols = length of matrix[0]
    
    // Define the logical 1D search space
    low = 0
    high = (rows * cols) - 1
    
    while low <= high:
        // Guess the 1D index
        guess = low + (high - low) / 2
        
        // Translate the 1D index to 2D matrix coordinates
        r = guess / cols
        c = guess % cols
        
        // Fetch the value from the matrix
        mid_val = matrix[r][c]
        
        // Standard Binary Search Logic
        if mid_val == target:
            return true
        else if mid_val < target:
            low = guess + 1
        else:
            high = guess - 1
            
    return false
```

## Complexity Analysis

- **Time Complexity:** $O(\log(M \cdot N))$. We perform a single binary search over a search space of size $M \cdot N$. This is mathematically equivalent to $O(\log M + \log N)$, making it perfectly optimal.
    
- **Space Complexity:** $O(1)$. We use zero extra memory because we use math to dynamically map 1D indices to the existing 2D matrix.
    

## Active Recall

**Q: In the "Two Binary Searches" method, why do we search for the _Last Occurrence_ where `matrix[i][0] <= target` instead of the _First Occurrence_?**

**A:** The target could be larger than the first elements of several rows. For example, if the target is 15, and row starts are `[1, 10, 23]`, 15 is $\ge 1$ and $\ge 10$. The first occurrence (`1`) puts us in the wrong row. The _last_ occurrence (`10`) guarantees we are in the correct row before the numbers become too large (`23`).

**Q: In the 1D Flattening trick, why is the row index calculated as `guess / cols` and the column index as `guess % cols`?**

**A:** Imagine the 2D matrix as rows stacked on top of each other. Every time you cross a multiple of `cols` (the number of items in one row), you drop down to the next row. Integer division (`/ cols`) counts exactly how many full rows you have skipped over. Modulo division (`% cols`) gives you the exact remainder, which corresponds to your horizontal position (column) within that current row.

**Q: Does the 1D Flattening trick work if the matrix rows are individually sorted, but `matrix[i][last]` is NOT guaranteed to be less than `matrix[i+1][0]`?**

**A:** No. If the rows don't connect sequentially (e.g., Row 1 is `[1, 5, 9]` and Row 2 is `[2, 6, 10]`), flattening them into a 1D array results in `[1, 5, 9, 2, 6, 10]`. This flattened array is _not sorted_, so Binary Search will fail completely. The 1D trick strictly requires the matrix to be globally sorted when read left-to-right, top-to-bottom.
