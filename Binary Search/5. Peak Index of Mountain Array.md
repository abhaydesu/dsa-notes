## Problem: Peak Index in a Mountain Array (LeetCode 852)

**Problem Statement:** An array `arr` is a mountain if:

- `arr.length >= 3`
    
- There exists some index `i` (the peak) where $0 < i < arr.length - 1$ such that:
    
    - $arr[0] < arr[1] < ... < arr[i - 1] < arr[i]$
        
    - $arr[i] > arr[i + 1] > ... > arr[arr.length - 1]$
        

Given a mountain array `arr`, return the index `i` (the peak).

**Example:**

- `arr = [1, 3, 4, 5, 4, 3]`
    
- **Output:** `3` (The element `5` is the peak).
    

## Logic & Intuition (The "Mountain Climbing" Analogy)

Imagine you are blindfolded and climbing a mountain. You take a step forward.

- If your front foot is _higher_ than your back foot, you are still going **Uphill** (Chadhai). The peak must be somewhere in front of you.
    
- If your front foot is _lower_ than your back foot, you are going **Downhill** (Dhalan). You have already passed the peak, or you are standing exactly on it.
    

### Defining the Monotonic State Space

Let's look at the array `[1, 3, 5, 7, 6, 4, 3]` and compare every element to its immediate right neighbor (`arr[i]` vs `arr[i+1]`):

1. `1 < 3` (Uphill)
    
2. `3 < 5` (Uphill)
    
3. `5 < 7` (Uphill)
    
4. **`7 > 6` (Downhill) $\rightarrow$ The Peak!**
    
5. `6 > 4` (Downhill)
    
6. `4 > 3` (Downhill)
    

This creates a perfect **Monotonic State Space**:

`[Uphill, Uphill, Uphill, Downhill, Downhill, Downhill]`

### Applying Binary Search

We want to find the **First Occurrence of Downhill**.

This perfectly matches the "First True" pattern we learned previously.

- **Predicate Function:** Is the current step a Downhill? (`arr[mid] > arr[mid + 1]`)
    
- If **True (Downhill):** This might be the peak. Record the index as a potential answer (`best_ans = mid`), but look to the **Left** (`high = mid - 1`) to see if the downhill actually started earlier.
    
- If **False (Uphill):** We haven't reached the peak yet. The peak must be to the **Right** (`low = mid + 1`).
    

## Pseudo-code: Peak Index in a Mountain Array

```cpp
function peakIndexInMountainArray(arr):
    n = length of arr
    low = 0
    high = n - 1
    best_ans = -1
    
    while low <= high:
        mid = low + (high - low) / 2
        
        // Predicate: Are we going Downhill?
        if arr[mid] > arr[mid + 1]:
            // We are on a downhill slope. This could be the peak.
            best_ans = mid
            
            // Search LEFT to find the FIRST occurrence of a downhill
            high = mid - 1
            
        else:
            // We are going Uphill. The peak is further ahead.
            low = mid + 1
            
    return best_ans
```

### 🚨 Handling Edge Cases (Out of Bounds)

A critical thinker might ask: _"If `mid` becomes `n - 1`, won't checking `arr[mid + 1]` cause an Array Out of Bounds exception?"_

**The Mathematical Proof against Out of Bounds:**

`mid` can only equal `n - 1` if both `low` and `high` collapse onto `n - 1`.

- `high` starts at `n - 1` and only moves _down_. It never exceeds `n - 1`.
    
- `low` starts at `0` and moves _up_ only when we encounter an Uphill.
    
- For `low` to reach `n - 1`, the _entire array_ from `0` to `n - 1` must be strictly increasing (Uphill).
    
- **The Guarantee:** The problem guarantees the input is a valid mountain (`arr[0] < ... < arr[i] > ... > arr[n-1]`). A valid mountain _must_ have a downhill section. Therefore, it is mathematically impossible for the array to be strictly increasing, meaning `mid` will never be evaluated at `n - 1` while looking for a peak.
    

## Complexity Analysis

- **Time Complexity:** $O(\log N)$. We halve the search space at every step based on the slope evaluation.
    
- **Space Complexity:** $O(1)$. We only maintain a few integer pointers (`low`, `high`, `mid`, `best_ans`).
    

## Active Recall

**Q: Why doesn't the classic "Sorted Array" binary search apply directly to a Mountain Array?**

**A:** A Mountain Array is not fully sorted; it increases and then decreases. Binary Search requires a monotonic state space. To achieve this, we do not search for a target number; instead, we search a monotonic boolean array of slopes (Uphill vs. Downhill).

**Q: In the Mountain Array, what defines the mathematical condition of being "Uphill"?**

**A:** An element is "Uphill" if it is strictly less than its immediate right neighbor (`arr[i] < arr[i+1]`).

**Q: Why do we update `high = mid - 1` when we find a "Downhill" condition (`arr[mid] > arr[mid+1]`)?**

**A:** Finding a downhill condition means we have either found the peak or we have stepped completely over the peak onto the descending slope. To find the _exact_ peak (which is the very _first_ downhill step), we must record our current position and force the search space to the left to see if an earlier downhill step exists.

**Q: Why do we not need an explicit check for `mid + 1` exceeding the array bounds in this specific problem?**

**A:** The problem guarantees the input is a valid mountain, meaning it strictly must contain at least one descending element at the end. Because the search space moves right (`low = mid + 1`) only on ascending elements, it will inevitably stop moving right when it hits the peak, mathematically preventing `mid` from ever reaching the absolute last index (`n - 1`).
