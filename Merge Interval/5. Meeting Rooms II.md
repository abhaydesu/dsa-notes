> This lecture tackles one of the most frequently asked FAANG interview questions: **Minimum Meeting Rooms** (often framed as train stations, hotel rooms, or CPU scheduling). The instructor explains how this problem departs from the traditional "merge" logic and instead requires a chronological "Time-Based / Event-Based" approach to track the maximum overlap of simultaneous events.

## Problem Statement: Minimum Meeting Rooms

Given an array of meeting time intervals consisting of start and end times `[[s1,e1], [s2,e2], ...]`, find the minimum number of conference rooms required so that no two meetings overlap in the same room.

**Alternative Framings:**

- **Hotel:** Given check-in and check-out times, how many rooms do you need?
- **Railway Station:** Given train arrival and departure times, how many platforms do you need?
- **CPU:** Given process start and end times, how many threads/cores are required?

**Example:**

- `Start Times: [2, 9, 6]`
- `End Times: [4, 12, 10]`
- **Result:** 2 Rooms.

## Logic & Intuition (The "Hotel Owner" Analogy)

Imagine you own a hotel that is currently under construction. You have zero rooms. You decide to only build a room exactly when a guest arrives and needs one. If a guest leaves, you demolish the room (or just mark it free).

Your goal is to find the **maximum number of rooms that existed simultaneously** at any point in time.

### The Chronological Approach

Instead of looking at intervals as pairs `[start, end]`, decouple them. Treat every `start` time and `end` time as an independent **Event** on a timeline.

- A **Start Event (Check-in):** A guest arrives. You _must_ allocate a room. (`rooms++`)
- An **End Event (Check-out):** A guest leaves. A room becomes free. (`rooms--`)

To process these events chronologically (in order of time):

1. Separate the `start` times and `end` times into two distinct arrays.
2. **Sort** both arrays independently in ascending order. (We don't care _who_ is leaving, we only care _when_ a room becomes free).
3. Use **Two Pointers** (`i` for start times, `j` for end times) to walk through the timeline.

### Handling Ties (Start Time == End Time)

If one meeting ends at 10:00 AM and another starts exactly at 10:00 AM, do you need a new room?

**No.** The standard convention is that the departing guest leaves _before_ the new guest arrives.

Therefore, if `start[i] == end[j]`, process the **End Event** first (`rooms--`, advance `j`) to free up the resource before allocating it to the new arrival.

## Pseudo-code: Minimum Meeting Rooms
```cpp
function minMeetingRooms(start_times, end_times):
    n = length of start_times
    
    // Step 1: Sort both arrays independently
    sort(start_times)
    sort(end_times)
    
    // Step 2: Initialize trackers
    rooms = 0
    max_rooms = 0
    
    i = 0 // Pointer for start_times (Arrivals)
    j = 0 // Pointer for end_times (Departures)
    
    // Step 3: Traverse the timeline using Two Pointers
    while i < n and j < n:
        
        // If a meeting is starting before the next one ends (or there's a conflict)
        if start_times[i] < end_times[j]:
            // Allocate a room
            rooms = rooms + 1
            // Update the global maximum of simultaneous rooms
            max_rooms = max(max_rooms, rooms)
            // Advance the start pointer
            i = i + 1
            
        // If a meeting is ending before (or exactly when) the next one starts
        else:
            // Free a room
            rooms = rooms - 1
            // Advance the end pointer
            j = j + 1
            
    // (Note: Once 'i' goes out of bounds, no new meetings are starting. 
    // We don't need to process the remaining 'j' elements because they 
    // will only decrease the room count, which doesn't affect our max_rooms).
            
    return max_rooms
```

## Complexity Analysis

- **Time Complexity:** $O(N \log N)$. Sorting the `start_times` and `end_times` arrays takes $O(N \log N)$ time. The subsequent two-pointer traversal takes $O(N)$ time. The sorting dominates the complexity.
- **Space Complexity:** $O(N)$. We need to separate the input intervals into two distinct arrays of size $N$ for sorting.

## Active Recall

**Q: In the "Minimum Meeting Rooms" problem, why do we separate the start and end times and sort them independently, breaking the original `[start, end]` pairings?**

**A:** Because we are evaluating resource usage over a chronological timeline. We don't care _which_ specific meeting is ending; we only care that _a_ room becomes available at a specific time. Sorting them independently allows us to process arrivals and departures purely based on when they occur.

**Q: When traversing the timeline with Two Pointers (`i` for start, `j` for end), why do we process the end time if `start[i] == end[j]`?**

**A:** By convention, if a meeting ends at the exact same time another starts, the departing group vacates the room first. By processing the end time first (`rooms--`), we free up the existing room so the new meeting can use it, preventing us from unnecessarily allocating an extra room.

**Q: In the Two Pointer `while` loop, why do we use `while (i < n and j < n)` and stop processing once `i` (the start pointer) reaches the end of its array?**

**A:** Our goal is to find the _maximum_ number of rooms needed. The room count only increases when we process a start time. Once `i` reaches the end of the array, there are no more arrivals. The remaining elements in the `j` array will only represent departures (`rooms--`), which can never increase the `max_rooms` count. Therefore, processing them is unnecessary.
