## Problem Statement: Overlapping Intervals

You are given an array of intervals. Your task is to simply determine if there are **any** overlapping intervals within the array. Return `true` if an overlap exists, and `false` otherwise.

**Example:**

- `intervals = [[1, 3], [5, 7], [2, 4], [6, 8]]`
- In this array, `[1, 3]` and `[2, 4]` overlap. Therefore, the function should return `true`.

## Logic & Intuition

If you have already mastered the "Merge Intervals" pattern (Lecture 31), this problem is trivial. The logic for merging intervals relies fundamentally on _detecting_ overlaps first. Therefore, we use the exact same overlap detection logic, but instead of merging them, we simply return `true` the moment an overlap is found.

### The Algorithm:

1. **Sort the Intervals:** The input array is often unsorted (as seen in the example). Before evaluating intervals, you **must** sort them by their start times. This is the core proposition of the Merge Interval pattern.
2. **Initialize Trackers:** Set `start1` and `end1` to the bounds of the first interval.
3. **Iterate and Compare:** For every subsequent interval (`start2`, `end2`):
    - **Check Overlap:** Is `end1 >= start2`? If yes, an overlap exists. Immediately return `true`.
    - **Update Trackers (No Overlap):** If they don't overlap, it means the current interval is completely disjoint from the running interval. Update your trackers to move forward. `start1` remains the same (as it is the absolute minimum of the current sequence), and `end1` becomes `max(end1, end2)`.
4. **Final Return:** If the loop finishes without returning `true`, it means no overlaps were found in the entire array. Return `false`.

## Pseudo-code: Check for Overlapping Intervals
```cpp
function hasOverlap(intervals):
    n = length of intervals
    if n <= 1: return false // 0 or 1 interval cannot overlap
    
    // Step 1: Crucial - Sort by start time
    sort(intervals by intervals[i][0])
    
    // Step 2: Initialize trackers with the first interval
    start1 = intervals[0][0]
    end1 = intervals[0][1]
    
    // Step 3: Iterate through the remaining intervals
    for i = 1 to n - 1:
        start2 = intervals[i][0]
        end2 = intervals[i][1]
        
        // Check for overlap condition
        if end1 >= start2:
            return true // Found an overlap, no need to continue
            
        // No overlap, update trackers to continue checking
        start1 = start1 // (Conceptually remains the same)
        end1 = max(end1, end2)
        
    // Step 4: Loop completed without finding any overlaps
    return false
```

## Complexity Analysis

- **Time Complexity:** $O(N \log N)$. The dominant operation is sorting the array at the beginning. The subsequent linear scan to check for overlaps takes $O(N)$ time.
- **Space Complexity:** $O(1)$ auxiliary space (ignoring the space required by the sorting algorithm, which can be $O(\log N)$ or $O(N)$ depending on the language implementation).

## Active Recall

**Q: In the "Merge Interval" pattern, what is the mandatory first step before checking any overlap conditions?**

**A:** You must sort the array of intervals by their start times. Without sorting, the logical check `end1 >= start2` will not reliably detect overlaps across the entire dataset.

**Q: If you are iterating through a sorted array of intervals and checking for overlaps, what does it mean if `end1 < start2`?**

**A:** It means there is no overlap between the currently tracked interval and the interval you are evaluating. The evaluated interval starts strictly after the tracked interval has completely finished.

Once you master the core logic of a pattern (like checking `end1 >= start2` for intervals), you can immediately apply that exact same logic to quickly solve related problems (like merging, inserting, or just checking for overlaps) without needing to re-learn the fundamental mechanics from scratch.
