## Problem: Search in Rotated Sorted Array (LeetCode 33)

**Problem Statement:** There is an integer array `nums` sorted in ascending order (with distinct values). Prior to being passed to your function, `nums` is possibly rotated at an unknown pivot index.

For example, `[0,1,2,4,5,6,7]` might be rotated at pivot index 3 and become `[4,5,6,7,0,1,2]`.

Given the array `nums` after the possible rotation and an integer `target`, return the index of `target` if it is in `nums`, or `-1` if it is not in `nums`.

_You must write an algorithm with $O(\log n)$ runtime complexity._

## Intuition & Logic (Visualizing the "Mall" Topology)

Imagine a mall where shops are arranged by price, but the mall has been split into two distinct sections due to rotation.

- **Part 1:** High prices that are sorted (`[50, 60, 70, 80, 90, 100]`)
    
- **Part 2:** Low prices that are sorted (`[10, 20, 30, 40]`)
    

**Key Property:** Every element in Part 1 is strictly greater than every element in Part 2.

We can instantly tell which part an element belongs to by comparing it to the absolute last element in the array (`arr[n-1]`):

- If `arr[mid] > arr[n-1]`: `mid` is in **Part 1**.
    
- If `arr[mid] <= arr[n-1]`: `mid` is in **Part 2**.
    

### The Guessing Strategy

When we guess a middle shop (`mid`), we must determine if our `target` lies to the left or to the right. Because of the rotation, the standard binary search logic (`if arr[mid] < target: go right`) breaks down.

We must break the logic into two main branches based on where our `mid` guess landed:

#### Scenario A: The Guess is in Part 1 (`arr[mid] > arr[n-1]`)

Let's say `arr[mid] = 80`.

1. **If `target > 80` (e.g., `target = 90`):**
    
    Look at the visual topology. Numbers greater than 80 in Part 1 only exist to the right. There are no numbers $>80$ in Part 2. **Go Right (`low = mid + 1`)**.
    
2. **If `target < 80` (e.g., `target = 30` or `60`):**
    
    Here is the tricky part! Numbers less than 80 exist on BOTH the left side (e.g., `60`) and the right side (e.g., `30` in Part 2).
    
    We must use the leftmost boundary of Part 1 (`arr[0]`) to decide:
    
    - If `arr[0] > target` (e.g., `50 > 30`): The target is smaller than the smallest element in Part 1. It cannot exist in Part 1. It must be in Part 2. **Go Right.**
        
    - If `arr[0] <= target` (e.g., `50 <= 60`): The target falls within the range of the left half of Part 1. **Go Left.**
        

#### Scenario B: The Guess is in Part 2 (`arr[mid] <= arr[n-1]`)

Let's say `arr[mid] = 20`.

1. **If `target < 20` (e.g., `target = 10`):**
    
    Numbers less than 20 in Part 2 only exist to the left. There are no numbers $<20$ in Part 1. **Go Left (`high = mid - 1`)**.
    
2. **If `target > 20` (e.g., `target = 30` or `70`):**
    
    Numbers greater than 20 exist on BOTH the right side (e.g., `30`) and the left side (e.g., `70` in Part 1).
    
    We must use the rightmost boundary of Part 2 (`arr[n-1]`) to decide:
    
    - If `arr[n-1] < target` (e.g., `40 < 70`): The target is larger than the largest element in Part 2. It cannot exist in Part 2. It must be in Part 1. **Go Left.**
        
    - If `arr[n-1] >= target` (e.g., `40 >= 30`): The target falls within the range of the right half of Part 2. **Go Right.**
        

## Pseudo-code: One-Pass Binary Search

```cpp
function searchRotatedArray(nums, target):
    n = length of nums
    low = 0
    high = n - 1
    
    while low <= high:
        mid = low + (high - low) / 2
        
        // Exact match found
        if nums[mid] == target:
            return mid
            
        // Determine which part of the array 'mid' is in
        if nums[mid] > nums[n - 1]:
            // ----------------------------------------------------
            // SCENARIO A: 'mid' is in Part 1 (Left, larger segment)
            // ----------------------------------------------------
            if nums[mid] < target:
                // Target is even larger. Must be to the right.
                low = mid + 1
            else:
                // Target is smaller than mid. It could be on the left or in Part 2 (right).
                if nums[0] > target:
                    // Target is smaller than the smallest element of Part 1. Go to Part 2.
                    low = mid + 1
                else:
                    // Target is within the left side of Part 1.
                    high = mid - 1
                    
        else:
            // ----------------------------------------------------
            // SCENARIO B: 'mid' is in Part 2 (Right, smaller segment)
            // ----------------------------------------------------
            if nums[mid] > target:
                // Target is even smaller. Must be to the left.
                high = mid - 1
            else:
                // Target is larger than mid. It could be on the right or in Part 1 (left).
                if nums[n - 1] < target:
                    // Target is larger than the largest element of Part 2. Go to Part 1.
                    high = mid - 1
                else:
                    // Target is within the right side of Part 2.
                    low = mid + 1
                    
    return -1
```

## Complexity Analysis

- **Time Complexity:** $O(\log N)$. We perform a single binary search pass. The logic to decide whether to move left or right consists purely of $O(1)$ bounds checking.
    
- **Space Complexity:** $O(1)$. Only three tracking variables (`low`, `high`, `mid`) are required.
    

## Active Recall

**Q: In an interview, why might the two-pass method (find minimum first, then search the appropriate half) be rejected in favor of the one-pass method?**

**A:** While the two-pass method is logically sound and mathematically evaluates to $O(\log N)$ time, interviewers often look for optimal code cleanliness and mastery of the state space. The one-pass method demonstrates a deeper understanding of how rotation visually affects boundaries, merging two binary search operations into a single, elegant loop.

**Q: When your `mid` guess lands in Part 1 (`arr[mid] > arr[n-1]`), and your `target` is less than `arr[mid]`, why must you check the target against `arr[0]`?**

**A:** Because elements smaller than `arr[mid]` exist on _both_ sides of `mid`. The elements to the immediate left of `mid` are smaller, but the entire Part 2 (to the right of `mid`) is also smaller. Checking against `arr[0]` (the absolute minimum of Part 1) tells you if the target belongs to the left half of Part 1 (`arr[0] <= target`) or if it's so small it must belong to Part 2 (`arr[0] > target`).

**Q: Why doesn't the one-pass algorithm break if the array is actually completely sorted (rotated $0$ times)?**

**A:** If the array is not rotated (e.g., `[10, 20, 30, 40]`), `arr[mid]` will never be strictly greater than `arr[n-1]`. The execution will always fall into the `else` block (Scenario B). Inside Scenario B, the check `nums[n-1] < target` ensures that if the target is out of bounds (which it shouldn't be if it's in a sorted array), it behaves correctly. For standard targets, it cleanly executes normal binary search logic.
