##  Problem Statement: Allocate Minimum Number of Pages

You are given an array `books` where `books[i]` represents the number of pages in the `i-th` book. You are also given an integer `k` representing the number of students.

**Rules for Allocation:**

1. Every student must get at least one book.
    
2. Every book must be allocated to a student.
    
3. One book can only be given to one student (you cannot split a book).
    
4. Books must be allocated in a **contiguous** sequence (e.g., a student can get books 1 and 2, but not 1 and 3).
    

**Task:** Allocate the books in such a way that the **maximum number of pages assigned to a single student is minimized**. Return this minimized maximum value.

**Example:**

- `books = [12, 34, 67, 90]`
    
- `k = 2` students
    
- **Output:** `113`
    
    _(Explanation: The optimal contiguous split is `[12, 34, 67]` to Student 1 (Total: 113 pages) and `[90]` to Student 2 (Total: 90 pages). The maximum pages given to a student here is 113. Any other split results in a higher maximum)._
    

## Logic & Intuition (Decoding "Minimize the Maximum")

The phrase "Minimize the Maximum" is the biggest clue that you must use **Binary Search on Answers**.

Instead of trying to calculate exactly how to partition the array, let's reverse the problem. Let's **guess** a limit (the maximum number of pages any single student is allowed to receive) and see if it's possible to distribute the books without exceeding this limit.

### 1. Formulating the Binary Search Space

Can we define a valid range for our guesses? Yes.

- **Minimum Possible Answer (`low`):** `max(books)`. Why? Because you must allocate every book. Even if you have 100 students and give the largest book (e.g., `90` pages) to one student all by itself, that student still receives `90` pages. The limit cannot physically be less than the largest single book.
    
- **Maximum Possible Answer (`high`):** `sum(books)`. Why? If there is only 1 student, they receive all the books. The maximum pages they get is simply the sum of all pages in the array.
    

### 2. The Monotonic State Space

Suppose our array is `[12, 34, 67, 90]` and `k = 2`.

- If we guess a limit of `100`, is it possible?
    
    - Student 1 takes `12, 34` (Sum = 46). They cannot take `67` because $46 + 67 = 113$, which exceeds 100.
        
    - Student 2 takes `67`. They cannot take `90` because $67 + 90 = 157 > 100$.
        
    - We have a book leftover (`90`), but we are out of students! **Limit 100 is NOT POSSIBLE (False).**
        
- If a limit of `100` fails, a limit of `90` will definitely fail. (If a backpack can't hold 10kg, it definitely can't hold 9kg).
    
- If a limit of `150` succeeds, a limit of `200` will definitely succeed.
    
- **State Space:** `[False, False, False, True, True, True]`
    
- We want to **Minimize** the valid limit. We are looking for the **First True**.
    

## The Helper Function: Validating the Guess

Given a `guess` (a hard limit on pages per student), can we distribute all the books to `k` students?

We use a **Greedy Approach**:

1. Start with Student 1. Keep giving them books one by one.
    
2. Before giving a book, check: `Current_Pages + Next_Book <= guess`.
    
3. If yes, give them the book and add to their total.
    
4. If no, this student is "full". Bring in the next student (`students_used++`). Give the current book to this new student.
    
5. If at any point `students_used > k`, we have run out of students before running out of books. Return `False`.
    
6. If we distribute all books successfully, return `True`.
    

```cpp
function canDistribute(books, k, limit):
    students_used = 1
    current_pages = 0
    
    for i = 0 to length(books) - 1:
        if current_pages + books[i] <= limit:
            // The student can take this book without exceeding the limit
            current_pages = current_pages + books[i]
        else:
            // The student is full. Bring in the next student.
            students_used = students_used + 1
            current_pages = books[i] // New student starts with this book
            
            if students_used > k:
                return false // Ran out of students
                
    return true
```

## Pseudo-code: Binary Search on Answers

```cpp
function findPages(books, k):
    n = length of books
    
    // Edge case: If there are fewer books than students, allocation is impossible.
    if n < k:
        return -1
        
    // Step 1: Define the Search Space
    low = max(books)
    high = sum(books)
    
    best_ans = -1
    
    // Step 2: Apply Binary Search
    while low <= high:
        mid = low + (high - low) / 2  // 'mid' is our guessed limit
        
        // Step 3: Validate the guess
        if canDistribute(books, k, mid) == true:
            // We CAN distribute all books with 'mid' as the maximum limit.
            // This is a valid answer. Record it.
            best_ans = mid
            
            // We want to MINIMIZE this limit (First Occurrence of YES).
            // Search LEFT to see if a tighter limit also works.
            high = mid - 1
            
        else:
            // We CANNOT distribute the books. The limit 'mid' is too strict.
            // Result is "NO". We must increase the limit. Go RIGHT.
            low = mid + 1
            
    return best_ans
```

## Complexity Analysis

- **Time Complexity:** $O(N \log (\text{Sum} - \text{Max}))$.
    
    - The binary search space is the difference between the sum of the array and its maximum element. Finding the `mid` takes $O(\log (\text{Range}))$ iterations.
        
    - In each iteration, `canDistribute` traverses the array, taking $O(N)$ time.
        
    - Total time is strictly $N \log(\text{Range})$.
        
- **Space Complexity:** $O(1)$. We only modify existing pointers (`low`, `high`, `mid`, `students_used`). No recursive stacks or external arrays are used.
    

## Active Recall

**Q: Why doesn't the Book Allocation problem require sorting the input array, unlike the Aggressive Cows problem?**

**A:** The problem statement explicitly requires **contiguous assignment** (you can only give a student a continuous sequence of books, e.g., books at index 0, 1, 2). Sorting the array would completely destroy the original ordering and violate the contiguous allocation constraint.

**Q: In defining the search space, why is `low` set to `max(books)` rather than `0` or `min(books)`?**

**A:** Because books cannot be divided. If you must assign every book to a student, the student receiving the largest book in the array will always receive _at least_ that many pages. Therefore, it is physically impossible for the maximum pages assigned to any student to be less than the size of the single largest book.

**Q: What happens if the `canDistribute` function finishes assigning all books but the number of `students_used` is strictly less than `k`? Does it return True or False?**

**A:** It returns `True`. If you can successfully assign all books to _fewer_ students than required without exceeding the page limit, you can always just take a book from one of the "full" students and hand it to an empty student. This redistributes the load, meaning the limit was completely valid.

**Q: If `canDistribute` returns `True`, why do we update `high = mid - 1`?**

**A:** Returning `True` means our guessed limit worked. Because the problem asks to _Minimize the Maximum_, we record the successful guess but push the search space to the left to see if we can distribute the books successfully with an even smaller limit.
