## Problem: Find Minimum in Rotated Sorted Array (LeetCode 153)

**Problem Statement:** Suppose an array of length `n` sorted in ascending order is rotated between `1` and `n` times. For example, the array `nums = [0,1,2,4,5,6,7]` might become:

- `[4,5,6,7,0,1,2]` if it was rotated 4 times.
    
- `[0,1,2,4,5,6,7]` if it was rotated 7 times (or 0 times).
    

Notice that rotating an array `[a[0], a[1], a[2], ..., a[n-1]]` 1 time results in the array `[a[n-1], a[0], a[1], a[2], ..., a[n-2]]`.

Given the sorted rotated array `nums` of **unique** elements, return the minimum element of this array.

_You must write an algorithm that runs in $O(\log n)$ time._

## Logic & Intuition (The "Part 1 vs. Part 2" Analogy)

If an array is strictly sorted, finding the minimum is trivial: it is `arr[0]`. However, due to rotation, the minimum element has been shifted somewhere into the middle of the array.

### What physically happens during rotation?

Consider the original sorted array: `[1, 2, 3, 4, 5, 6, 7]`.

Let's divide it into two parts based on an arbitrary rotation point:

- **Part 1:** `[1, 2, 3, 4]` (The smaller elements at the beginning)
    
- **Part 2:** `[5, 6, 7]` (The larger elements at the end)
    

When rotated, **Part 2** is picked up and placed in front of **Part 1**.

- **Rotated Array:** `[5, 6, 7, 1, 2, 3, 4]`
    

### Visualizing the Monotonic State Space

If we plot the values of the rotated array `[5, 6, 7, 1, 2, 3, 4]`, it looks like this:

1. High values that are increasing (`5, 6, 7` $\rightarrow$ **Part 2**)
    
2. A sudden, massive drop off a cliff.
    
3. Low values that are increasing (`1, 2, 3, 4` $\rightarrow$ **Part 1**)
    

What exactly are we looking for? **The minimum element.**

Looking at the structure, the minimum element is simply the **First Element of Part 1**.

### The Predicate Function (How to distinguish P1 from P2?)

To use Binary Search, we need to guess an index (`mid`) and answer a simple question: _Does this index belong to Part 1 or Part 2?_

Look at the last element of the rotated array (`arr[n-1]`), which is `4`.

- Every element in Part 2 (`5, 6, 7`) is strictly **greater** than `4`.
    
- Every element in Part 1 (`1, 2, 3, 4`) is strictly **less than or equal to** `4`.
    

_(Why? Because Part 2 represents the absolute largest elements from the original sorted array, making them strictly larger than the largest element of Part 1, which sits at the very end of the rotated array)._

**The Mathematical Check:**

If `arr[mid] > arr[n - 1]`: The guess is in **Part 2**.

If `arr[mid] <= arr[n - 1]`: The guess is in **Part 1**.

**State Space Representation:**

`[Part 2, Part 2, Part 2, Part 1, Part 1, Part 1, Part 1]`

This is perfectly Monotonic! We just need to find the **First Occurrence of Part 1**.

## Pseudo-code: Minimum in Rotated Sorted Array

```cpp
function findMin(nums):
    n = length of nums
    low = 0
    high = n - 1
    best_ans = -1
    
    while low <= high:
        // Guess the middle index
        mid = low + (high - low) / 2
        
        // Predicate: Does 'mid' belong to Part 2?
        if nums[mid] > nums[n - 1]:
            // It belongs to Part 2. 
            // The minimum (start of Part 1) must be further to the right.
            low = mid + 1
            
        else:
            // It belongs to Part 1. 
            // This is a potential minimum. Record it.
            best_ans = mid
            
            // However, we want the FIRST occurrence of Part 1.
            // Force the search space to the LEFT to see if Part 1 started earlier.
            high = mid - 1
            
    // best_ans holds the index of the minimum element. 
    // The problem asks for the actual number.
    return nums[best_ans]
```

### Edge Case Check: What if the array is NOT rotated?

Example: `[1, 2, 3, 4, 5]`

- `arr[n-1] = 5`.
    
- Is any element `> 5`? No.
    
- The predicate evaluation will be `[P1, P1, P1, P1, P1]`.
    
- Since every evaluation hits the `else` block (Part 1), `best_ans` continuously records the index and pushes `high` to the left.
    
- Eventually, `best_ans` will correctly settle on index `0` (the element `1`), and the loop will terminate. The logic holds perfectly even for unrotated arrays!
    

## Complexity Analysis

- **Time Complexity:** $O(\log N)$. We halve the search space during each iteration based on a constant time $O(1)$ comparison against the last element of the array.
    
- **Space Complexity:** $O(1)$. Only three variables (`low`, `high`, `mid`) are maintained throughout the execution.
    

## Active Recall

**Q: In a rotated sorted array, why is comparing `arr[mid]` to `arr[n-1]` a reliable way to determine which "part" of the array you are currently looking at?**

**A:** A rotated sorted array consists of two sorted segments: the larger elements moved to the front (Part 2) and the smaller elements pushed to the back (Part 1). Because the array contains unique elements, every element in Part 2 is mathematically guaranteed to be strictly greater than the largest element of Part 1 (which always sits at the very end of the array, `arr[n-1]`). Therefore, comparing against `arr[n-1]` definitively splits the state space monotonically.

**Q: If `arr[mid] > arr[n-1]`, in which direction do we shift our search space, and why?**

**A:** We shift to the right (`low = mid + 1`). If `arr[mid]` is greater than the last element, it belongs to "Part 2" (the larger, front segment). We are searching for the minimum element, which marks the beginning of "Part 1". Therefore, we must move right to step off the "Part 2 cliff" and drop down into "Part 1".

**Q: When we find an element belonging to Part 1 (`arr[mid] <= arr[n-1]`), why do we record it and continue searching to the left (`high = mid - 1`) instead of immediately returning it?**

**A:** Because _every_ element in Part 1 is less than or equal to `arr[n-1]`. Simply finding an element in Part 1 doesn't guarantee it is the _minimum_ element. The minimum is specifically the _first_ occurrence (leftmost element) of Part 1. We must search left to see if the drop-off point happened earlier.
