## Overview: The "Pratyush Mall" Analogy

Before diving into the questions, the instructor frames Binary Search using the **Pratyush Mall** analogy:

- Imagine a massive mall where shops are strictly arranged from left to right in **increasing order of shirt prices**.
    
- Because the mall is sorted, checking a shop in the middle gives you absolute certainty about the rest of the mall.
    
- The core of Binary Search isn't just `mid = low + high / 2`; it is **Search Space Reduction**. By making one guess, you can confidently eliminate half of the remaining options.
    
- _Rule of Thumb:_ Your guess must yield a **monotonic** result (e.g., a sequence of `False` followed by a sequence of `True`, or `Less` followed by `More`).
    

##  Question 1: Standard Binary Search (Exact Match)

### Problem Statement

Given a sorted array of distinct integers and a target value `x`, return the index if the target is found. If not, return `-1`.

_Analogy:_ You have exactly ₹30. Find the shop that sells a shirt for exactly ₹30.

### Instructor's Breakdown

- **The Pattern:** If you map the array against your target, the conditions will look like this: `Less, Less, Less, EQUAL, More, More, More`.
    
- **The Actions:**
    
    1. If `arr[mid] == target`: You found the exact shop. Return the index immediately.
        
    2. If `arr[mid] < target`: You are in the `Less` zone. The ₹30 shop must be to the right. Eliminate the left half (`low = mid + 1`).
        
    3. If `arr[mid] > target`: You are in the `More` zone. The ₹30 shop must be to the left. Eliminate the right half (`high = mid - 1`).
        
- If `low` becomes greater than `high`, it means the search space is exhausted and the shop doesn't exist.
    

> **External Knowledge Context:** Standard Binary Search runs in $O(\log n)$ time and $O(1)$ space. Because the search space halves every iteration, an array of 1,000,000 elements takes at most ~20 comparisons to find the target or prove it's missing.

### Pseudo-Code

```cpp
function standardBinarySearch(arr, target):
    low = 0
    high = arr.length - 1
    
    while low <= high:
        mid = low + (high - low) / 2
        
        if arr[mid] == target:
            return mid
        else if arr[mid] < target:
            low = mid + 1 // Eliminate left
        else:
            high = mid - 1 // Eliminate right
            
    return -1 // Target not found
```

##  Question 2: Find the "Ceiling" (Greater Than or Equal To)

### Problem Statement

Find the index of the smallest element in the array that is **greater than or equal to** `x`.

_Analogy:_ You want a shirt that costs at least ₹30, but you want the cheapest one possible from that valid pool (e.g., if no ₹30 shirt exists, a ₹32 or ₹35 shirt is fine, but ₹40 is worse than ₹35).

### Instructor's Breakdown

- **The Pattern:** Your array now breaks down into two zones: `Less` and `More (which includes Equal)`.
    
    `Less, Less, Less, MORE, MORE, MORE`.
    
- **The Actions:**
    
    1. If `arr[mid] < target`: You are in the `Less` zone (e.g., ₹25). This is useless. Eliminate the left half (`low = mid + 1`).
        
    2. If `arr[mid] >= target`: You are in the `More` zone (e.g., ₹45). **This could be the answer.**
        
        - _Customer Logic:_ You tell the shopkeeper, "I'll bookmark your shop, but let me check the left side of the mall to see if there's a cheaper valid shirt."
            
        - Store the index (`ans = mid`) and eliminate the right half (`high = mid - 1`).
            

> ** External Knowledge Context (Crucial Naming Distinction):** The instructor refers to this as "Upper Bound". However, in standard C++ STL and general algorithmic terminology, finding the first element $\ge x$ is called the **Lower Bound** (`std::lower_bound`). The **Upper Bound** (`std::upper_bound`) specifically finds the first element strictly $> x$. Keep this in mind when solving problems on LeetCode or using built-in language functions!

### Pseudo-Code

```cpp
function findCeil(arr, target):
    low = 0
    high = arr.length - 1
    ans = -1
    
    while low <= high:
        mid = low + (high - low) / 2
        
        if arr[mid] < target:
            // Too small, eliminate left
            low = mid + 1
        else:
            // Valid candidate! Store it, but keep searching left for a smaller valid one
            ans = mid
            high = mid - 1
            
    return ans
```

##  Question 3: First and Last Occurrence of an Element

### Problem Statement

Given a sorted array that contains duplicates, find the starting (first) and ending (last) position of a given target value.

_Analogy:_ There are multiple shops selling a ₹30 shirt side-by-side. You need to find the leftmost ₹30 shop and the rightmost ₹30 shop.

### Instructor's Breakdown

Instead of stopping as soon as you find the target (like in Question 1), you must recognize that finding the target just means you've hit _a_ valid shop, not necessarily the _first_ or _last_ one.

**For the First Occurrence:**

- **Pattern:** `Less, Less, EQUAL, EQUAL, EQUAL, More, More`
    
- When you hit `EQUAL` (`arr[mid] == target`), you store it (`ans = mid`).
    
- To find if it's the _first_ occurrence, where do you look? The left! So, you eliminate the right half: `high = mid - 1`.
    

**For the Last Occurrence:**

- The logic is identical, but inverted.
    
- When you hit `EQUAL`, store it (`ans = mid`).
    
- To find if there's a _later_ occurrence, where do you look? The right! So, you eliminate the left half: `low = mid + 1`.
    

> **🌍 External Knowledge Context:** You can solve this by writing two separate Binary Search functions (one for First, one for Last) and calling them consecutively. The total time complexity remains $O(\log n) + O(\log n) = O(\log n)$, which is perfectly optimal.

### Pseudo-Code

```cpp
function findFirstOccurrence(arr, target):
    low = 0; high = arr.length - 1; ans = -1
    
    while low <= high:
        mid = low + (high - low) / 2
        
        if arr[mid] == target:
            ans = mid
            high = mid - 1 // Found it, but keep searching LEFT
        else if arr[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
            
    return ans

function findLastOccurrence(arr, target):
    low = 0; high = arr.length - 1; ans = -1
    
    while low <= high:
        mid = low + (high - low) / 2
        
        if arr[mid] == target:
            ans = mid
            low = mid + 1 // Found it, but keep searching RIGHT
        else if arr[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
            
    return ans
```
