> [!abstract] **Lecture Context**

> This lecture tackles an advanced and highly frequently asked interview variation of Kadane's algorithm: **Maximum Subarray Sum with One Deletion**. It requires extending the standard "best ending here" logic to maintain _two_ distinct states. The lecture also briefly covers the **Maximum Absolute Sum of Any Subarray** problem to demonstrate how simple logical extensions of Kadane's can solve entirely new problems.

## Problem 1: Maximum Subarray Sum with One Deletion

**Problem Statement:** Given an array of integers, return the maximum sum for a non-empty contiguous subarray. However, you are allowed to choose at most **one** element from the subarray and delete (ignore) it. (LeetCode 1186).

### Intuition & Logic

In standard Kadane's Algorithm, you track exactly one state at index `i`:

- `no_delete`: The maximum sum of a subarray ending at index `i` with _zero_ deletions.

Because the problem allows us an option (a "power") to delete exactly one element, we must now track **two distinct states** at every index `i`:

1. `no_delete`: The max subarray sum ending at `i` with 0 deletions. (This is identical to standard Kadane's).
2. `one_delete`: The max subarray sum ending at `i` where exactly _one_ element has been deleted.

**How do we update `one_delete` at index `i`?**

To calculate the best `one_delete` ending at `i`, we have exactly two choices:

- **Choice A:** The deletion already happened somewhere before index `i`. Therefore, we must take the previous `one_delete` state and simply add the current element `arr[i]` to it.
- **Choice B:** We decide to use our "delete power" exactly on the current element `arr[i]`. If we delete `arr[i]`, we must attach it to a subarray that has had _zero_ deletions so far. Therefore, we take the previous `no_delete` state. (If we attached it to the previous `one_delete` state, we would be performing _two_ deletions, which is illegal).

### Pseudo-code
```cpp
function maximumSumWithOneDeletion(arr):
    n = length of arr
    
    // Initialize state variables with the first element
    no_delete = arr[0]
    one_delete = 0 // Conceptually invalid for a 1-element array
    
    // Result starts as arr[0]
    max_sum = arr[0]
    
    for i = 1 to n - 1:
        // Store previous states before updating them
        prev_no_delete = no_delete
        prev_one_delete = one_delete
        
        // 1. Update no_delete (Standard Kadane's)
        no_delete = max(prev_no_delete + arr[i], arr[i])
        
        // 2. Update one_delete
        // Edge case: If previous one_delete hasn't been properly formed yet
        if i == 1:
            // First possible deletion is dropping arr[1] and keeping arr[0] (which is prev_no_delete)
            one_delete = prev_no_delete
        else:
            // Choice A: Deletion happened before, add current arr[i]
            // Choice B: Delete current arr[i], take previous no_delete
            one_delete = max(prev_one_delete + arr[i], prev_no_delete)
            
        // 3. Update global maximum
        max_sum = max(max_sum, max(no_delete, one_delete))
        
    return max_sum
```

## Problem 2: Maximum Absolute Sum of Any Subarray

**Problem Statement:** Given an integer array, find the maximum absolute sum of any contiguous subarray. (LeetCode 1749).

_Absolute sum implies `abs(sum)`. E.g., `abs(-10) = 10` and `abs(10) = 10`._

### Intuition & Logic

This problem is a "fake out" (a highly disguised simple problem).

Because we are looking for the maximum _absolute_ value, a subarray that yields a massive positive sum is great (e.g., `sum = 50` $\rightarrow$ `abs(50) = 50`).

However, a subarray that yields a massive _negative_ sum is equally great (e.g., `sum = -60` $\rightarrow$ `abs(-60) = 60`).

Therefore, the maximum absolute sum of an array will ALWAYS be either:

1. The Maximum Subarray Sum.
2. The Absolute value of the Minimum Subarray Sum.

### Pseudo-code
```cpp
function maxAbsoluteSum(arr):
    n = length of arr
    
    // Run standard Kadane's for Maximum Sum
    max_sum_ending = arr[0]
    global_max_sum = arr[0]
    
    // Run standard Kadane's for Minimum Sum
    min_sum_ending = arr[0]
    global_min_sum = arr[0]
    
    for i = 1 to n - 1:
        // Max sum logic
        max_sum_ending = max(max_sum_ending + arr[i], arr[i])
        global_max_sum = max(global_max_sum, max_sum_ending)
        
        // Min sum logic
        min_sum_ending = min(min_sum_ending + arr[i], arr[i])
        global_min_sum = min(global_min_sum, min_sum_ending)
        
    // Return the maximum of the positive sum or the absolute of the negative sum
    return max(global_max_sum, abs(global_min_sum))
```

## Active Recall

**Q: In the "Maximum Subarray Sum with One Deletion" problem, why must we track a `no_delete` state if the problem asks us about making a deletion?**

**A:** Because to make the choice to delete the _current_ element `arr[i]`, you must attach it to a contiguous subarray that has had _zero_ deletions so far. If you attached it to a state that already had a deletion, you would be making two deletions, violating the constraints.

**Q: For `one_delete` at index `i`, what does the choice `prev_one_delete + arr[i]` conceptually represent?**

**A:** It represents the decision that the single allowed deletion was already utilized on some element prior to index `i`. Because the deletion "power" is spent, we must include the current element `arr[i]` in our running sum.

**Q: Why does finding the "Maximum Absolute Sum" just require finding the Maximum Sum and Minimum Sum?**

**A:** Absolute value removes the negative sign from a number. Thus, a deeply negative sum (the minimum possible sum) will flip into a highly positive number. The maximum absolute sum must inherently be derived from either the highest positive peak (Max Sum) or the lowest negative valley (Min Sum) of the array.
