## Problem: Subarray Sums Divisible by K (LeetCode 974)

**Problem Statement:** Given an integer array `nums` and an integer `k`, return the number of non-empty subarrays that have a sum divisible by `k`.

### Intuition & The "Green/Red Part" Analogy

In the previous problem ("Subarray Sum Equals K"), the condition was exact. If the entire running sum is $Total$, and we want a "Green Part" (the valid subarray ending at our current position) to exactly equal $K$, the "Red Part" (the prefix we need to chop off) must equal $Total - K$.

**How does this change for divisibility by K?**

Suppose the `Total` running sum at index $i$ is `21`, and $K = 5$.

We want a valid subarray ("Green Part") whose sum is divisible by $5$. This means the Green Part could be $10, 15, 20, 30$, etc.

Let's assume the Green Part is `10`.

$$Red\_Part = Total - Green\_Part$$

$$Red\_Part = 21 - 10 = 11$$

Now let's check the remainders when dividing by $K=5$:

- `Total % K` $\rightarrow$ `21 % 5 = 1`
- `Red_Part % K` $\rightarrow$ `11 % 5 = 1`

_This is the core mathematical realization!_

If we want the remaining subarray (Green Part) to be perfectly divisible by $K$ (remainder $0$), the prefix we chop off (Red Part) must leave the **exact same remainder** as the Total sum when divided by $K$.

**The Mathematical Proof:**

Let `Total = 5x + y` (where `y` is the remainder).

Let the valid subarray `Green_Part = 5k` (since it must be divisible by 5).

$$Red\_Part = Total - Green\_Part$$

$$Red\_Part = (5x + y) - 5k = 5(x - k) + y$$

Since $5(x - k)$ is perfectly divisible by 5, the remainder of the Red Part is exactly $y$.

### The Hash Map Logic

Instead of tracking the actual prefix sums, we track the **frequencies of the remainders**.

- **Key:** The remainder of the prefix sum (`current_sum % k`).
- **Value:** The frequency (how many times we have seen this remainder).

**Goal:** At every index, calculate `rem = current_sum % k`. Then ask the Hash Map: _"How many times have I seen this exact remainder `rem` in the past?"_ Every past occurrence represents a valid prefix we can chop off to create a subarray divisible by $K$.

### Handling Negative Remainders in Programming Languages

In languages like C++ and Java, the modulo operator (`%`) on a negative number returns a negative remainder.

- Example: `-9 % 5 = -4`.
    In modular arithmetic, remainders must be positive. To find the true mathematical remainder, you add $K$ to the negative result.
- `-4 + 5 = 1`.
    Therefore, if `rem < 0`, you must adjust it: `rem = rem + k`.

## Pseudo-code: Subarray Sums Divisible by K
```cpp
function subarraysDivByK(nums, k):
    n = length of nums
    count = 0
    current_sum = 0
    
    // Hash map to store <Remainder, Frequency>
    rem_map = empty hash map
    
    // CRITICAL: Seed the map for subarrays that start at index 0
    // A running sum of 0 has a remainder of 0.
    rem_map[0] = 1
    
    for i = 0 to n - 1:
        // Step 1: Update the running total sum
        current_sum = current_sum + nums[i]
        
        // Step 2: Calculate the remainder
        rem = current_sum % k
        
        // Handle negative remainders (Language specific)
        if rem < 0:
            rem = rem + k
            
        // Step 3: Check how many times we've seen this remainder before
        if rem_map contains rem:
            count = count + rem_map[rem]
            
        // Step 4: Record the current remainder into the Hash Map
        if rem_map contains rem:
            rem_map[rem] = rem_map[rem] + 1
        else:
            rem_map[rem] = 1
            
    return count
```

### Complexity Analysis

- **Time Complexity:** $O(N)$. A single pass through the array. Calculating the modulo and performing hash map lookups take $O(1)$ constant time.
- **Space Complexity:** $O(K)$. The hash map only stores remainders, and there are only exactly $K$ possible remainders ($0$ to $K-1$). Therefore, the space complexity is bounded by $K$.

## Active Recall

**Q: In the "Subarray Sums Divisible by K" problem, why do we store the remainders in the Hash Map rather than the actual prefix sums?**

**A:** Because we are looking for a subarray that is a multiple of $K$. For the difference between a total prefix sum and an earlier prefix sum to be a multiple of $K$, both prefix sums must leave the exact same remainder when divided by $K$. Storing the actual sums would require scanning the map to calculate remainders, whereas tracking the remainders directly allows for instant $O(1)$ lookups.

**Q: Why does the modulo of a negative number (e.g., `-9 % 5`) return `-4` in many programming languages, and how do we logically correct it to the mathematical remainder of `1`?**

**A:** Programming languages often calculate modulo by truncating towards zero, leaving a negative remainder. Mathematically, the modulo is the distance to the next smaller multiple. For `-9` modulo `5`, the next smaller multiple is `-10`. The distance from `-10` to `-9` is `1`. We fix the programming language quirk by simply adding `K` to any negative remainder (`-4 + 5 = 1`).

**Q: Why is the space complexity for this problem $O(K)$ and not $O(N)$?**

**A:** Because the Hash Map stores the remainders of `Sum % K` as its keys. Regardless of how long the array ($N$) is, there are strictly only $K$ possible remainders (from $0$ up to $K-1$). Therefore, the maximum number of keys in the map is limited to $K$.

**Q: What does the initial seed `rem_map[0] = 1` mathematically represent in this algorithm?**

**A:** It represents an "empty" prefix sum of `0` occurring before the array starts. If a running sum up to index `i` is itself perfectly divisible by `K` (leaving a remainder of `0`), we need `rem_map` to acknowledge that we can "chop off" nothing and still have a valid subarray. Without `rem_map[0] = 1`, we would miss these valid subarrays starting exactly from index `0`.
