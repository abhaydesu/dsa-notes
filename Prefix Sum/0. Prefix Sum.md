## Concept: What is a Prefix Sum?

The term "Prefix" means "before" or "early", and "Sum" means addition.

In the context of an Array, the **Prefix Sum at index `i`** represents the total sum of all elements from index `0` up to index `i-1`.
- It asks the question: _"What is the sum of everything that came before me?"_

Similarly, the **Suffix Sum at index `i`** represents the total sum of all elements from index `i+1` to the end of the array.
- It asks the question: _"What is the sum of everything that comes after me?"_

### Why do we need it when we have Sliding Window?

Sliding Window is excellent for contiguous subarrays, **but it fails completely when negative numbers are introduced.**

- In Sliding Window, expanding the window (`high++`) is assumed to increase the sum, and shrinking the window (`low++`) is assumed to decrease it.
- If the array contains negative numbers, expanding the window might _decrease_ the sum (if you include a `-5`), and shrinking it might _increase_ the sum. You lose the ability to make logical decisions about pointer movement. Prefix Sum solves this.

## Pattern Identification: When to use Prefix Sum?

Use the following flowchart to identify Prefix Sum problems:

1. **Data Structure:** Array. (Prefix sum fundamentally relies on contiguous numeric indexing).
2. **Entity:** Subarrays or Ranges.
3. **The Dealbreaker (Why not Sliding Window?):** The array contains **Negative Numbers**.
4. **Goal/Keywords:**
    - Find the Sum of subarrays.
    - Count the number of subarrays with a specific sum `K`.
    - Find sub-arrays where the sum is _exactly_ `K` (or `Sum % K == 0`).
    - Compare the "Left part" of an array with the "Right part" (e.g., equilibrium or pivot point).

### The Four Tiers of Prefix Sum Problems

Depending on the exact question, Prefix Sum requires different auxiliary data structures:

1. **Simple Variables / Arrays (Easy):** Comparing Left vs Right sums (e.g., Pivot Index).
2. **Hash Maps (Medium):** Finding exact sums (`== K`) or modular sums (`% K == 0`).
3. **Deque (Hard):** Shortest window with `Sum >= K` containing negative numbers.
4. **Merge Sort on Prefix Array (Very Hard):** Complex Range Sum queries.

## Building Prefix and Suffix Arrays

### The Prefix Array Formula

To calculate the prefix sum at index `i`, you do not need to loop from `0` to `i-1`. You simply take the prefix sum from the previous index and add the previous element.

$$Prefix[i] = Prefix[i-1] + arr[i-1]$$

_(Note: $Prefix[0]$ is always $0$, as there is nothing before the first element)._

### The Suffix Array Formula

Suffix arrays are built backwards. To calculate the suffix sum at index `i`, you take the suffix sum from the next index and add the next element.

$$Suffix[i] = Suffix[i+1] + arr[i+1]$$

_(Note: $Suffix[N-1]$ is always $0$, as there is nothing after the last element)._


## Active Recall

**Q: Why is the Prefix Sum pattern required for subarray sum problems when the array contains negative numbers, rendering Sliding Window useless?**

**A:** Sliding Window relies on the logic that expanding the window increases the sum and shrinking the window decreases the sum. Negative numbers break this rule (expanding to include a negative number decreases the sum). Prefix Sum mathematically maps the cumulative sum at every point, allowing for constant-time sub-array sum lookups regardless of positive/negative fluctuations.

**Q: In the formula $Prefix[i] = Prefix[i-1] + arr[i-1]$, why are we adding $arr[i-1]$ instead of $arr[i]$?**

**A:** Because the prefix sum at index `i` is defined as the sum of all elements _strictly before_ index `i`. Therefore, it must include the element exactly preceding it ($arr[i-1]$), but not the element at the current index itself.

**Q: In the optimal $O(1)$ space solution for the Pivot Index problem, what is the mathematical formula used to dynamically calculate the `Right_Sum` without needing a Suffix Array?**

**A:** `Right_Sum = Total_Sum - arr[i] - Left_Sum`.

**Q: In the optimal Pivot Index algorithm, why is `left_sum` updated _after_ the `if (left_sum == right_sum)` check rather than before?**

**A:** Because the definition of the pivot index is that the left sum includes elements strictly _before_ the current index `i`. If we updated `left_sum` before the check, we would be incorrectly including `arr[i]` in the left sum while evaluating index `i`
