> This lecture explores the second major category of Prefix Sum problems: finding subarrays that meet an exact sum condition. The instructor explains why Sliding Window fails for arrays with negative numbers and details how combining Prefix Sums with Hash Maps provides an elegant $O(N)$ solution to problems asking for an "Exact Sum" or "Divisible Sum". The primary example used is the famous LeetCode 560: "Subarray Sum Equals K".

## Pattern Identification: When to use Prefix Sum + Hash Map?

Before writing code, verify if the problem fits this specific Prefix Sum category.

**The Flowchart Indicators:**

1. **Data Structure:** Array.
2. **Entity Required:** Subarray (must be contiguous elements).
3. **Goal/Keywords:** You need to find the `Count`, `Number of`, or check the `Existence` of subarrays.
4. **The Dealbreaker (Why not Sliding Window?):** The array contains a mix of **positive and negative numbers**. (Remember: expanding a window over a negative number decreases the sum, breaking the sliding window logic).
5. **The Specific Condition:** The required sum of the subarray must be:
    - **Exactly `K`:** (`Sum == K`)
    - **A multiple of `K`:** (`Sum % K == 0`)

If these 5 conditions are met, there is a 100% guarantee that the problem is solved using a **Running Prefix Sum + Hash Map**.

## The Mathematical Concept (The "Why")

How does knowing the sum from the beginning of the array help us find the sum of a subarray in the middle?

Imagine an array `[A, B, C, D, E]`.

Suppose you are currently at element `E` (index 4).

You have been keeping a running total from the start.

Let's call this the **Total Sum**: $A + B + C + D + E$.

You want to know if there is _any_ subarray ending at `E` whose sum is exactly $K$. (e.g., $D + E = K$, or $C + D + E = K$).

Let's assume the subarray $C + D + E$ equals exactly $K$.

Mathematically, we can write the Total Sum as:

$$(A + B) + (C + D + E) = Total\_Sum$$

Substitute $K$ into the equation:

$$(A + B) + K = Total\_Sum$$

Rearrange the formula to solve for $(A + B)$:

$$(A + B) = Total\_Sum - K$$

**The Epiphany:**

$(A + B)$ is simply a previously calculated Prefix Sum!

If we want to find a subarray ending at our current position that equals $K$, we just need to ask: **"Have I ever seen a prefix sum equal to $(Total\_Sum - K)$ in the past?"**

If the answer is yes, then cutting that prefix off our current `Total_Sum` leaves us with a subarray of exactly sum $K$.

## The Hash Map Logic

To quickly answer the question "Have I seen this prefix sum before, and how many times?", we use a Hash Map.

- **Key:** The Prefix Sum encountered.
- **Value:** The frequency (how many times we have seen this specific sum).

### The Critical Edge Case: `Map[0] = 1`

Before starting the loop, you must initialize the hash map with the key `0` and value `1` (`freq_map[0] = 1`).

**Why?**

Imagine your very first element is `K` (e.g., `arr = [3]`, `K = 3`).

Your `Total_Sum` is 3. Your formula asks: Have I seen `Total_Sum - K` $\rightarrow$ `3 - 3 = 0`?

If you haven't seeded the map with `0`, the map will say "No", and you will miss the fact that the prefix itself (from index 0 to current) equals $K$. Seeding `0` represents the "empty subarray" that exists before the array begins.

## Problem: Subarray Sum Equals K (LeetCode 560)

**Problem Statement:** Given an array of integers `nums` and an integer `k`, return the total number of continuous subarrays whose sum equals to `k`. (The array can contain negative numbers).

### Pseudo-code
```cpp
function subarraySum(nums, k):
    n = length of nums
    
    count = 0
    current_sum = 0
    
    // Hash map to store <Prefix Sum, Frequency>
    freq_map = empty hash map
    
    // CRITICAL: Seed the map for subarrays that start at index 0 and equal K
    freq_map[0] = 1
    
    for i = 0 to n - 1:
        // Step 1: Update the running total sum
        current_sum = current_sum + nums[i]
        
        // Step 2: Formulate the question (What prefix sum do we need to chop off?)
        target_prefix = current_sum - k
        
        // Step 3: Ask the Hash Map if it has seen this target prefix
        if freq_map contains target_prefix:
            // If yes, add the frequency of that prefix to our result count
            count = count + freq_map[target_prefix]
            
        // Step 4: Record the current_sum into the Hash Map for future iterations
        if freq_map contains current_sum:
            freq_map[current_sum] = freq_map[current_sum] + 1
        else:
            freq_map[current_sum] = 1
            
    return count
```

### Complexity Analysis

- **Time Complexity:** $O(N)$. We traverse the array exactly once. Hash map lookups and insertions take $O(1)$ on average.
- **Space Complexity:** $O(N)$. In the worst-case scenario (where all elements are positive or distinct), every running sum is unique, and we store $N$ distinct prefix sums in the hash map.

## Active Recall

**Q: Why does the Sliding Window pattern fail for the "Subarray Sum Equals K" problem?**

**A:** Sliding Window requires predictability: expanding the window increases the sum, and shrinking decreases it. Because the input array contains negative numbers, adding a new element might decrease the sum, and removing an element might increase it. This breaks the fundamental logic of when to move the `low` and `high` pointers.

**Q: In the formula `target_prefix = current_sum - k`, what does `target_prefix` logically represent?**

**A:** `target_prefix` represents the sum of a segment at the _beginning_ of the array. If we have previously recorded a prefix sum matching `target_prefix`, it means we can mathematically "chop off" that segment from our `current_sum`, and the remaining elements will sum to exactly `k`.

**Q: Why must we initialize the hash map with the key-value pair `<0, 1>` before the loop begins?**

**A:** It accounts for subarrays that start precisely at index 0 and sum to `K`. If `current_sum` equals `K`, then `current_sum - k = 0`. Without `<0, 1>` in the map, the algorithm would incorrectly assume no such subarray exists because it hasn't artificially recorded the "empty prefix" before the array started.

**Q: Why do we add the _frequency_ of the prefix sum from the hash map to our result count, rather than just adding 1?**

**A:** Because of zeros and negative numbers, the running prefix sum can fluctuate and return to the same value multiple times. If `target_prefix` has occurred 3 times in the past, it means there are 3 distinct starting points we can "chop off" to form a valid subarray ending at the current index. Therefore, we must add all 3 occurrences to our total count.
