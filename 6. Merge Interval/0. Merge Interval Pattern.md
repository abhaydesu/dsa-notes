## Pattern Identification Flowchart

Unlike other patterns (like Sliding Window or Two Pointers) where you have to deduce the data structure, the Merge Interval pattern is very explicitly defined by its input.

### Step 1: Data Structure Check

- **The Input MUST be a 2D Array of Ranges/Intervals.**
- A "Range" is simply a pair of numbers `[start, end]`, where `start <= end`.
- If the input is not a collection of these start/end pairs, this pattern does not apply.

### Step 2: Keyword Check

Look for specific keywords in the problem description that imply scheduling, overlapping, or combining ranges:

- `Overlap`
    
- `Conflict`
    
- `Merge`
    
- `Free Time` / `Simultaneous Usage`
    
- Contextual nouns like: `Rooms`, `Load`, `CPU`, `Meetings`, `Flights`.

_If you have an array of intervals and any of these keywords/concepts, it is 100% a Merge Intervals problem._

## The Core Concept: The Clothing Store Analogy

Imagine you manage a clothing store. You have different categories of shirts based on price ranges:

1. `[10, 15]` (Shirts priced ₹10 to ₹15)
2. `[12, 16]` (Shirts priced ₹12 to ₹16)
3. `[20, 25]` (Shirts priced ₹20 to ₹25)

**The Problem (Overlapping Intervals):**

If a new shirt arrives priced at `₹13`, which shelf do you put it on? It fits into Category 1 AND Category 2. This ambiguity exists because your first two categories **overlap** (`[10, 15]` and `[12, 16]`).

**The Solution (Merging Intervals):**

To remove ambiguity, you must redesign your store by merging overlapping categories into a single, comprehensive category.

If you combine `[10, 15]` and `[12, 16]`, the new category should cover all possible prices in both ranges.

- **New Start:** The minimum of both starts $\rightarrow$ `10`.
    
- **New End:** The maximum of both ends $\rightarrow$ `16`.
    
- **Merged Category:** `[10, 16]`.
    
    Now, your store only has two distinct, non-overlapping categories: `[10, 16]` and `[20, 25]`.

## The Mathematical Logic of Merging

Before writing code, we must establish the rules for how the computer knows _if_ two intervals overlap, and _how_ to merge them.

### Rule 1: Always Sort by Start Time

You must sort the 2D array of intervals based on their **start** values before processing.

_Why?_ If the array is unsorted (e.g., `[1, 5]`, `[10, 20]`, `[2, 3]`), you would have to compare every interval against every other interval ($O(N^2)$). Sorting by start time ensures that any overlapping intervals will be immediately adjacent to each other in the array ($O(N \log N)$).

_(Note: Because we sort by start time, we guarantee that `start1 <= start2` for any adjacent pair of intervals)._

### Rule 2: How to Detect an Overlap

Given two sorted intervals: `Interval 1 = [start1, end1]` and `Interval 2 = [start2, end2]`.

They overlap **if and only if**:

$$end1 \ge start2$$

- _Example (Overlap):_ `[1, 6]` and `[5, 7]`. Here, `6 >= 5`. They overlap.
    
- _Example (No Overlap):_ `[1, 5]` and `[8, 10]`. Here, `5 < 8`. They do not overlap.
    

### Rule 3: How to Merge Two Overlapping Intervals

If `end1 >= start2`, we combine them into a new interval `[new_start, new_end]`.

- `new_start = start1` (Since we sorted the array, `start1` is mathematically guaranteed to be the absolute minimum).
    
- `new_end = max(end1, end2)` (Because we don't know which interval extends further, we must take the maximum of their end values).
    


## Active Recall

**Q: In the Merge Intervals pattern, why is it strictly necessary to sort the array of intervals by their _start_ times before evaluating overlaps?**

**A:** If the array is not sorted, overlapping intervals could be located anywhere in the array, forcing you to compare every single interval against every other interval (an $O(N^2)$ brute force operation). Sorting guarantees that any overlapping intervals will sit adjacent to one another, allowing you to resolve all merges in a single $O(N)$ linear pass.

**Q: Given two intervals, `[start1, end1]` and `[start2, end2]`, that have already been sorted by their start times, what is the exact mathematical condition to check if they overlap?**

**A:** They overlap if `end1 >= start2`.

**Q: When merging two overlapping intervals, why is the new end time calculated as `max(end1, end2)` instead of just defaulting to `end2`?**

**A:** Because sorting by start time does not guarantee anything about the end times. An interval could completely engulf the next interval (e.g., `[1, 10]` and `[3, 5]`). If you blindly took `end2` (`5`), your merged interval `[1, 5]` would incorrectly truncate data. Using `max()` ensures the new interval covers the maximum extent of both.

**Q: In the pseudo-code, why is there a final `result.append([start1, end1])` outside and after the main `for` loop?**

**A:** The `for` loop either merges the current element into the running interval or pushes the _previous_ completed interval into the result list. When the loop ends, the very last running interval (whether it was freshly created or the result of multiple merges) has not yet been pushed to the result array.
