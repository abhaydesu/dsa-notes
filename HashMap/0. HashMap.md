[[Data Structure]]
## Core Analogy: The Diary

To truly understand a Hashmap, think of it as a personal diary. If you write a diary entry every day, you might write:

- Dec 5: Bought a bike.
- Dec 6: Fell down and broke a leg.
- Dec 7: Sold the bike.

If someone asks you, "What happened on December 7th?" fifteen days later, you wouldn't need to read the whole diary page by page. You would directly open the page for December 7th and get the exact answer immediately. This direct lookup mechanism is exactly what a Hashmap does.

## Key and Value Concept

Data inside a Hashmap is strictly stored in **Pairs**: a `Key` and a `Value`.

- **Value**: The actual data or payload you want to store (e.g., "Bought a bike", an integer, or an array).
- **Key**: The unique identifier used to find that data (e.g., the date "Dec 5").

> **External Knowledge Context**: Under the hood, a Hashmap uses a mathematical algorithm called a "hash function." This function takes your `Key`, crunches it into a numeric code, and uses that number as an index in an underlying array. This is why looking up data by its key is incredibly fast, generally operating in **O(1) constant time** for search, insertion, and deletion.

### Flexibility and Consistency of Keys

You have complete freedom to define what the Key and Value should be.

- A shopkeeper might use a person's name (String) as the Key and the amount they owe (Integer) as the Value.
    
- You can use complex data structures (like a Vector or a Set) as values.
    

**Crucial Rules**:

1. **Consistency**: In strongly typed languages (like C++ or Java), if you declare a Hashmap to hold Integer keys and String values, you cannot dynamically insert a Character as a key.
    
2. **Unique Keys**: Keys must always be unique. You cannot have two identical keys pointing to different values. If you insert a value at an already existing key, it strictly overwrites the old value.
    

## The Powers and Limitations of a Hashmap

A Hashmap is a highly specialized tool. It is not intelligent; it is merely a storage and retrieval system.

### What a Hashmap CAN do (Fast Exact Operations)

1. Tell you the exact value associated with a specific key.
2. Tell you the total number of entries (Key-Value pairs) it currently holds.
3. Tell you whether a specific key exists in it or not (True/False).

### What a Hashmap CANNOT do (Complex/Relative Queries)

It cannot answer complex, relative, or range-based queries without iterating through everything.

- "What happened _before_ December 10th?"
- "What was the _last_ entry added?" (Unordered hashmaps do not maintain insertion order).
- "How many entries have a value greater than 50?"
- "What happened _between_ December 5th and December 10th?"

If your algorithmic problem requires answering these complex relative queries, a Hashmap is the wrong data structure. You might need a Heap, a Binary Search Tree, or a simple Array instead.

## When to Use a Hashmap in Problem Solving

Use a Hashmap when the core challenge of a problem is **remembering historical data** to answer direct, exact lookups later. If you find yourself thinking, "I need to remember what I saw earlier so I can match it exactly with what I am seeing right now," you should immediately consider a Hashmap.

## Implementations & Pseudo-code

### C++ (Unordered Map)

In C++, the standard Hashmap is called `unordered_map`.

```cpp
// Pseudo-code / Syntax for C++ Unordered Map
#include <unordered_map>

// 1. Declaration (Key: int, Value: int)
unordered_map<int, int> f;

// 2. Insertion / Updation
f[1] = 10;       // Inserts key 1 with value 10
f[1] = 20;       // Updates key 1's value to 20
f[2]++;          // If key 2 doesn't exist, initializes to 0, then increments to 1.

// 3. Deletion
f.erase(1);      // Removes the entry with key 1

// 4. Size
int s = f.size(); // Returns number of unique keys

// 5. Checking if a key exists
if (f.find(1) != f.end()) {
    // Key 1 exists
} else {
    // Key 1 does not exist
}

// 6. Iterating through the map (Order is not guaranteed)
for (auto i : f) {
    int key = i.first;
    int val = i.second;
}
```
## Active Recall

**Q1: What is the primary difference between a Key and a Value in a Hashmap?** _Answer_: The Key is the unique identifier used to look up data, while the Value is the actual payload or information being stored.

**Q2: If you execute `map[5] = 100` and then later execute `map[5] = 200`, what exactly happens inside the Hashmap?** _Answer_: The original value of 100 is overwritten by 200. Keys must remain uniquely identifiable, so the data structure updates the existing key rather than creating a duplicate entry.

**Q3: What is the average time complexity for searching, inserting, and deleting an element in a Hashmap?** _Answer_: O(1) or constant time.

**Q4: Why is a Hashmap a poor choice if a problem asks you to find the "maximum value" or "elements within a specific range"?** _Answer_: Unordered Hashmaps do not maintain data in any sorted order. Finding a maximum or checking a range would require iterating through every single entry, taking O(N) time, which defeats the purpose of using a Hashmap.

**Q5: How does C++ handle the operation `map[10]++` if the key `10` does not exist in the map yet?** _Answer_: C++ will automatically create the key `10`, assign it a default value of `0`, and then instantly increment it to `1`.
