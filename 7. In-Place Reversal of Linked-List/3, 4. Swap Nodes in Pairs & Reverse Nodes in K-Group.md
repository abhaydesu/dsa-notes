## Problem Statement: Reverse Nodes in K-Group

Given the `head` of a linked list, reverse the nodes of the list `k` at a time, and return the modified list.

- `k` is a positive integer and is less than or equal to the length of the linked list.
    
- If the number of nodes is not a multiple of `k` then left-out nodes in the end should remain as they are.
    

_(Note: **Swap Nodes in Pairs** is literally the exact same problem, but hardcoded with $k = 2$.)_

## Logic & Intuition

Do not try to memorize a massive, complex loop for this problem. Break it down into the exact same 3 steps used in standard sub-list reversal:

1. **Identify the Group:** Determine the start and end of the `K` nodes you want to reverse.
    
2. **Reverse the Group:** Apply the standard 3-pointer reversal algorithm.
    
3. **Reconnect the Wires:** Connect the end of the _previous_ group to the new head of the _current_ group, and point the tail of the _current_ group to the start of the _next_ group.
    

### The "Dummy Node" Trick

Because the very first group will be reversed, the original `head` of the linked list will no longer be the head of the final list. To avoid writing messy `if/else` edge cases just for the first group, we use a **Dummy Node** placed right before the `head`.

- `dummy.next = head`
    
- This ensures _every_ group (even the first one) has a valid `previous_tail` node sitting right in front of it to connect to.
    

### Step-by-Step Breakdown

1. **Count the Nodes:** Traverse the list once to count the total number of nodes. This helps us know exactly how many full `K`-groups we can reverse.
    
2. **State Variables:** We need to track where we are.
    
    - `prev_group_tail`: Starts at the Dummy Node. It is responsible for pointing to the new head of whatever group we just reversed.
        
    - `curr`: The current node being reversed.
        
3. **The Inner Reversal Loop:** Runs `K` times. Standard `prev`, `curr`, `next_node` logic.
    
4. **The Reconnection:** After reversing a group of `K`:
    
    - The node that _was_ the head of this group is now the tail.
        
    - `prev_group_tail.next = new_head_of_group`
        
    - `prev_group_tail` moves to become the new tail.
        
5. **Remaining Nodes:** If fewer than `K` nodes remain, simply attach them to the `prev_group_tail` as they are, without reversing.
    

## Pseudo-code: Reverse Nodes in K-Group

```cpp
function reverseKGroup(head, k):
    if head == null or k == 1:
        return head
        
    // Step 1: Count total nodes
    count = 0
    temp = head
    while temp != null:
        count = count + 1
        temp = temp.next
        
    // Step 2: Initialize Dummy Node and track previous group's tail
    dummy = new Node(0)
    dummy.next = head
    
    prev_group_tail = dummy
    curr = head
    
    // Step 3: Loop while we have enough nodes for a full K-group
    while count >= k:
        group_head = curr
        prev = null
        
        // Reverse exactly 'k' nodes
        times = k
        while times > 0:
            next_node = curr.next
            curr.next = prev
            prev = curr
            curr = next_node
            times = times - 1
            
        // Step 4: Reconnect the wires
        // 'prev' is now the new head of this reversed group
        // 'group_head' is now the tail of this reversed group
        
        prev_group_tail.next = prev
        group_head.next = curr // Connect to the remainder of the list
        
        // Step 5: Update tracking variables for the next group
        prev_group_tail = group_head
        count = count - k
        
    return dummy.next
```

## Complexity Analysis

- **Time Complexity:** $O(N)$. We make one pass to count the nodes ($O(N)$), and a second pass to reverse the groups ($O(N)$). Total time is strictly linear.
    
- **Space Complexity:** $O(1)$. We only modify existing pointers (`prev`, `curr`, `next_node`, `dummy`) and do not use any recursive stack or external data structures.
    

## Active Recall

**Q: Why is "Swap Nodes in Pairs" considered the exact same problem as "Reverse Nodes in K-Group"?**

**A:** "Swap Nodes in Pairs" is just a specific sub-case where $K = 2$. If you write the dynamic algorithm for $K$ size groups, passing $K = 2$ perfectly swaps every pair, proving that memorizing the $K$-group logic makes learning pair-swapping obsolete.

**Q: Why do we traverse the linked list to count the total number of nodes before doing any reversals?**

**A:** The problem statement strictly requires that if a group has fewer than $K$ nodes (the leftover nodes at the very end), they must _not_ be reversed. By calculating the total count first, we know exactly how many full $K$-groups exist and can stop the `while` loop before accidentally reversing a partial group.

**Q: What is the purpose of the `Dummy Node` placed before the `head`?**

**A:** In sub-list reversal, you must connect the node _before_ the reversed section to the _new head_ of the reversed section. For the very first group, there is no "before" node. The Dummy Node artificially creates a "before" node, allowing us to use the exact same reconnecting logic for the first group as we do for every subsequent group.

**Q: After reversing a `K`-group, which node does the `prev_group_tail` point to, and which node does the new `group_tail` point to?**

**A:** The `prev_group_tail` (from the previous iteration) points to the `prev` pointer (which is the new head of the freshly reversed group). The new `group_tail` (which was the original `group_head` before reversal) points to the `curr` pointer (which is the start of the next unreversed sequence).
