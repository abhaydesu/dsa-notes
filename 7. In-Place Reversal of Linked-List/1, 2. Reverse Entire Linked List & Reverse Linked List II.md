## Concept: Reversing a Linked List

Reversing a linked list doesn't mean moving the data inside the nodes; it means systematically changing the direction of the `next` pointers so that the list flows backwards.

### The "Train, Mechanic, and Helper" Analogy

Imagine a train where each bogie points to the next. You want to reverse the train.

- **The Mechanic (`curr` pointer):** Stands on the current bogie. His job is to detach the link pointing forward and reconnect it to the bogie immediately behind him.
- **The Helper (`prev` pointer):** Stands on the bogie _immediately behind_ the mechanic so the mechanic knows where to connect the link.
- **The Blueprint (`next` pointer):** Before the mechanic breaks the forward link, he must note down the location of the next bogie so he knows where to move next.

**The Process:**

1. The Helper (`prev`) starts off the train (at `NULL`).
2. The Mechanic (`curr`) starts at the Engine (`head`).
3. The Mechanic notes the next bogie (`next = curr.next`).
4. The Mechanic reverses his link to point to the Helper (`curr.next = prev`).
5. The Helper moves to where the Mechanic is (`prev = curr`).
6. The Mechanic moves to the noted next bogie (`curr = next`).
7. Repeat until the Mechanic falls off the end of the train (`curr == NULL`). The Helper will be standing on the new Head of the train.

## Pseudo-code 1: Reverse Entire Linked List (LeetCode 206)

```cpp
function reverseList(head):
    // Helper starts at NULL
    prev = null
    
    // Mechanic starts at the head
    curr = head
    
    while curr != null:
        // 1. Note the next node before breaking the link
        next_node = curr.next
        
        // 2. Reverse the link (Mechanic points to Helper)
        curr.next = prev
        
        // 3. Helper moves forward to Mechanic's position
        prev = curr
        
        // 4. Mechanic moves forward to the saved next node
        curr = next_node
        
    // Once curr is null, prev is standing on the last node (the new head)
    return prev
```

## Problem: Reverse Linked List II (LeetCode 92)

**Problem Statement:** Given the `head` of a singly linked list and two integers `left` and `right` where $1 \le left \le right \le n$, reverse the nodes of the list from position `left` to position `right`, and return the reversed list.

### Intuition & Logic

The core idea is that reversing a sub-list is exactly the same as reversing a full list, but bounded by a specific `number_of_times`.

`times = right - left + 1`.

The complexity comes from **reconnecting the reversed sub-list back to the original list.**

When the sub-list is reversed:

1. The node immediately _before_ the `left` position (`before_node`) must point to the _new head_ of the reversed sub-list (which will be `prev`).
    
2. The node that was originally at the `left` position (`t_node`) becomes the tail of the reversed sub-list. It must point to the node immediately _after_ the `right` position (which will be `curr`).
    

### The Edge Case: `left == 1`

If `left == 1`, the reversal starts at the very first node. This means there is no `before_node`. The `prev` pointer automatically becomes the brand new `head` of the entire linked list.

## Pseudo-code 2: Reverse Sub-List

```cpp
function reverseBetween(head, left, right):
    // Edge cases
    if head == null or left == right:
        return head
        
    t = head         // Pointer to traverse to the 'left' position
    before = null    // Pointer to track the node exactly before 'left'
    pos = 1          // 1-based indexing position tracker
    
    // Step 1: Traverse to the 'left' position
    while t != null and pos < left:
        before = t
        t = t.next
        pos = pos + 1
        
    // At this point, 't' is sitting on the 'left' node.
    // 'before' is sitting on the node right before it.
    
    // Step 2: Reverse exactly 'right - left + 1' times
    curr = t
    prev = null
    times = right - left + 1
    
    while times > 0:
        next_node = curr.next
        curr.next = prev
        prev = curr
        curr = next_node
        times = times - 1
        
    // Step 3: Reconnect the severed links
    // 't' is now the tail of the reversed section. Connect it to 'curr' (the rest of the list)
    t.next = curr
    
    // Check the edge case: Did we reverse from the very beginning?
    if before != null:
        // Connect the non-reversed prefix to the new head of the reversed section
        before.next = prev
        return head
    else:
        // If before is null, it means left == 1. 
        // The new head of the entire list is 'prev'.
        return prev
```

## Complexity Analysis

- **Time Complexity:** $O(N)$. We make a single pass through the linked list to find the `left` position and then continue that pass to reverse the required nodes. We touch each node at most once.
- **Space Complexity:** $O(1)$. We are only manipulating pointers (`prev`, `curr`, `next`, `before`, `t`). No auxiliary data structures are used.

## Active Recall

**Q: In the standard Linked List Reversal algorithm, why is it strictly necessary to store `next_node = curr.next` before changing `curr.next = prev`?**

**A:** Changing `curr.next` severs the link to the rest of the list. If you don't store the memory address of the next node in a temporary variable first, you will lose access to the remainder of the linked list permanently and won't be able to advance the `curr` pointer.

**Q: After the `while (curr != null)` loop finishes in a full list reversal, why do we return `prev` as the new head instead of `curr`?**

**A:** The loop terminates strictly when `curr == null`. At that exact moment, `prev` is resting on the last valid node of the original list. Because the list has been reversed, the last node of the original list is the new head.

**Q: In the "Reverse Linked List II" problem, how do you calculate the exact number of nodes that need to be reversed given `left` and `right` positions?**

**A:** The number of nodes (or reversal iterations) is calculated inclusively as `right - left + 1`.

**Q: If `left == 1` in the sub-list reversal problem, why must the function return `prev` instead of `head`?**

**A:** If `left == 1`, the reversal begins at the original head of the list. This means the original head is moved to the middle/end of the list, and a new node (currently tracked by `prev`) takes its place at the very front. Returning the original `head` would incorrectly return the middle of the new list.
