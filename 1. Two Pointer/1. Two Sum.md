## Deep Dive: The "Two Sum" Problem

The classic "Two Sum" problem asks you to find two numbers in an array that add up to a specific target  However, the problem has two variations that completely change whether Two Pointers can be used.

### Variation 1: Return Indices vs. Variation 2: Return Numbers

If the problem asks you to return the **indices** of the two numbers, and the array is _unsorted_, you **cannot** sort it to use Two Pointers. Sorting the array scrambles the original indices (e.g., what was at index 2 might move to index 0), meaning your final answer would be wrong 

You can only apply the Two-Pointer technique if:

- The problem asks you to return the **actual numbers** (because sorting doesn't change the numbers themselves)
- The problem asks for indices, but the array is **already sorted** for you (often called _Two Sum II_)

### Approach 1: Brute Force

The approach a beginner would take:

- Run a loop with `i` from the start to the end.
- For every `i`, run an inner loop `j` to search the rest of the array for the remaining value (`target - array[i]`).
- **Time Complexity:** $O(n^2)$ — If an array has 100,000 elements, your computer attempts $10^{10}$ operations and crashes 
- **Space Complexity:** $O(1)$.

```cpp
vector<int> twoSumBruteForce(vector<int>& nums, int target) {
    int n = nums.size();

    // Check every possible pair
    for (int i = 0; i < n; i++) {

        // Start from the next element
        for (int j = i + 1; j < n; j++) {

            // If the pair sums to the target
            if (nums[i] + nums[j] == target) {
                return {nums[i], nums[j]};   // or {i, j}
            }
        }
    }

    // No valid pair found
    return {};
}
```
### Approach 2: Hash Map

To avoid the inner loop, you can store every element and its index in a Hash Map.

- As you iterate through the array, you simply ask the Hash Map: "Do you have `target - array[i]`?" The Hash Map checks in $O(1)$ time 
- **Time Complexity:** $O(n)$ — Fast.
- **Space Complexity:** $O(n)$ — If you have an array of $10^9$ elements, storing a Hash Map could consume 16 GB of RAM, causing the program to crash. Space is expensive in enterprise environments.
```cpp
vector<int> twoSumHashMap(vector<int>& nums, int target) {
    unordered_map<int, int> mp;

    // Traverse the array once
    for (int i = 0; i < nums.size(); i++) {

        int current = nums[i];
        int needed = target - current;

        // If the complement already exists, we've found the pair
        if (mp.find(needed) != mp.end()) {
            return {needed, current};   // or {mp[needed], i}
        }

        // Store the current element for future lookups
        mp[current] = i;
    }

    // No valid pair found
    return {};
}
```

This is where the Two-Pointer technique shines: it gives you the speed of an optimized search without the massive memory footprint of a Hash Map.
## The Optimal: Two-Pointer Algorithm

If you are asked to return the _numbers_ without using extra space, follow these steps 

**1.Sort the Array:**

First, sort the array in ascending order.

**2.Initialise the Pointers:**

Place pointer `i` at the start (index `0`) and pointer `j` at the very end (index `n-1`).

**3.Calculate the Current Sum:**

Loop while `i < j` (they must never cross or land on the same index. Calculate `sum = array[i] + array[j]`.

**4.Check the Target:**

Compare the `sum` to your `target`. The universe only allows three possibilities:

- **If `sum == target`:** You found the pair! Return `array[i]` and `array[j]`.
- **If `sum < target`:** The sum is too small. Because the array is sorted, moving `j` backwards would only give you an even smaller sum. Instead, increment `i` (`i++`) to bring in a larger number 
- **If `sum > target`:** The sum is too large. Moving `i` forward would only give you a larger sum. Instead, decrement `j` (`j--`) to bring in a smaller number
```cpp
sort(nums.begin(), nums.end());

int left = 0;
int right = nums.size() - 1;

while (left < right) {
    int sum = nums[left] + nums[right];

    if (sum == target) {
        return {nums[left], nums[right]};
    }
    if (sum < target) {
        left++;
    }
    else {
        right--;
    }
}

return {};
```
### Final Algorithm Complexity

- **Time Complexity:** $O(n \log n)$ — The array traversal takes $O(n)$, but the initial sorting takes $O(n \log n)$. Since $n \log n$ is the larger term, it dominates.
- **Space Complexity:** $O(1)$ — We only use two variables (`i` and `j`), regardless of whether the array has 5 elements or 5 billion elements
## Active Recall Q&A 

**Q: What is the Time and Space complexity of solving Two Sum using a Hash Map?**

**A:** Time: $O(N)$, Space: $O(N)$.

**Q: What is the Time and Space complexity of solving Two Sum using Two Pointers?**

**A:** Time: $O(N \log N)$ (due to sorting), Space: $O(1)$.

**Q: In the Two Pointers sorted approach, what do you do if `arr[i] + arr[j] < target`?**

**A:** Increment the left pointer (`i++`). The sum is too small, so we need to move to a larger number (which is to the right).

**Q: In the Two Pointers sorted approach, what do you do if `arr[i] + arr[j] > target`?**

**A:** Decrement the right pointer (`j--`). The sum is too big, so we need to move to a smaller number (which is to the left).

**Q: What is the strictly correct `while` loop condition for Two Pointers, and why?**

**A:** `while (i < j)`. Pointers must not cross, and they shouldn't land on the same exact index (`i <= j` is wrong because a pair requires two distinct elements).
