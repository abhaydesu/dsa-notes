## Pattern Identification: Which Subarray Pattern to Use?

When dealing with Subarray problems, you generally have three pattern choices. Here is how to distinguish them:

1. **Kadane's Algorithm:**
    - **Goal:** Find a maximum or minimum value (e.g., Maximum Subarray Sum, Minimum Subarray Product).
    - **Condition:** Rarely has strict equality constraints like `== K`.
2. **Sliding Window:**
    - **Goal:** Find length (Longest/Shortest), Count, or Max/Min.
    - **Condition:** Inequalities or equalities (e.g., `Sum <= K`, `Sum == K`).
    - **The Catch:** Fails completely if the array contains negative numbers (or unpredictable state changes) because expanding/shrinking the window no longer guarantees a predictable increase/decrease in the state.
3. **Prefix Sum:**
    - **Goal:** Find Count, Existence, or Length (Longest/Shortest).
    - **Condition:** Strict mathematical constraints (e.g., `Sum == K`, `Sum % K == 0`, `Equal number of 0s and 1s`).
    - **The Catch:** Works perfectly with negative numbers and unpredictable state changes. Uses auxiliary Data Structures (Variables, Arrays, Hash Maps) to track historical states.

## The Universal "Green Part / Red Part" Framework

Instead of memorizing different templates for `Sum == K`, `Sum % K == 0`, or `Equal 0s and 1s`, use this single logical framework to derive the solution for _any_ prefix sum problem.

At any index `i`, imagine the array from `0` to `i` is split into two contiguous parts:

- **Green Part:** The subarray ending at `i` that perfectly satisfies the problem's condition. (This is the answer we want).
- **Red Part:** The prefix of the array (from `0` to some index `j`) that we need to "chop off" to isolate the Green Part.

### The 4-Step Thought Process:

1. **Calculate the Total State:** At index `i`, what is the total state from index `0`? (e.g., Total Sum, Total Difference).
2. **Assume the Green State:** Mathematically define what the Green Part _must_ be to satisfy the condition (e.g., `Green_Sum = K`).
3. **Derive the Red State:** Use basic algebra to find out what the Red Part must be.
    
    $$Red\_State = Total\_State - Green\_State$$
    
4. **Query the Hash Map:** Ask the Hash Map, _"Have I ever seen this `Red_State` before?"_
    
    - If **Yes**, it means chopping off that historical Red Part will leave you with a valid Green Part ending at your current index `i`.
### Example Derivations using the Framework:

- **Problem:** Subarray Sum Equals K
    - _Total State:_ `Running_Sum`
    - _Green State:_ Exactly `K`.
    - _Red State required:_ `Running_Sum - K`.
    - _Query:_ Does the Hash Map contain `Running_Sum - K`?
- **Problem:** Equal number of 0s and 1s
    - _Total State:_ `Difference` between count of 0s and 1s.
    - _Green State:_ Difference must be exactly `0`.
    - _Red State required:_ `Total_Difference - 0 = Total_Difference`.
    - _Query:_ Does the Hash Map contain the exact same `Total_Difference`?

## The Universal Prefix Sum + Hash Map Template

```cpp
function prefixSumTemplate(arr, k):
    n = length of arr
    
    // Step 1: Initialize the state and the result
    state = 0 // Could be sum, difference, etc.
    result = 0 // Could be count = 0, or max_len = 0
    
    // Step 2: Initialize the Hash Map and seed the "Empty Prefix"
    // Value represents Frequency (for counting) or Index (for length)
    history_map = empty hash map
    
    // Seed value depends on the problem!
    // For 'Sum == K' -> history_map[0] = 1 (seen sum of 0 once)
    // For 'Longest Subarray' -> history_map[0] = -1 (seen difference of 0 at index -1)
    seed_initial_state(history_map) 
    
    // Step 3: Iterate through the array
    for i = 0 to n - 1:
        
        // Update current running state
        state = update_state(state, arr[i])
        
        // Derive the Red Part based on the problem's condition
        red_target = calculate_red_target(state, k)
        
        // Query the Hash Map
        if history_map contains red_target:
            // If counting: result += history_map[red_target]
            // If length: result = max(result, i - history_map[red_target])
            update_result(result, history_map, red_target, i)
            
        // Record the current state for future iterations
        // If counting: history_map[state]++
        // If length: insert only if not already present
        update_history(history_map, state, i)
        
    return result
```

## Active Recall

**Q: If an array contains entirely positive numbers, should you use Sliding Window or Prefix Sum to find the shortest subarray with `Sum >= K`?**

**A:** You should use Sliding Window. Sliding Window requires $O(1)$ space and is generally faster to write and execute. Prefix Sum + Hash Map requires $O(N)$ space. Prefix Sum is mandatory only when negative numbers are introduced, breaking the Sliding Window logic.

**Q: In the "Green Part / Red Part" framework, what does the "Red Part" physically represent in the array?**

**A:** The Red Part represents a prefix of the array (starting from index `0` up to some index `j`). It is the portion of the running total that must be "chopped off" or discarded so that the remaining elements (the Green Part ending at the current index `i`) perfectly satisfy the problem's condition.

**Q: Why do we update the `history_map` with the current state _after_ querying it for the `red_target`?**

**A:** If we added the current state to the map first, and the required `red_target` happened to equal our current state (e.g., searching for `Sum == 0`, so `Target = Current_Sum - 0 = Current_Sum`), the algorithm would falsely match with itself. Querying first ensures we are only chopping off _previous_ prefixes, leaving a non-empty valid subarray.
