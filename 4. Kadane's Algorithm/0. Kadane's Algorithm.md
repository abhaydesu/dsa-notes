## Pattern Identification: When to use Kadane's Pattern?

Before learning the algorithm, we must know when to apply it. The flowchart for Kadane's is closely related to Sliding Window, but it specifically handles scenarios where Sliding Window fails.

**The Flowchart / Indicators:**

1. **Data Structure:** Array (or sequential linear data).
2. **Entity:** Subarray (must be **contiguous**).
3. **Goal:** Find the `Best` possible outcome (Maximum or Minimum) of a calculation (like `Sum` or `Product`).
4. **The Dealbreaker (Why not Sliding Window?):** The array contains a mix of **positive and negative** numbers.

### Why does Sliding Window fail with negative numbers?

In Sliding Window, we rely on predictable outcomes: Expanding the window (`high++`) generally increases the sum, and shrinking the window (`low++`) decreases the sum.

When negative numbers are introduced, this predictability breaks. Expanding the window to include a `-5` will _decrease_ the sum. The decision-making power of when to shrink or expand is lost.

_Kadane's Pattern exists to solve the contiguous subarray optimization problem when predictability is broken by negative numbers._

## The Core Thought Process (The Template)

Instead of looking at the whole array or maintaining a dynamic window, Kadane's focuses exclusively on building the answer **index by index**.

At every index $i$ from $0$ to $n-1$, you ask one fundamental question:

**"What is the best possible answer for a subarray that strictly ENDS at index $i$?"**

To find the "Best Ending at index $i$", the current element `arr[i]` has exactly two choices:

- **Choice 1:** Join the "Best Ending" from the previous index ($i-1$) to form a larger subarray.
- **Choice 2:** Reject the previous subarray and start a brand new subarray containing only itself (`arr[i]`).

Whichever choice yields the "better" result (higher for max problems, lower for min problems) becomes the new "Best Ending at index $i$".

Since _every_ valid subarray must end at _some_ index, the global optimal answer is simply the maximum/minimum of all the "Best Endings" we calculated.

##  Active Recall

**Q: Why does the Sliding Window pattern fail for the Maximum Subarray Sum problem if the array contains negative numbers?**

**A:** Sliding Window relies on the predictable assumption that expanding the window increases the sum and shrinking it decreases the sum. Negative numbers break this logic, making it impossible to know when to predictably expand or shrink the window to optimize the sum.

**Q: In Kadane's pattern, what are the two choices evaluated at every index `i` to calculate the "Best Ending Here"?**

**A:** The element at index `i` can either: 1) Join the contiguous subarray ending at `i-1` (adding itself to the previous Best Ending). 2) Reject the previous subarray and start a brand new subarray consisting only of itself.
