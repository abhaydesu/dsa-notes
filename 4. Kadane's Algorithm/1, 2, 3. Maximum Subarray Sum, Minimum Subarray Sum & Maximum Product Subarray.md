## Problem 1: Maximum Subarray Sum

**Problem:** Find the contiguous subarray with the largest sum. (LeetCode 53)

### Logic

- **Best Ending at $0$:** Just `arr[0]`.
- **Choice at $i$:** `max(Best Ending at (i-1) + arr[i], arr[i])`.
- **Global Result:** `max(Result, Best Ending at i)`.

### Pseudo-code: Maximum Subarray Sum

```cpp
function maxSubArray(arr):
    n = length of arr
    
    // Step 1: Initialize at index 0
    best_ending_here = arr[0]
    global_max = arr[0]
    
    // Step 2: Iterate through the rest of the array
    for i = 1 to n - 1:
        // Option 1: Join previous subarray
        v1 = best_ending_here + arr[i]
        // Option 2: Start fresh
        v2 = arr[i]
        
        // Make the choice
        best_ending_here = max(v1, v2)
        
        // Update global result
        global_max = max(global_max, best_ending_here)
        
    return global_max
```

_Time Complexity: $O(N)$ | Space Complexity: $O(1)$_

## Problem 2: Minimum Subarray Sum

**Problem:** Find the contiguous subarray with the smallest sum
### Logic

The thought process is identical to Maximum Subarray Sum. The only difference is the definition of "Best". Here, "Best" means "Minimum". Therefore, all `max()` functions are replaced with `min()`.
### Pseudo-code: Minimum Subarray Sum
```cpp
function minSubArray(arr):
    n = length of arr
    best_ending_here = arr[0]
    global_min = arr[0]
    
    for i = 1 to n - 1:
        v1 = best_ending_here + arr[i]
        v2 = arr[i]
        
        // Make the choice (we want the smallest possible sum)
        best_ending_here = min(v1, v2)
        global_min = min(global_min, best_ending_here)
        
    return global_min
```

## Problem 3: Maximum Product Subarray

**Problem:** Find the contiguous subarray with the largest product. (LeetCode 152)
### The Twist

Why can't we just use the exact same template with multiplication?

_Because of negative numbers._ `Negative * Negative = Positive`.

If the current element is `-4`, and the "Max Ending" so far is `3`, the product is `-12`. If we only tracked the Max Ending, we would throw this away.

But what if the "Min Ending" (the most negative product so far) was `-6`? Then `-4 * -6 = 24`.

A negative number considers a large negative product to be its "Best" option because multiplying two negatives yields a massive positive number.

**To solve this, we must track BOTH the Maximum Ending and Minimum Ending at every index.**
### Logic

At index $i$, we now have THREE choices to evaluate to find the new Max/Min Endings:

1. Current element itself: `arr[i]`
2. Current element multiplied by previous Max Ending: `arr[i] * max_ending`
3. Current element multiplied by previous Min Ending: `arr[i] * min_ending`

The highest of these three is the new `max_ending`. The lowest is the new `min_ending`.

### Pseudo-code: Maximum Product Subarray
```cpp
function maxProduct(arr):
    n = length of arr
    
    max_ending = arr[0]
    min_ending = arr[0]
    global_max = arr[0]
    
    for i = 1 to n - 1:
        // Calculate the 3 options
        opt1 = arr[i]
        opt2 = arr[i] * max_ending
        opt3 = arr[i] * min_ending
        
        // Update both Max and Min endings
        max_ending = max(opt1, max(opt2, opt3))
        min_ending = min(opt1, min(opt2, opt3))
        
        // Update global result with the highest possible product found
        global_max = max(global_max, max_ending)
        
    return global_max
```

_Time Complexity: $O(N)$ | Space Complexity: $O(1)$_



## Active Recall
**Q: How do you modify Kadane's algorithm from finding the Maximum Subarray Sum to finding the Minimum Subarray Sum?**

**A:** Because the core logic remains exactly the same, you only need to change what is considered "Best". You simply replace the `max()` functions used for making choices and updating the global result with `min()` functions.

**Q: Why must you track BOTH the maximum ending product and the minimum ending product when solving the Maximum Product Subarray problem?**

**A:** Because a very small (highly negative) minimum product can instantly become the largest positive product if it is multiplied by another negative number. Tracking both ensures you don't lose potential large positive products caused by two negatives multiplying.
