## Problem 1: Sum of Digits (Number Recursion)

**Problem Statement:** Given a positive integer `n`, return the sum of its digits.

_Example:_ `n = 687` $\rightarrow$ `6 + 8 + 7 = 21`

### Logic & Intuition

You cannot easily extract the first digit of a number, but you can easily extract the last digit using the modulo operator (`% 10`).

1. **Isolate:** Extract the last digit (`d = n % 10`).
    
2. **Shrink:** Remove the last digit from the number (`n = n / 10`).
    
3. **Leap of Faith:** Ask the recursive function to find the sum of the digits for the shrunken number.
    
4. **Base Case:** What is the sum of digits for `0`? It's `0`.
    

### Pseudo-code

```cpp
function sumOfDigits(n):
    // Step 1: Base Case
    if n == 0:
        return 0
        
    // Step 2: Isolate the small part
    last_digit = n % 10
    remaining_num = n / 10
    
    // Step 3: Leap of Faith
    rest_sum = sumOfDigits(remaining_num)
    
    // Step 4: Combine
    return last_digit + rest_sum
```

## Problem 2: Check if Array is Sorted (Array Recursion)

**Problem Statement:** Given an array of integers, return `true` if it is sorted in strictly ascending order, and `false` otherwise.

_Example:_ `[10, 20, 30]` $\rightarrow$ `True`, `[10, 50, 20]` $\rightarrow$ `False`

### Logic & Intuition

A human checks if an array is sorted by looking at two adjacent elements at a time. If you ever find an element that is strictly greater than the one immediately following it, the array is unconditionally unsorted.

1. **Isolate:** Compare the current element (`arr[i]`) with the next element (`arr[i+1]`).
    
2. **Early Exit:** If `arr[i] > arr[i+1]`, instantly return `False`. No further checking is needed.
    
3. **Leap of Faith:** If they are in the correct order, the array's sorted status now entirely depends on whether the _rest_ of the array (`i+1` to the end) is sorted.
    
4. **Base Case:** An array of length 0 or 1 is naturally sorted (`True`).
    

### Pseudo-code

```cpp
function isSorted(arr, n, i):
    // Step 1: Base Case
    // If we reach the last element (or array is empty), no unsorted pairs were found
    if i == n - 1 or i == n:
        return true
        
    // Step 2: Small local check
    if arr[i] > arr[i + 1]:
        return false
        
    // Step 3: Leap of Faith (Check the rest)
    return isSorted(arr, n, i + 1)
```

## Problem 3: Remove All Occurrences of a Character (String Recursion)

**Problem Statement:** Given a string `s` and a target character `c`, return a new string with all occurrences of `c` removed.

_Example:_ `s = "apple", c = 'p'` $\rightarrow$ `ale`

### Logic & Intuition

We evaluate the string character by character.

1. **Leap of Faith (First):** Assume the recursive function can perfectly remove the target character from the _rest_ of the string (from index `i+1` to the end). You now have a clean `processed_rest` string.
    
2. **Isolate & Combine:** Look at your current character (`s[i]`).
    
    - If it matches the target `c`, your handwriting is "bad"—discard your character and just return the `processed_rest`.
        
    - If it does _not_ match `c`, your handwriting is "good"—append your character to the front of the `processed_rest` and return the combined string.
        
3. **Base Case:** If you reach the end of the string (length 0), the result is an empty string `""`.
    

### Pseudo-code

```cpp
function removeChar(s, n, i, target):
    // Step 1: Base Case
    if i == n:
        return ""
        
    // Step 2: Leap of faith on the rest of the string
    processed_rest = removeChar(s, n, i + 1, target)
    
    // Step 3: Combine based on condition
    if s[i] == target:
        // Discard current character
        return processed_rest
    else:
        // Keep current character
        return s[i] + processed_rest
```

## Complexity Analysis

For all three problems:

- **Time Complexity:** $O(N)$. The function makes exactly one recursive call per digit, array element, or string character, performing $O(1)$ operations at each step.
    
- **Space Complexity:** $O(N)$. Due to the Call Stack, the recursion will drill down $N$ levels deep before hitting the base case and unwinding.
    
    _(Note: In Problem 3, string concatenation at each step may create additional string copies depending on the language, potentially increasing time/space to $O(N^2)$ unless optimized with a string builder, but the core recursive depth remains $O(N)$)._
    

## Active Recall

**Q: In the "Sum of Digits" problem, why do we use `n == 0` as the base case instead of `n == 1`?**

**A:** Because we are dividing the number by 10 (`n / 10`) at each step. When a single-digit number (like `7`) is divided by 10, integer division yields `0`. If our base case was `n == 1`, we would completely miss single digits that don't happen to be `1`. Reaching `0` signifies there are no more digits left to process.

**Q: In the "Check if Array is Sorted" problem, why do we return `false` immediately if `arr[i] > arr[i+1]`, rather than continuing to check the rest of the array?**

**A:** If even a single pair of adjacent elements violates the ascending order rule, the entire array is mathematically unsorted. Continuing to check the rest of the array would be redundant and waste processing time. This is a form of "short-circuiting" the recursion.

**Q: In the "Remove Occurrences" problem, why does the recursive call happen _before_ we evaluate the current character `s[i]`?**

**A:** By making the recursive call first, we let the function dive all the way to the base case (the end of the string) and then build the new string backwards as the stack unspools. If we evaluated `s[i]` and built the string forwards without passing an accumulator, we wouldn't have a returned string to append our current character to. (Both top-down and bottom-up approaches are valid, but building it backwards relies purely on the return values).
