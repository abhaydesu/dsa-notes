## Concept: Two Types of Recursion

Recursion generally falls into two primary categories in DSA:

1. **Sub-Problem Based (Focus of this lecture):** You have a large input (e.g., an array of size $N$). You separate one element, recursively solve the remaining $N-1$ elements, and combine the results. Used heavily in Trees and 30% of DP problems.
    
2. **Choice/Backtracking Based:** You have a sequence of decisions to make (e.g., take or don't take an item). You explore paths and reverse decisions. Used heavily in Graphs (DFS) and 70% of DP problems.
    

## The Universal Sub-Problem Template

Any problem that asks you to compute a singular result (Sum, Max, Min, Product) over an input can be solved using this exact 4-step template.

### Step 1: The Base Case (Smallest Input)

What is the absolute smallest, most trivial input for this problem?

- _For an array:_ Usually an array of size `1`.
    
- _Action:_ Return the obvious answer for that input. (e.g., The max of a 1-element array is just that element).
    

### Step 2: Isolate the Current Element

Grab the "last" element of the current input and hold onto it.

- _Action:_ `last_element = arr[n - 1]`
    

### Step 3: The Leap of Faith

Assume you have a magical helper function that can give you the correct answer for the rest of the array ($N-1$ elements). You do not need to know _how_ it works, just trust that it will.

- _Action:_ Call the exact same function, but pass `n - 1` as the size.
    
- `answer_for_rest = recursiveFunction(arr, n - 1)`
    

### Step 4: The Combination Step

Combine your isolated `last_element` with the `answer_for_rest` to form the final answer for size $N$.

- _For Sum:_ `return last_element + answer_for_rest`
    
- _For Max:_ `return max(last_element, answer_for_rest)`
    

## Example: Find Maximum in an Array

Let's apply the template to finding the maximum element in an array without using a `for` loop.

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

using namespace std;

int findMax(vector<int>& arr, int n) {
    // Step 1: Base Case (Smallest possible input)
    // If the array has only 1 element, that element is the maximum.
    if (n == 1) {
        return arr[0];
    }
    
    // Step 2: Isolate the current element
    // Grab the last element of the current array slice.
    int last_element = arr[n - 1];
    
    // Step 3: Leap of Faith
    // Trust the function to find the maximum in the remaining (n-1) elements.
    int max_of_rest = findMax(arr, n - 1);
    
    // Step 4: Combine
    // The absolute maximum is simply the larger of the two.
    return max(last_element, max_of_rest);
}

int main() {
    vector<int> arr = {5, 3, 2};
    cout << findMax(arr, 3) << endl; // Output: 5
    return 0;
}
```

## Behind the Magic: The Call Stack Trace

Why does this work when it looks like "no actual work" is being done? Because the work is deferred until the Base Case is hit, and then computed backwards.

Let's trace `findMax([5, 3, 2], 3)`:

1. **Call `findMax(n=3)`:**
    
    - `last = 2`
        
    - Calls `findMax(n=2)`. **Pauses.**
        
2. **Call `findMax(n=2)`:**
    
    - `last = 3`
        
    - Calls `findMax(n=1)`. **Pauses.**
        
3. **Call `findMax(n=1)`:**
    
    - Base case triggered! Returns `arr[0]` which is `5`.
        
4. **Resume `findMax(n=2)`:**
    
    - Receives `5` from the recursive call.
        
    - Combines: `max(last=3, rest=5)` $\rightarrow$ Returns `5`.
        
5. **Resume `findMax(n=3)`:**
    
    - Receives `5` from the recursive call.
        
    - Combines: `max(last=2, rest=5)` $\rightarrow$ Returns `5`.
        

The "magic" happens on the way back up the stack. Every paused function waits for the smaller answer, combines it with its own piece of data, and passes the updated answer up the chain.

##  Active Recall

**Q: In the Sub-Problem template, why do we isolate `arr[n-1]` and recursively call `n-1` instead of isolating `arr[0]` and passing the rest?**

**A:** In languages like C++ or Java, passing "the rest of the array" starting from index 1 requires creating a new subarray or passing start/end pointers, which uses extra memory or complicates the function signature. By simply passing the original array and reducing the "size" parameter (`n`), we effectively ignore the last element (`arr[n-1]`) in the next call, logically shrinking the array from the right side down to index 0 using $O(1)$ extra space per call.

**Q: What happens mathematically if the Base Case in this `findMax` function is set to `if (n == 0) return 0;` instead of `if (n == 1) return arr[0];`?**

**A:** If the base case returns `0` for an empty array, the algorithm will fail if the input array contains _only negative numbers_ (e.g., `[-5, -10]`). The combination step would eventually evaluate `max(-5, 0)` and incorrectly return `0` as the maximum, even though `0` is not in the array. Setting the base case to `n == 1` returning `arr[0]` ensures the baseline comparison is an actual element from the input data.

**Q: How would you modify the combination step (Step 4) if the problem asked you to find the _product_ of all elements in the array?**

**A:** Instead of using the `max()` function, you would simply multiply the isolated element with the result of the recursive call: `return last_element * answer_for_rest;`. The Base Case would also remain `if (n == 1) return arr[0];`.
