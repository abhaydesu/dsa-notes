## Problem 1: Fibonacci Number

**Problem Statement:** The Fibonacci numbers form a sequence where each number is the sum of the two preceding ones, starting from 0 and 1.

`F(0) = 0, F(1) = 1`

`F(n) = F(n - 1) + F(n - 2), for n > 1.`

Given `n`, calculate `F(n)`.

**Example:**

- `n = 4`
    
- Sequence: `0, 1, 1, 2, 3...`
    
- **Output:** `3`
    

### Logic & Intuition

To solve this recursively, we apply the Universal 3-Step Template:

1. **Base Case (The Smallest Input):** If `n` is `0`, the answer is `0`. If `n` is `1`, the answer is `1`. We are explicitly given these starting values.
    
2. **The Leap of Faith:** If we want the $N^{th}$ Fibonacci number, we need the answers for the $(N-1)^{th}$ and $(N-2)^{th}$ numbers. We blindly trust our function to fetch these two values for us: `ans1 = fib(n-1)` and `ans2 = fib(n-2)`.
    
3. **The Small Contribution:** Once we receive those two values, our only job is to add them together and return the result: `return ans1 + ans2`.
    

### Pseudo-code

```cpp
function fib(n):
    // Step 1: Base Case
    if n == 0:
        return 0
    if n == 1:
        return 1
        
    // Step 2: Leap of Faith (Trust the function)
    ans1 = fib(n - 1)
    ans2 = fib(n - 2)
    
    // Step 3: Combine and return
    return ans1 + ans2
```

### The Call Stack Trace (Dry Run for `n = 3`)

1. **`fib(3)`** is called. It needs `fib(2)` and `fib(1)`. It calls `fib(2)` and **pauses**.
    
2. **`fib(2)`** is called. It needs `fib(1)` and `fib(0)`. It calls `fib(1)` and **pauses**.
    
3. **`fib(1)`** is called. _Base case hit!_ Returns `1` to `fib(2)`.
    
4. **`fib(2)`** resumes, now calls `fib(0)`.
    
5. **`fib(0)`** is called. _Base case hit!_ Returns `0` to `fib(2)`.
    
6. **`fib(2)`** has both answers. It calculates `1 + 0 = 1` and returns `1` to `fib(3)`.
    
7. **`fib(3)`** resumes. It now has `ans1 = 1`. Next, it calls `fib(1)` (for `ans2`).
    
8. **`fib(1)`** is called. _Base case hit!_ Returns `1` to `fib(3)`.
    
9. **`fib(3)`** has both answers. It calculates `1 + 1 = 2` and returns the final answer: **`2`**.
    

## Problem 2: Valid Palindrome String

**Problem Statement:** Given a string, determine if it reads the same forwards and backwards.

**Example:**

- `s = "naman"` $\rightarrow$ **Output:** `True`
    
- `s = "abc"` $\rightarrow$ **Output:** `False`
    

### Logic & Intuition

Think about how a human checks a palindrome. We look at the first and last letters. If they are different, we instantly know it's not a palindrome. If they are the same, we ignore them and move inward to check the remaining substring.

1. **Base Case:** What is the smallest string?
    
    - A string of length `0` (empty) is technically a palindrome (`True`).
        
    - A string of length `1` is exactly the same forwards and backwards (`True`).
        
2. **The Small Contribution:** Compare the first and last characters (`s[low]` and `s[high]`). If they are NOT equal, immediately return `False`.
    
3. **The Leap of Faith:** If the first and last characters _are_ equal, the fate of the entire string depends purely on the middle portion. We trust the recursive function to evaluate the substring by moving the pointers inward: `return checkPalindrome(s, low + 1, high - 1)`.
    

### Pseudo-code

```cpp
function isPalindrome(s, low, high):
    
    // Calculate the length of the current substring
    length = high - low + 1
    
    // Step 1: Base Case
    if length == 0 or length == 1:
        return true
        
    // Step 2: The Small Contribution (Check outer bounds)
    if s[low] != s[high]:
        return false
        
    // Step 3: Leap of Faith (Delegate the middle portion)
    return isPalindrome(s, low + 1, high - 1)
```

_(Note: If `s[low] == s[high]`, the function doesn't need to do any additional addition or combination like the Fibonacci problem. It simply directly returns whatever the inner substring evaluation dictates)._

## Complexity Analysis

**Fibonacci (`fib(n)`):**

- **Time Complexity:** $O(2^N)$. Every function call spawns two more function calls, creating a massive binary tree of recursion. This is highly inefficient and will be optimized later using Dynamic Programming.
    
- **Space Complexity:** $O(N)$ auxiliary stack space. The maximum depth of the recursive call stack is $N$.
    

**Palindrome (`isPalindrome`):**

- **Time Complexity:** $O(N)$. In the worst-case scenario (a valid palindrome), the pointers traverse to the middle of the string, performing a constant time $O(1)$ check at each step.
    
- **Space Complexity:** $O(N)$ auxiliary stack space due to the recursive calls waiting on the stack.
    

## Active Recall

**Q: In the Fibonacci recursion tree, why is it considered inefficient?**

**A:** The standard recursive Fibonacci solution performs a massive amount of redundant work. For example, to calculate `fib(5)`, it computes `fib(4)` and `fib(3)`. But to compute `fib(4)`, it _again_ computes `fib(3)`. The same sub-problems are repeatedly solved from scratch, leading to an exponential $O(2^N)$ time complexity.

**Q: For the Palindrome problem, how does `high - low + 1` accurately determine the base cases for both even and odd length strings?**

**A:** For odd-length strings (like `"naman"`), the pointers will eventually land on the exact same middle character (e.g., `low = 2`, `high = 2`). `2 - 2 + 1 = 1`, triggering the length `1` base case. For even-length strings (like `"naan"`), the pointers will cross each other after checking the middle two characters (e.g., `low = 2`, `high = 1`). `1 - 2 + 1 = 0`, triggering the length `0` base case.

**Q: What would happen if we omitted the `length == 0` base case in the Palindrome function and only kept `length == 1`?**

**A:** The function would fail (or throw an Out-of-Bounds/Stack Overflow error) for any even-length palindrome. The pointers would cross each other (`low > high`), completely skipping the `length == 1` check, and the function would continue recursing infinitely or crash when trying to access invalid indices.

**Q: In the recursive Fibonacci function, what happens to `fib(3)` while it waits for `fib(2)` to finish executing?**

**A:** The execution of `fib(3)` is completely paused and stored on the Call Stack. It cannot proceed to its next line of code (calling `fib(1)`) until `fib(2)` has fully resolved and returned an integer value.
