### 1. The Core Philosophy of Recursion

- **The Myth:** Most people think recursion is primarily about "making the input smaller."
    
- **The Reality:** The primary action in recursion is **making decisions (choices)**.
    
- **The Flow:** You are given a problem statement. You look at your available choices and make a decision. As a direct result of taking that decision, the input _automatically_ becomes smaller.
    
- _Takeaway:_ Focus on the choices you need to make, and the input reduction will happen as a byproduct.
    

### 2. The Recursive Tree

- Because recursion involves making multiple choices at multiple steps, you need a way to visualize these decisions.
    
- We use a **Recursive Tree** to represent all possible choices and their outcomes. If you can build the tree, you can solve the problem.
    

### 3. The "Input-Output" Method

A simple technique to perfectly design a Recursive Tree on paper:

- **The Setup:** You start with two variables: your given `Input` (e.g., string "abc") and an empty `Output` (e.g., "").
    
- **The Branches (Decisions):** At each step, you take an element from the input and make a choice (e.g., _Branch 1: Include the character in the output. Branch 2: Do not include it._)
    
- **The Progression:** Every time you move down a branch, the `Input` shrinks (because you processed an element), and the `Output` updates based on your decision.
    
- **The Leaf Nodes:** When the `Input` becomes completely empty, you have reached the end of that branch. The data collected in your `Output` variable at these leaf nodes are your final answers.
    

### 4. The 2-Step Process to Solve Any Recursion Problem

1. **Step 1: Design the Recursive Tree.** Use the Input-Output method to draw out the decisions on paper. Do not skip this!
    
2. **Step 2: Write the Code.** If your recursive tree is logically sound, writing the code is a piece of cake. The code will simply mimic the branches of your tree.
