## Key concepts

|**Term**|**Definition (your words)**|
|---|---|
|**Binary Tree**|A hierarchical data structure where any parent node is restricted to having a maximum of two child nodes.|
|**Subtree**|A structural subset consisting of a specific node and every descendant extending beneath it.|
|**Full Binary Tree**|A structural classification where every single node must have either exactly zero or exactly two children.|
|**Complete Binary Tree**|A tree where all upper levels are maximally packed, and the lowest level fills sequentially from the far left without gaps.|
|**Perfect Binary Tree**|A perfectly symmetrical tree where every internal node has two children and every leaf terminates at the exact same depth.|
|**Degenerate Tree**|A skew structure where every node has only one child, functionally reducing the tree to a linear linked list.|

## Structured notes

### Hierarchy & Nomenclature

- Trees organize data hierarchically (akin to file system folders), contrasting with linear arrays or linked lists (established).
    
- The topmost starting node acts as the `root`, while nodes lacking any children are designated as `leaf` nodes (consensus).
    
- Any node situated strictly above a target node in its direct lineage is classified as an `ancestor` (established).
    

### Tree Classifications

- **Full Binary Trees** evaluate node capacity: a single child is an invalid state (established).
    
- **Complete Binary Trees** evaluate structural density: the final tier must populate strictly left-to-right (established).
    
    - > [!warning] A single gap on the left side of the lowest level invalidates the "Complete" classification, even if the right side has nodes.
        
- **Balanced Binary Trees** restrict maximum vertical depth strictly to $\log_2(n)$ (where $n$ is total nodes) to optimize search efficiency (consensus).
    
- **Degenerate Trees** occur when the hierarchy breaks down into a single line, causing operations to degrade to $O(n)$ time complexity (established).
    

## Elaboration

> [!question] Why differentiate between Full and Complete binary trees?
> 
> A _Full_ binary tree restricts the number of children per node (strictly 0 or 2) but ignores their depth alignment. A _Complete_ binary tree ignores the 0-or-2 rule at the bottom layer but enforces strict left-to-right filling. This left-to-right density is what allows Complete trees to be represented efficiently as flat arrays (vital for Heap data structures) without wasting memory on empty indices.

## Quick recall

**What is the foundational rule that makes a tree a "Binary" tree?**

A parent node can possess zero, one, or two children, but never more than two.

**How does a Perfect Binary Tree structurally differ from a Complete Binary Tree?**

A Perfect Binary Tree requires all leaf nodes to terminate at the exact same depth level. A Complete tree allows the lowest level to be partially filled as long as nodes are placed strictly left-to-right.

**What makes a Degenerate Tree dangerous for performance?**

Since every parent has exactly one child, the tree becomes a linked list, stripping away the logarithmic search efficiencies usually associated with tree structures.

**If a node has two children, but those children are leaves at different depths, can the tree be considered a Full Binary Tree?**

Yes. Full Binary Trees only require nodes to have 0 or 2 children; they do not enforce alignment or depth rules.
