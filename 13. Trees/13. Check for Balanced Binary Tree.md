## The Basics

A **Balanced Binary Tree** is a tree where, for _every single node_, the height of its left subtree and the height of its right subtree differ by no more than 1.

- **Condition:** `| Height(Left Subtree) - Height(Right Subtree) | <= 1`
    
- If even a single node in the entire tree violates this rule, the entire tree is considered unbalanced.
    

## The Naive Approach (O(N²))

- **How it works:** Traverse to every node in the tree. For each node, calculate the height of its left subtree and the height of its right subtree using a standard height function.
    
- **Why it's bad:** Calculating the height takes O(N) time. Doing this for every single node (N nodes) makes the overall time complexity O(N²). For large trees, or specifically skewed trees, this is highly inefficient.
    

## The Optimal Approach (O(N))

- **The Core Idea:** You can calculate the height and check for balance at the exact same time in a single bottom-up recursive traversal.
    
- **The Trick:** Modify the standard "Find Height" function.
    
    - Normally, a height function returns an integer representing the height.
        
    - We change it so that if a subtree is _balanced_, it returns its actual height.
        
    - If a subtree is _unbalanced_, it immediately returns **`-1`**.
        
- **The Logic:**
    
    1. Recursively find the height of the left subtree (`LH`).
        
    2. If `LH` comes back as `-1`, it means the left side is unbalanced. Immediately return `-1` to the parent without checking anything else.
        
    3. Recursively find the height of the right subtree (`RH`).
        
    4. If `RH` comes back as `-1`, immediately return `-1`.
        
    5. Check the balance of the current node: If the absolute difference between `LH` and `RH` is greater than 1, return `-1`.
        
    6. If it passes all checks, return the actual height of the node: `1 + max(LH, RH)`.
        

## The Final Check

In your main function, you simply call this modified DFS height function.

- If the result is `-1`, the tree is unbalanced (return `false`).
    
- If the result is anything else (a positive integer), the tree is balanced (return `true`).
    

## Complexity Analysis

- **Time Complexity:** **O(N)**. We visit every node exactly once during the DFS traversal. The moment we spot an imbalance, we short-circuit and backtrack, making it very efficient.
    
- **Space Complexity:** **O(H)** auxiliary space for the recursion stack, where H is the height of the tree. In the worst case (a completely skewed tree), this is **O(N)**.
    

## Active Recall

**Q1: What defines a balanced binary tree?** **Answer:** For every node in the tree, the absolute difference between the height of its left subtree and its right subtree cannot exceed 1.

**Q2: Why is the naive approach to checking balance O(N²)?** **Answer:** Because it visits every node (O(N)) and calls a separate height-calculating function (which also takes O(N)) on every single node.

**Q3: In the optimal O(N) approach, what dual purpose does the recursive function serve?** **Answer:** It calculates and returns the actual height of valid subtrees, but acts as an error flag by returning `-1` the moment it detects an unbalanced subtree.

**Q4: During the optimal recursive traversal, what happens if the recursive call to the left child returns `-1`?** **Answer:** The current node immediately returns `-1` to its parent without even bothering to calculate the right side, short-circuiting the process.

**Q5: What is the space complexity of the optimal solution and what dictates it?** **Answer:** The space complexity is O(H) or worst-case O(N). It is dictated entirely by the recursion stack trace depth.
