## The Basics

Postorder sequence: **Left -> Right -> Root**. While using two stacks is easier to implement, doing it with just **one Stack** is a classic interview challenge. It requires careful tracking of nodes to know whether you are returning from a left child or returning from a right child.

## The Core Concept

The algorithm mimics the recursive stack strictly:

1. Go as far Left as possible, pushing nodes onto the stack.
    
2. If you hit `null` (no left child), check if there is a Right child.
    
    - If yes, move to that Right child and repeat step 1.
        
    - If no Right child exists (it's a leaf), **Print** the node.
        
3. **The Tricky Part (Backtracking):** After printing a node, you must check if that just-printed node was the _right child_ of the node currently sitting on top of the stack.
    
    - If it was, it means both the left and right sides of that parent node are finished. You must pop and print the parent node too, and repeat this check upwards.
        

## The Algorithm Steps

1. **Initialize:** Create a `current` node pointing to `root`, and an empty `Stack`.
    
2. **Start Outer Loop:** Run while `current` is not `null` OR the Stack is not empty.
    
3. **Go Left:** If `current` is not `null`:
    
    - Push `current` to the stack.
        
    - Move `current = current.left`.
        
4. **Process/Go Right:** If `current` is `null` (hit a dead end):
    
    - Peek at the top of the stack. Check its right child using a temporary variable `temp = stack.top().right`.
        
    - **Case A (Right exists & unvisited):** If `temp` is NOT `null`, it means we haven't explored the right side yet. Move `current = temp` to start plunging down this right branch.
        
    - **Case B (No right child OR right child already visited):** If `temp` IS `null`, we are at a leaf.
        
        - Pop the top node from the stack (using `temp`) and print/store it.
            
        - _Backtrack Loop:_ Now, repeatedly check if `temp` (the node you just popped) is equal to `stack.top().right`.
            
        - If they match, it means you just finished processing a right child, so its parent (currently on top of the stack) is also completely finished. Pop the parent, print it, and update `temp` to this new popped node. Continue checking upward until this condition fails.
            

## Complexity

- **Time Complexity:** **O(2N)** which simplifies to **O(N)**. In the worst case, you visit every node to push it into the stack, and then the inner `while` loop checks/pops every node on the way back up.
    
- **Space Complexity:** **O(H)**, where H is the height of the tree, representing the maximum depth of the stack. In the worst-case (a completely skewed tree), this is **O(N)**.
    

## Active Recall

**Q1: What is the sequence for a Postorder Traversal?** **Answer:** Left -> Right -> Root.

**Q2: In the 1-Stack method, what do you do first?** **Answer:** You travel as far left as possible, pushing every node you encounter onto the stack.

**Q3: When the `current` pointer becomes `null`, what do you check before popping a node?** **Answer:** You peek at the top node of the stack and check if it has a right child that hasn't been visited yet.

**Q4: How does the algorithm know it's time to process a parent node (root) from the stack?** **Answer:** It uses an inner `while` loop to check if the node it just popped and printed was the _right child_ of the node currently at the top of the stack. If it was, the parent node is also finished and ready to be printed.

**Q5: Why is the worst-case time complexity considered O(2N)?** **Answer:** Because it takes O(N) operations to traverse and push all nodes into the stack, and another O(N) operations for the inner `while` loop to pop and process them as it backtracks up the tree.
