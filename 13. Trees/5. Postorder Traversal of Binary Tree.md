## The Basics

Postorder traversal dictates that we visit the nodes in this exact sequence: **Left -> Right -> Root**. As the name "post" implies, the root node of any given subtree is processed (or printed) last.

## The Code Logic (Recursive)

Just like Preorder and Inorder traversals, the logic is very simple and directly mimics the traversal rule.

1. **Base Case:** If the current `node` is `null`, `return`.
    
2. **Visit Left:** Recursively call `postorder(node.left)`.
    
3. **Visit Right:** Recursively call `postorder(node.right)`.
    
4. **Process Root:** Print (or process) the data of the current `node`.
    

## Dry Run Visualization

When dry running this algorithm, remember that a node can only be printed when _both_ its left and right subtrees have been completely resolved.

- Starting at the main root, the program dives down the left side of the tree as far as possible.
    
- When it reaches a node whose left child is `null`, it returns. The program then checks that same node's right child.
    
- If the right child is also `null` (meaning it's a leaf node), it returns.
    
- Now that the node has checked Left and checked Right, it finally executes the **Print** command.
    
- Once printed, that recursive call ends and control is handed back up to the parent node. The parent node will then move to check its own Right side before it is allowed to print itself.
    

## Key Takeaway

Trust the recursive flow. You do not need to overcomplicate the logic; just remember the three steps (Left, Right, Print) and the recursion stack naturally handles the complex traversal path.

## Active Recall

**Q1: What is the specific sequence for a Postorder traversal?** **Answer:** Left -> Right -> Root.

**Q2: In the recursive Postorder function, when is a node actually printed?** **Answer:** A node is printed only after both its recursive left call and recursive right call have completely executed and returned.

**Q3: What happens when the recursive function encounters a `null` node?** **Answer:** It hits the base case and immediately returns, handing control back to the function that called it.

**Q4: If a node has a left child but no right child, what happens after the left subtree finishes processing?** **Answer:** The code will try to process the right child, immediately hit a `null` and return, and then move on to print the current node's data.
