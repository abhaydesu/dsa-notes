## Concept: What is a Sliding Window?

A "window" represents a contiguous subset of elements within a linear data structure.

"Sliding" means this window moves across the data structure. It operates using two pointers (often `low` and `high`, or `left` and `right`) that traverse the data strictly in one direction (left to right).

- **Expand:** Incrementing the `high` (right) pointer increases the distance between the two pointers, expanding the window's size.
    
- **Shrink:** Incrementing the `low` (left) pointer decreases the distance between the two pointers, shrinking the window's size.
    

_(External Note: Unlike standard Two Pointer problems where pointers might move toward each other from opposite ends, Sliding Window pointers act like a caterpillar, always crawling in the same direction)._

##  Pattern Identification: When to Use Sliding Window?

The instructor provides a strict flowchart to identify Sliding Window problems. You must pass all checks.

### 1. Data Structure Check

- **Must be:** Array or String. (Strings are essentially character arrays).
    
- **Must NOT be:** Linked List. (Sliding window requires contiguous memory evaluation, which is inefficient/impractical in a linked list).
    

### 2. State/Keyword Check

The problem description must specifically ask you to evaluate a continuous segment.

- **Keywords:** "Subarray" (for arrays) or "Substring" (for strings).
    
- **Warning:** Do not confuse these with "Subsequence".
    
    - _Subarray/Substring:_ Strictly contiguous elements (e.g., in `[1, 2, 3]`, `[1, 2]` is a subarray).
        
    - _Subsequence:_ Elements in order, but not necessarily contiguous (e.g., in `[1, 2, 3]`, `[1, 3]` is a subsequence). Sliding Window **cannot** be used for sub-sequences.
        

### 3. Goal Check

If checks 1 and 2 are passed, look for what the question is asking you to compute regarding that subarray/substring.

- **Find the:** `Maximum`, `Minimum`, `Longest`, `Shortest`
    
- **Calculate the:** `Sum`, `Average`, `Count`
    
- **Satisfy conditions like:** `At most K`, `At least K`, `Exactly K` (e.g., "Longest substring with at most K distinct characters").
    

##  Types of Sliding Windows

There are two variations of the Sliding Window technique depending on the problem's constraints.

### 1. Fixed-Size Window

Used when the problem explicitly gives you the length/size of the subarray or substring (e.g., "Find the maximum sum of any subarray of size $K=3$").

- **Logic:** The window size never changes. Once the window reaches size $K$, for every new element added by sliding `high` forward, you must instantly drop the oldest element by sliding `low` forward.
    

### 2. Dynamic-Size Window

Used when the length of the subarray/substring is not given, or the goal is to _find_ the length (e.g., "Find the longest subarray whose sum is less than $K$").

- **Logic:** The window expands as long as a certain condition is met. Once the condition is violated, the window shrinks until the condition becomes valid again.
    

## The Core Optimization (Why it's faster)

To understand why Sliding Window is an optimization, let's look at calculating the maximum sum of a subarray of size $K=3$ on the array `[1, 0, 3, 5, 2]`.

### Approach 1: Brute Force

Find all possible subarrays of size 3 and sum them from scratch.

- Sum of `[1, 0, 3]` $\rightarrow$ $1 + 0 + 3 = 4$
    
- Sum of `[0, 3, 5]` $\rightarrow$ $0 + 3 + 5 = 8$
    
- Sum of `[3, 5, 2]` $\rightarrow$ $3 + 5 + 2 = 10$
    
    Notice that between the first and second subarray, the elements `0` and `3` overlap completely. The brute force method blindly recalculates this overlapping segment.
    

### Pseudo-code: Brute Force

Plaintext

```
function maxSumBruteForce(arr, k):
    n = length of arr
    max_sum = -infinity
    
    // Loop through every possible starting position
    for i = 0 to n - k:
        current_sum = 0
        // Calculate sum of the next k elements
        for j = i to i + k - 1:
            current_sum = current_sum + arr[j]
            
        max_sum = max(max_sum, current_sum)
        
    return max_sum
```

### Approach 2: Sliding Window (Optimal)

Instead of recalculating the entire subset, take the previous sum, **subtract the element leaving the window**, and **add the new element entering the window**.

- Initial Window Sum (`[1, 0, 3]`): $4$
    
- Slide Window Right: Previous Sum ($4$) $-$ Element Leaving ($1$) $+$ Element Entering ($5$) $=$ $8$.
    
- Slide Window Right: Previous Sum ($8$) $-$ Element Leaving ($0$) $+$ Element Entering ($2$) $=$ $10$.
    

This converts an $O(N \times K)$ brute-force approach into a strictly $O(N)$ linear pass.

### Pseudo-code: Fixed Sliding Window

Plaintext

```
function maxSumSlidingWindow(arr, k):
    n = length of arr
    if n < k:
        return 0
        
    max_sum = 0
    current_sum = 0
    
    // Step 1: Compute the sum of the first window (size k)
    for i = 0 to k - 1:
        current_sum = current_sum + arr[i]
        
    max_sum = current_sum
    
    // Step 2: Slide the window across the array
    for i = k to n - 1:
        // Subtract the element going out of the window
        // Add the element coming into the window
        current_sum = current_sum - arr[i - k] + arr[i]
        
        max_sum = max(max_sum, current_sum)
        
    return max_sum
```

## Active Recall

**Q: What is the fundamental difference between a Subarray/Substring and a Subsequence, and why does it matter for Sliding Window?**

**A:** A Subarray/Substring consists of strictly contiguous (adjacent) elements. A Subsequence consists of elements in order, but they do not have to be contiguous. Sliding Window can only be used on contiguous data; it cannot solve Subsequence problems.

**Q: When reading a problem description, how do you determine if you need a Fixed-Size window or a Dynamic-Size window?**

**A:** You use a Fixed-Size window when the problem explicitly gives you the length `K` of the subarray/substring to evaluate. You use a Dynamic-Size window when the problem asks you to _find_ the length (e.g., longest, shortest) based on a specific condition.

**Q: What is the core mathematical trick that makes a Fixed Sliding Window faster than a Brute Force loop for calculating sums?**

**A:** Instead of recalculating the sum of the entire window from scratch every time it moves, you take the previously calculated sum, subtract the value of the single element leaving the window, and add the value of the single element entering the window.

**Q: If a problem asks you to evaluate elements in a Linked List, should you use the Sliding Window pattern?**

**A:** No. Sliding Window almost exclusively applies to Arrays and Strings because it relies on evaluating a continuous block of memory/indices, which Linked Lists do not support efficiently.
