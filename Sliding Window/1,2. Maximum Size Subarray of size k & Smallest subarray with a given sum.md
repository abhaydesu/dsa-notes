## The 4-Step Framework for Sliding Window

Before jumping into the problems, the instructor outlines a universal 4-step framework that applies to every sliding window question.

1. **Identify the Pattern:** Use the flowchart (Array/String $\rightarrow$ Subarray/Substring $\rightarrow$ Goal: Max/Min/Sum/Average/At most K).
2. **Determine Window Type:** Is the window _Fixed_ (size is given and constant) or _Variable_ (size changes based on a condition)?
3. **Find Starting Window Information:** Determine the starting pointers (`low`, `high`) and calculate the initial "information" (e.g., sum, count, max) for this first window manually.
4. **Slide and Update:** Slide the window. Instead of recalculating the information from scratch, update it by _subtracting_ the element that left the window and _adding_ the new element that entered. Repeat until the array ends.

## Problem 1: Maximum Sum of Any Subarray of Size K

**Type:** Easy | Fixed-Size Window

**Problem Statement:** Given an array of integers and a number $K$, find the maximum sum of any contiguous subarray of size exactly $K$.

### Pattern Identification

- **Structure:** Array.
- **Keyword:** Subarray.
- **Goal:** Maximum Sum.
- **Window Type:** Fixed (size $K$ is explicitly given).

### Logic & Intuition

The naive approach is to calculate the sum of every $K$-sized subarray from scratch. However, when sliding a window by one step, only two things change: one element leaves the window (from the back), and one new element enters the window (at the front).

**The Human Analogy:**

If 5 people give you money and you count a total of ₹26, and then one person says "Give me my ₹2 back, my brother will give you ₹1 instead"—you don't return everyone's money and count again. You take the ₹26, subtract ₹2, add ₹1, and know you have ₹25.

### Pseudo-code: Fixed Sliding Window
```cpp
function maxSumFixedWindow(arr, k):
    n = length of arr
    if n < k:
        return 0 // Edge case if array is smaller than window
        
    low = 0
    high = k - 1 // High is always placed at the end of the window
    
    current_sum = 0
    
    // Step 3: Find info for the first window
    for i = low to high:
        current_sum = current_sum + arr[i]
        
    max_sum = current_sum
    
    // Step 4: Slide the window
    while high < n - 1:
        // Move the window forward
        low = low + 1
        high = high + 1
        
        // Update information: Subtract the element left behind, add the new element
        current_sum = current_sum - arr[low - 1] + arr[high]
        
        // Record maximum
        max_sum = maximum(max_sum, current_sum)
        
    return max_sum
```

_Note: In the video, the instructor placed the `max` check and then sliding logic inside the `while` loop. The logic remains mathematically identical as long as the first window is evaluated._

### Complexity Analysis

- **Time Complexity:** $O(N)$. We process the array once. The `while` loop runs $(N - K)$ times doing $O(1)$ constant operations.
- **Space Complexity:** $O(1)$. No auxiliary data structures are used.

##  Problem 2: Minimum Size Subarray Sum

**Type:** Medium | Variable-Size Window

**Problem Statement:** Given an array of positive integers and a target variable, return the **minimal length** of a contiguous subarray whose sum is **greater than or equal to** the target. If there is no such subarray, return 0.

###  Pattern Identification

- **Structure:** Array.
- **Keyword:** Subarray.
- **Goal:** Minimum length + sum condition (greater than or equal to target).
- **Window Type:** Variable. (The problem asks for the minimum length, implying the length is unknown and dynamic).

### Logic & Intuition: The Amazon Hiring & Firing Analogy

In a variable sliding window, `low` and `high` both start at `0` (an empty/1-element company).

- **Expanding the Window (`high++`) = "Hiring":** Amazon keeps hiring employees (adding `arr[high]` to `current_sum`) until the work gets done (i.e., `current_sum >= target`).
- **Shrinking the Window (`low++`) = "Firing":** Once the work is getting done, the company gets greedy. They want to know if the work can be done with _fewer_ people to save money. They record the current team size (window length). Then, they fire the oldest employee (subtract `arr[low]` and increment `low`).
- If the work is _still_ getting done, they record the new smaller team size and fire the next person.
- If the work stops getting done (`current_sum < target`), they pause firing and go back to the college to hire the next available person (`high++`).

### Pseudo-code: Variable Sliding Window

```cpp
function minSubArrayLen(arr, target):
    n = length of arr
    low = 0
    high = 0
    
    // Initialize to infinity so any valid length will be smaller
    min_length = infinity 
    current_sum = 0
    
    while high < n:
        // "Hiring": Add the new element to our current work capacity
        current_sum = current_sum + arr[high]
        
        // "Work is getting done": While condition is met, try to minimize the window
        while current_sum >= target:
            // Calculate current window length
            current_length = (high - low) + 1
            min_length = minimum(min_length, current_length)
            
            // "Firing": Remove the oldest element and shrink from the left
            current_sum = current_sum - arr[low]
            low = low + 1
            
        // Move to the next potential hire
        high = high + 1
        
    // If min_length wasn't updated, no valid subarray was found
    if min_length == infinity:
        return 0
        
    return min_length
```

### Complexity Analysis

- **Time Complexity:** $O(N)$. Even though there is a `while` loop inside a `while` loop, this is strictly $O(N)$. Why? The `high` pointer iterates through the array at most $N$ times. The `low` pointer also iterates through the array at most $N$ times. Both pointers only ever move forward. Total operations are bounded by $2N$.
- **Space Complexity:** $O(1)$.

##  Active Recall

**Q: In the 4-step framework for Sliding Window, what is the core difference between Step 3 (First Window Info) and Step 4 (New Window Info)?**

**A:** In Step 3, you usually have to calculate the information (like sum) manually by looping through the elements of the first window. In Step 4, you optimize by avoiding a loop: you take the previous window's information, subtract the element that left, and add the element that entered.

**Q: When solving a "Variable Size" sliding window problem, why do both `low` and `high` pointers start at index 0?**

**A:** Because the size of the valid window is unknown. You must start from the smallest possible valid state (a window of size 1 at the beginning of the array) and organically grow (`high++`) or shrink (`low++`) the window based on the problem's conditions.

**Q: In the Amazon hiring/firing analogy, what triggers the "firing" phase, and what mathematical operation does it represent?**

**A:** The "firing" phase triggers the moment the required condition is met (e.g., `current_sum >= target`). Mathematically, it represents an inner `while` loop that subtracts `arr[low]` from the running sum and increments the `low` pointer (`low++`), shrinking the window to find a smaller valid length.

**Q: Why is the time complexity of the variable sliding window $O(N)$ even though there is a nested `while` loop?**

**A:** Because the pointers `high` and `low` only move in one direction (forward). The `high` pointer processes each element exactly once, and the `low` pointer processes each element at most once. Therefore, the total number of inner loop iterations across the entire execution is at most $N$, making it $O(N)$ overall.
