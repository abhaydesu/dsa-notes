## Problem: Minimum Window Substring

**Problem Statement:** Given two strings `s` and `t` of lengths $N$ and $M$ respectively, return the **minimum window substring** of `s` such that every character in `t` (including duplicates) is included in the window. If there is no such window, return the empty string `""`.

**Example:**

- `s = "ADOBECODEBANC"`
- `t = "ABC"`
- **Goal:** Find the shortest substring in `s` that contains at least one 'A', one 'B', and one 'C'. (Order does not matter).

###  Pattern Identification

- **Structure:** String.
- **Keyword:** Substring.
- **Goal:** Minimum length substring satisfying a condition.
- **Window Type:** Variable (The size of the minimum window is unknown).
- **Template to Use:** The _Minimum Window Template_ (where we shrink the window while the condition is **VALID** to find smaller valid configurations).

## Logic & Intuition

How do we decide if a window is "valid"?

1. **The Information State:**
    We need to track the frequency of characters in our target string `t` (what we _need_) and the frequency of characters in our current sliding window in `s` (what we _have_).
2. **Using Arrays instead of Hash Maps:**
    Because there are 256 possible ASCII characters, we can use two fixed-size integer arrays of length 256.
    - `needed[256]`: Populated beforehand by iterating through `t`.
    - `have[256]`: Dynamically updated as our sliding window moves through `s`.
3. **Validity Check (The `isValid` function):**
    A window is valid if and only if, for _every_ character, `have[char] >= needed[char]`. If even a single character's frequency in `have` is strictly less than its frequency in `needed`, the window is invalid. (Extra characters in `have` do not affect validity).

## Pseudo-code: Minimum Window Substring

### Part 1: The Sliding Window Logic
```cpp
function minWindow(s, t):
    n = length of s
    m = length of t
    
    if n < m: return ""
    
    // Arrays for constant O(1) tracking
    needed = array of size 256 initialized to 0
    have = array of size 256 initialized to 0
    
    // Populate the 'needed' array based on target string t
    for char in t:
        needed[ascii_value(char)]++
        
    low = 0
    min_len = infinity
    start_index = 0
    
    // Step 1: Expand the window
    for high = 0 to n - 1:
        // Step 2: Include the 'high' character in our 'have' state
        current_char = ascii_value(s[high])
        have[current_char]++
        
        // Step 3: Shrink the window WHILE the information is VALID
        while isValid(have, needed):
            // Record the valid answer
            current_len = (high - low) + 1
            if current_len < min_len:
                min_len = current_len
                start_index = low
                
            // Remove the 'low' character and shrink
            char_to_remove = ascii_value(s[low])
            have[char_to_remove]--
            low = low + 1
            
    // Step 4: Return result
    if min_len == infinity:
        return ""
    else:
        return substring(s, start_index, min_len)
```

### Part 2: The Validity Check Function
```cpp
function isValid(have, needed):
    // Check all 256 possible characters
    for i = 0 to 255:
        // If we have less of ANY character than what is needed, it's invalid
        if have[i] < needed[i]:
            return false
            
    // If loop completes without returning false, all requirements are met
    return true
```

##  Complexity Analysis

- **Time Complexity:**
    - The `high` pointer iterates $N$ times.
    - The `low` pointer iterates at most $N$ times over the entire execution.
    - Inside the `while` loop, the `isValid` function takes exactly 256 operations ($O(1)$ constant time).
    - Overall Time Complexity: $O(N \times 256)$, which simplifies to strictly **$O(N)$**.
- **Space Complexity:** $O(1)$. The two frequency arrays (`have` and `needed`) always take exactly 256 slots regardless of the input sizes $N$ and $M$.

##  Active Recall

**Q: In the Minimum Window Substring problem, why do we use arrays of size 256 instead of standard Hash Maps to track character frequencies?**
**A:** Because there are a maximum of 256 standard ASCII characters. Using fixed-size arrays allows for true $O(1)$ constant-time lookups and updates without the hashing overhead. It also makes the `isValid` check execute in exactly 256 operations every time, maintaining the overall $O(N)$ time complexity.

**Q: When determining if the current sliding window is valid, do characters present in the window (`have`) that are NOT present in the target string (`needed`) make the window invalid?**
**A:** No. The condition is strictly `have[i] >= needed[i]`. If a character is not in `t`, its `needed[i]` value is `0`. Having any amount of that character in the window means `have[i] >= 0`, which satisfies the condition. Extra characters do not invalidate the window.

**Q: How do we extract the final substring answer if the sliding window process only tracks lengths?**
**A:** Whenever we find a valid window that is strictly shorter than our current `min_len`, we update `min_len` AND record the current `low` pointer as `start_index`. At the very end of the function, we use these two values to slice the original string.
