## Pattern Identification Flowchart

Before writing any code, verify if the problem fits the Sliding Window profile:

1. **Data Structure:** Array or String. (Rarely Linked Lists).
2. **Entity Required:** Subarray, Substring, or Window (must be contiguous elements).
3. **Target Objective:** You need to find or calculate something across these subarrays:
    - `Longest` / `Shortest`
    - `Maximum` / `Minimum`
    - `Sum` / `Average` / `Frequency`
    - Specific conditions like `Exactly K`, `At most K`, or `At least K`.

If a problem asks for a combination of these (e.g., "Find the longest substring with at most K distinct characters"), there is a 90% chance it is a Sliding Window problem.

## The 4 Universal Steps of Sliding Window

1. **Identify:** Confirm it's a sliding window problem using the flowchart.
2. **Determine Window Type:**
    - **Fixed:** The problem explicitly provides the size of the subarray/substring (e.g., "Subarrays of size K").
    - **Variable:** The problem asks you to _find_ the size (e.g., "Longest subarray", "Shortest subarray").
3. **Define Information:** What are you tracking inside the window? (e.g., Sum, Frequency Hash Map, Max value).
4. **Define Transitions:** How does the information update when the window slides? (e.g., subtract the leaving element, add the entering element).

##  Template 1: Fixed-Size Window

In a fixed-size window of length `K`, the pointers are always exactly `K-1` steps apart. The window slides one unit at a time.
### Pseudo-code: Fixed Sliding Window

```cpp
function fixedSlidingWindow(arr, k):
    n = length of arr
    
    // Step 1: Initialize window pointers
    low = 0
    high = k - 1
    
    // Step 2: Compute information for the FIRST window
    current_info = 0
    for i = low to high:
        current_info = current_info + arr[i] // Example: calculating sum
        
    result = current_info // Store initial result
    
    // Step 3: Slide the window
    while high < n - 1:
        // Remove the element leaving the window
        current_info = current_info - arr[low]
        low = low + 1
        
        // Add the element entering the window
        high = high + 1
        current_info = current_info + arr[high]
        
        // Update the result (e.g., finding the maximum sum)
        result = max(result, current_info)
        
    return result
```

##  Template 2: Variable-Size Window

In a variable-size window, the window starts empty. `low` and `high` both start at `0`.

- The `high` pointer continuously expands the window.
- The `low` pointer shrinks the window in an inner loop **only when the window's information becomes INVALID** (and shrinking it has the potential to make it valid again).

### Pseudo-code: Variable Sliding Window
```cpp
function variableSlidingWindow(arr, target):
    n = length of arr
    low = 0
    result = appropriate_initial_value // 0 for max length, infinity for min length
    current_info = initialize_info()
    
    // Step 1: Expand the window using a loop for 'high'
    for high = 0 to n - 1:
        // Include the 'high' element in the window's information
        current_info = add_to_info(current_info, arr[high])
        
        // Step 2: Check if information is INVALID
        // (e.g., if sum > target and we want exact target)
        while is_invalid(current_info):
            // Shrink the window from the left to try and fix the information
            current_info = remove_from_info(current_info, arr[low])
            low = low + 1
            
        // Step 3: Check if information is VALID
        // If it is, update the result
        if is_valid(current_info):
            current_length = (high - low) + 1
            result = update_result(result, current_length)
            
    return result
```

###  Critical Logic Check: When to Shrink (`low++`)

You only trigger the inner `while` loop to shrink the window if moving `low` forward will push the window _towards_ a valid state.

- **Example:** You need a target weight of exactly `100`.
- If current weight is `70` (Invalid), moving `low` forward will _decrease_ the weight (e.g., to `50`). This takes you further from `100`. Therefore, **do not shrink**.
- If current weight is `120` (Invalid), moving `low` forward will _decrease_ the weight (e.g., to `100`). This pushes you toward the goal. Therefore, **you must shrink**.

##  Active Recall

**Q: In a Fixed-Size Sliding Window of size `K`, if `low` starts at `0`, what index must `high` initially be set to?** 
**A:** `k - 1`.

**Q: When applying the Variable Sliding Window template to find a minimum or maximum, how should you initialize the `result` variable?** 
**A:** If finding a **minimum**, initialize `result` to Infinity (`INT_MAX`). If finding a **maximum**, initialize `result` to Negative Infinity (`INT_MIN`).

**Q: In a Variable Sliding Window, why is the outer loop typically an expansion loop (moving `high`) rather than a shrinking loop?** 
**A:** Because a variable window starts empty (`low = 0`, `high = 0`). You must first accumulate elements into the window (by moving `high`) to evaluate the information before you can decide if you need to shrink it (by moving `low`).

**Q: True or False: If the window's current state is invalid, you should always increment the `low` pointer until it becomes valid.**
**A:** False. You should only increment the `low` pointer if shrinking the window logically pushes the state _toward_ validity. If the condition requires a minimum threshold (e.g., sum must be exactly 100, but current sum is 70), shrinking the window will only decrease the sum further, making it impossible to reach the valid state.
