## Problem Statement: Rotate List (LeetCode 61)

Given the `head` of a linked list, rotate the list to the right by `k` places.

**Example:**

- **Input:** `head = [1, 2, 3, 4, 5]`, `k = 2`
    
- **Right Rotation 1:** `[5, 1, 2, 3, 4]` (The last element moves to the front).
    
- **Right Rotation 2:** `[4, 5, 1, 2, 3]`
    
- **Output:** `[4, 5, 1, 2, 3]`
    

## Logic & Intuition (The Circular Approach)

To rotate an Array, you must physically shift elements. But to rotate a Linked List, you don't shift nodes; you simply change two pointers.

Imagine taking the tail of the list and plugging it into the head. You now have a circle (a circular linked list).

Once you have a circle, rotating it just means choosing a _new_ place to cut the circle. The node right after the cut becomes the new `head`, and the node where you made the cut becomes the new `tail` (pointing to `NULL`).

### Finding the Cut Point

If the list has length $N$, and we rotate to the right by $K$:

- If $K = N$, the list completes a full cycle and looks exactly the same.
    
- Therefore, the effective rotations we actually need to perform is $K_{eff} = K \pmod N$.
    

When you rotate to the right by $K_{eff}$, the last $K_{eff}$ nodes move to the front.

This means the new tail of the list will be the node at position $N - K_{eff}$ (using 1-based indexing).

### Step-by-Step Breakdown

1. **Find Length and Tail:** Traverse the list to find its total length ($N$) and get a pointer to the very last node (`tail`).
    
2. **Make it Circular:** Point the `tail.next` to the original `head`.
    
3. **Calculate Effective K:** $K_{eff} = K \pmod N$.
    
    - If $K_{eff} == 0$, the list doesn't change. Break the circle (`tail.next = null`) and return `head`.
        
4. **Find the New Tail:** The new tail is located $N - K_{eff}$ steps from the original head. Traverse to this node.
    
5. **Break the Circle:**
    
    - The `new_head` is `new_tail.next`.
        
    - Sever the circle: `new_tail.next = null`.
        
6. **Return `new_head`**.
    

## Pseudo-code: Rotate List

```cpp
function rotateRight(head, k):
    // Edge cases: Empty list, single node, or no rotation needed
    if head == null or head.next == null or k == 0:
        return head
        
    // Step 1: Find the length of the list and the original tail node
    length = 1
    tail = head
    while tail.next != null:
        length = length + 1
        tail = tail.next
        
    // Step 2: Calculate effective rotations
    k_eff = k % length
    if k_eff == 0:
        return head // No rotation actually changes the list
        
    // Step 3: Make the list circular
    tail.next = head
    
    // Step 4: Find the new tail (N - k_eff - 1 steps from head)
    // (We subtract 1 because we are already standing on the head)
    steps_to_new_tail = length - k_eff - 1
    new_tail = head
    
    while steps_to_new_tail > 0:
        new_tail = new_tail.next
        steps_to_new_tail = steps_to_new_tail - 1
        
    // Step 5: Break the circle
    new_head = new_tail.next
    new_tail.next = null
    
    return new_head
```

## Complexity Analysis

- **Time Complexity:** $O(N)$. We traverse the list once to find the length and the tail ($O(N)$). We traverse it a second time (partially) to find the new tail ($O(N - K_{eff})$). The total operations scale strictly linearly with the number of nodes.
    
- **Space Complexity:** $O(1)$. We are only allocating a few pointers (`tail`, `new_tail`, `new_head`). No auxiliary data structures are used.
    

## Active Recall

**Q: Why is rotating a Linked List functionally different (and easier) than rotating an Array?**

**A:** In an Array, elements sit in contiguous memory; rotating requires physically moving data or executing a complex 3-step reversal algorithm. A Linked List's elements are connected by logical pointers. You can achieve rotation instantly by forming a loop (tail to head) and breaking the link at the exact point where the new tail should end.

**Q: Why must we calculate `K_eff = K % N` instead of just using `K` directly?**

**A:** Because `K` can be much larger than the length of the list ($N$). Rotating a list $N$ times results in the exact same original list. The modulo operation removes these redundant full cycles, giving us the minimal number of effective shifts required. It also prevents us from trying to traverse out of bounds when looking for the new tail.

**Q: After connecting `tail.next = head` to form a circular list, how do you mathematically determine the position of the new tail?**

**A:** When rotating right by $K_{eff}$, the last $K_{eff}$ nodes move to the front of the list. Therefore, the node that _precedes_ them—which is located at position $N - K_{eff}$—becomes the new tail.

**Q: Why would the Array reversal technique (Reverse All, Reverse First K, Reverse Last N-K) be a poor choice for a Linked List?**

**A:** While theoretically possible, reversing a Linked List is a destructive operation that requires careful tracking of `prev`, `curr`, and `next` pointers. Doing this three separate times, while also maintaining pointers to reconnect the sub-lists back together, introduces massive complexity and edge-case liabilities compared to the elegant "form a circle and break it" approach.
