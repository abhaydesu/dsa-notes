## Problem: Top K Frequent Elements (LeetCode 347)

**Problem Statement:** Given an integer array `nums` and an integer `k`, return the `k` most frequent elements. You may return the answer in any order.

_Your algorithm's time complexity must be better than $O(N \log N)$, where $N$ is the array's size._

**Example:**

- `nums = [1, 1, 1, 2, 2, 3]`
    
- `k = 2`
    
- **Output:** `[1, 2]` _(1 appears 3 times, 2 appears 2 times)._
    

## Why Not Sorting or Max-Heap?

### The Brute Force (Sorting)

1. Count frequencies using a Hash Map $\rightarrow O(N)$
    
2. Store map entries in an array and sort them by frequency descending $\rightarrow O(N \log N)$
    
3. Take the top $K$ elements.
    
    _Result:_ Fails the better-than-$O(N \log N)$ constraint.
    

### The Max-Heap Trap

1. Count frequencies in a Hash Map $\rightarrow O(N)$.
    
2. Push _every single_ unique element into a Max-Heap based on its frequency.
    
3. Pop $K$ times.
    
    _Result:_ If all elements in the array are unique, the Hash Map has size $N$. Pushing $N$ elements into a heap takes $O(N \log N)$ time. This also fails the constraint.
    

## The Optimal Solution: Min-Heap of Size K

**The Golden Rule of Heaps:**

- To find the Top $K$ **Smallest/Lowest** $\rightarrow$ Use a **Max-Heap**.
    
- To find the Top $K$ **Largest/Most Frequent** $\rightarrow$ Use a **Min-Heap**.
    

### The Logic (The "Teacher's Bench" Revisited)

You are looking for the $K$ elements with the _highest_ frequencies.

If you keep a bench (Min-Heap) of exactly size $K$, the element sitting at the very top of that heap is the **weakest** (lowest frequency) element currently on your bench.

1. Put the first $K$ unique elements from your Hash Map onto the bench.
    
2. For every subsequent element in the Hash Map:
    
    - Compare the incoming element's frequency to the frequency of the "weakest" benched element (the top of the Min-Heap).
        
    - **If the incoming frequency < top frequency:** The incoming element is even weaker than your weakest benched element. It has no chance of being in the Top $K$. **Ignore it.**
        
    - **If the incoming frequency > top frequency:** The incoming element is stronger. The current weakest element on the bench is no longer worthy of the Top $K$. **Pop the top, and Push the incoming element.**
        

By the time you finish iterating through the Hash Map, the $K$ elements surviving on the bench are guaranteed to be the $K$ most frequent elements.

## Structuring the Data in the Heap

A heap needs to know what it is sorting by. We need to store both the Frequency and the Element.

- **Data Structure:** `Pair<Frequency, Element>`
    
- By placing `Frequency` as the `first` value in the Pair, the Min-Heap will automatically sort by Frequency.
    

## Pseudo-code: Top K Frequent Elements

```cpp
function topKFrequent(nums, k):
    // Step 1: Build the Frequency Map
    freqMap = empty HashMap
    for num in nums:
        freqMap[num]++
        
    // Step 2: Create a Min-Heap of Pairs (Frequency, Element)
    minHeap = empty Min-Heap
    
    // Step 3: Iterate through the Hash Map
    count = 0
    for (element, frequency) in freqMap:
        
        // Push the first K elements blindly
        if count < k:
            minHeap.push( Pair(frequency, element) )
            count++
        else:
            // Compare incoming frequency with the weakest benched frequency
            weakest_freq = minHeap.top().first
            
            if frequency > weakest_freq:
                // Incoming is stronger. Evict the weakest and seat the incoming.
                minHeap.pop()
                minHeap.push( Pair(frequency, element) )
                
            // If incoming <= weakest_freq, do nothing (ignore)

    // Step 4: Extract the surviving elements from the bench
    result = empty Array
    while not minHeap.isEmpty():
        survivor = minHeap.top()
        result.push(survivor.second) // We only want the Element, not the frequency
        minHeap.pop()
        
    return result
```

## Complexity Analysis

- **Time Complexity:** $O(N \log K)$.
    
    - Building the Hash Map: $O(N)$.
        
    - Iterating over unique elements: Let $U$ be the number of unique elements ($U \le N$). For each element, we might push/pop to a heap of size $K$, which takes $O(\log K)$. Total heap operations: $O(U \log K) \approx O(N \log K)$.
        
    - Because $K \le N$, $O(N \log K)$ strictly outperforms $O(N \log N)$.
        
- **Space Complexity:** $O(N)$.
    
    - The Hash Map takes $O(N)$ space in the worst case (all elements unique).
        
    - The Heap takes $O(K)$ space.
        

## Active Recall

**Q: Why do we push `(Frequency, Element)` into the Min-Heap instead of `(Element, Frequency)`?**

**A:** Most standard priority queue implementations (like C++ and Python) sort pairs based on the first element, breaking ties with the second. Because our objective is to find the most _frequent_ elements, the heap must sort and compare based on frequency. Putting the frequency first allows the heap to automatically bubble the lowest frequency to the top.

**Q: When iterating past the first $K$ elements, under what exact condition do we pop the heap and push a new element?**

**A:** We pop and push ONLY if the incoming element's frequency is strictly **greater than** the frequency of the element at the top of the Min-Heap (`incoming.freq > minHeap.top().first`).

**Q: Why does pushing every unique element into a Max-Heap and popping $K$ times violate the problem's constraints?**

**A:** If all elements in the array `nums` are unique, the Hash Map will have size $N$. Pushing $N$ elements into a Max-Heap takes $O(N \log N)$ time. Popping $K$ times takes $O(K \log N)$ time. The total time $O(N \log N)$ violates the requirement that the algorithm must run _better_ than $O(N \log N)$.

**Q: If two elements have the exact same frequency, how does the Min-Heap handle the tie?**

**A:** Because we pass `(Frequency, Element)`, if the frequencies are tied, the heap will look at the `Element` to break the tie. In a Min-Heap, the smaller numeric element will bubble above the larger one. For this specific problem (LeetCode 347), the relative order of elements with the same frequency does not matter, so the default tie-breaking behavior is perfectly safe.
