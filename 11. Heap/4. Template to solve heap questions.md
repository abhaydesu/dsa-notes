## The Logical Proof: Min-Heap vs. Max-Heap

The biggest point of confusion in heaps is the inversion:

- To find the **Smallest / Bottom $K$**, we use a **Max-Heap**.
    
- To find the **Largest / Top $K$**, we use a **Min-Heap**.

### Why? (The Elimination Strategy)

Imagine an array of 10 elements, and you want to find the **Bottom 4 (Smallest 4)** elements.

Instead of trying to accurately select the smallest 4, we use the heap to **eliminate the largest 6**.

1. We maintain a "bench" (a Heap) of size $K$ (which is 4).
    
2. If we want the _smallest_ elements, we must identify and kick out elements that are too large.
    
3. How do we know if an element is too large to be in the Bottom 4?
    
    - If an element is strictly greater than 4 other elements, it sits at the 5th position (or worse) in a sorted array. It is mathematically impossible for it to be in the Bottom 4.
        
4. By using a **Max-Heap**, the absolute largest element on our bench is always at the top (`heap.top()`).
    
5. When a new element comes in, we push it onto the bench (size becomes 5). The Max-Heap automatically pushes the absolute largest of those 5 elements to the top.
    
6. That top element is now mathematically larger than 4 other elements. It cannot be in the Bottom 4. We instantly pop it (eliminate it).
    

This exact logic applies in reverse for the Top $K$ elements using a Min-Heap.

## The 7-Step Universal Heap Template

You can solve almost any standard Heap problem by blindly applying these 7 steps.

### Step 1: Identify the Pattern

Look for keywords in the problem statement:

- `Kth Largest`, `Kth Smallest`
    
- `Top K Frequent`, `K Closest to Origin`
    
- `Longest K`, `Shortest K`
    
- Any requirement to find the "best," "worst," "highest," or "lowest" subset of size $K$.
    

### Step 2: Identify the "Sorting Metric"

Ask yourself: _What exactly makes one element "better" or "worse" than another?_

- Is it their actual value?
    
- Is it their frequency? (Requires building a Hash Map first).
    
- Is it their distance? (Requires a mathematical helper function to calculate $x^2 + y^2$).
    

### Step 3: Define the Data Structure (Heap of Pairs)

Unless you are sorting purely by the element's raw value, you will need a Heap of Pairs.

- **Pair Structure:** `<Metric, Identifier>`
    
- `Metric`: The value from Step 2 (Frequency, Distance, etc.). The heap will sort based on this.
    
- `Identifier`: The original element or its array index (so you know _who_ the metric belongs to after popping).
    

### Step 4: Choose the Heap Type

- Looking for **Large / Top / Most / Furthest** $\rightarrow$ Build a **Min-Heap**.
    
- Looking for **Small / Bottom / Least / Closest** $\rightarrow$ Build a **Max-Heap**.
    
- _Note: Ensure you write the correct custom comparator if your pairs have specific tie-breaking rules._
    

### Step 5: Blindly Push the First $K$ Items

Do not use conditional logic for the first $K$ items. Iterate from $0$ to $K-1$ and blindly `push()` them into the heap. The heap will naturally arrange them.

### Step 6: The "Push & Pop" Loop for Remaining Items

For items from index $K$ to $N-1$:

1. Blindly `push()` the incoming item into the heap. (The heap size temporarily becomes $K+1$).
    
2. Immediately `pop()` the heap.
    
    _Why?_ The heap automatically surfaces the "worst" element out of the $K+1$ group to the top. Popping it eliminates it, returning the heap size strictly back to $K$ containing the "best" candidates seen so far.
    

### Step 7: Extract the Answer

The loop finishes. Your heap now contains exactly the $K$ elements you need.

Pop them out one by one, extract their `Identifier` (the `.second` value of the pair), and push them into your result array.

## Template in Action: K Closest Points to Origin (LeetCode 973)

Let's apply the 7 steps to a new problem: Find the $K$ points closest to `[0, 0]`.

1. **Pattern:** "K Closest" (Bottom K).
    
2. **Metric:** Distance from origin $\rightarrow x^2 + y^2$.
    
3. **Data Structure:** `Pair<Distance, Index>`.
    
4. **Heap Type:** Looking for _Closest_ (Smallest) $\rightarrow$ **Max-Heap**.
    
5. **Push First K:** Push distances of points $0$ to $K-1$.
    
6. **Push & Pop:** For points $K$ to $N-1$, `push()` new pair, then `pop()` the top.
    
7. **Extract:** The $K$ indices remaining are the closest points.
    

```cpp
vector<vector<int>> kClosest(vector<vector<int>>& points, int k) {
    // Step 4: Define Max-Heap (Default in C++)
    priority_queue<pair<int, int>> maxHeap; 
    
    // Step 5: Push first K
    for (int i = 0; i < k; i++) {
        int dist = (points[i][0] * points[i][0]) + (points[i][1] * points[i][1]); // Step 2
        maxHeap.push({dist, i}); // Step 3
    }
    
    // Step 6: Push & Pop remaining
    for (int i = k; i < points.size(); i++) {
        int dist = (points[i][0] * points[i][0]) + (points[i][1] * points[i][1]);
        maxHeap.push({dist, i});
        maxHeap.pop(); // Automatically evicts the point furthest away
    }
    
    // Step 7: Extract answers
    vector<vector<int>> result;
    while (!maxHeap.empty()) {
        int idx = maxHeap.top().second;
        result.push_back(points[idx]);
        maxHeap.pop();
    }
    
    return result;
}
```

## Active Recall

**Q: Why do we blindly `push()` and then immediately `pop()` in Step 6 instead of using an `if` statement to check if the incoming element is better than the top element?**

**A:** Blindly pushing and popping achieves the exact same mathematical result as the conditional check but with cleaner, error-free code. By pushing the new element, the heap (now size $K+1$) naturally bubbles the absolute worst element to the top. Popping immediately removes that worst element. If the incoming element was the worst, it gets popped right back out. If an older element was the worst, it gets evicted. It simplifies the logic entirely.

**Q: In Step 3, why is the Metric (Frequency, Distance) stored as the `first` element of the pair, and the Identifier (Index, Value) as the `second`?**

**A:** Priority Queues in languages like C++ and Python default to sorting tuples/pairs based on the first element. By placing the metric first, the heap automatically organizes the tree based on what we care about (the frequency or distance) without requiring a complex custom comparator.

**Q: If you are asked to find the $K$ items with the _Lowest Frequency_, what is your Metric, Data Structure, and Heap Type?**

**A:**

- Metric: Frequency (calculated via Hash Map).
    
- Data Structure: `Pair<Frequency, Value>`.
    
- Heap Type: **Max-Heap**. (You want the lowest/smallest, so you use a Max-Heap to constantly eliminate the ones with the highest frequencies).
