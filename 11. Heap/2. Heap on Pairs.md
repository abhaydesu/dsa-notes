> This lecture bridges the gap between theoretical Heap knowledge and practical implementation in complex interview problems. While basic heaps store single integers, many real-world problems (like "Top K Frequent Elements") require tracking two associated pieces of data (e.g., an element and its frequency). The instructor explains how to store complex data structures (Pairs) inside Priority Queues and, crucially, how to write custom comparators to teach the heap _how_ to sort them (e.g., sort by the second value first, and break ties using the first value).

## Concept: Why do we need Heaps of Pairs?

A standard heap knows how to sort integers because $5 > 3$.

But what if you need to find the "Top K most frequent names"? You must store both the `name` (String) and its `frequency` (Integer).

**Example Data:**

- `("Aman", 4)`
    
- `("Namita", 3)`
    
- `("Pratyush", 5)`
    

If you put these tuples/pairs into a heap, how does the heap know what makes one pair "greater" than another? Should it sort alphabetically by the name? Should it sort numerically by the frequency?

**The Tie-Breaker Problem:**

What if you have `("Aman", 4)` and `("Pratyush", 4)`? If the heap is sorting by frequency, they are equal. You must tell the heap how to break ties (e.g., "If frequencies are equal, sort alphabetically by name").

To do this, we use **Custom Comparators**.

## C++ Implementation (`std::priority_queue` with `std::pair`)

In C++, you can use `std::pair<T1, T2>`. By default, C++ sorts pairs by the `first` element. If the `first` elements are equal, it breaks ties using the `second` element.

**Trick for C++:** If you want to sort by frequency, always put the frequency as the `first` element of the pair!

## cmp function
```cpp
class Solution {
public:

struct cmp {
	bool operator() (pair<int, string>&a, pair<int, string>&b) {
		if (a.first != b.first) 
			return a.first > b.first; //min heap
		return a.second > b.second; // mean heap on second
	}
}

int mainFunction() {
	//declaration
	priority_queue<pair<int, string>, vector<pair<int, string>>, cmp> pq;

};
```

## Active Recall

**Q: Why do we need custom comparators or specific tuple ordering when storing complex data in a Heap?**

**A:** A heap must mathematically know how to compare two elements to bubble the "greatest" or "smallest" to the root. When storing pairs (e.g., Name and Frequency), the heap doesn't inherently know if you want to sort by the string or the integer. Furthermore, it needs strict rules on how to break ties if the primary sorting values are equal.

**Q: In C++ , if you insert a pair `(A, B)` into a heap, what is the default sorting behavior?**

**A:** Both languages default to sorting by the first element (`A`). If the first elements of two tuples are exactly equal, they use the second element (`B`) as a tie-breaker. Therefore, if you want to sort by frequency, the frequency must be placed in the first position `(Frequency, Value)`.
