## Problem: Reorganize String (LeetCode 767)

**Problem Statement:** Given a string `s`, rearrange the characters of `s` so that any two adjacent characters are not the same.

If possible, return any possible rearrangement. If not possible, return an empty string.

**Examples:**

- `s = "aab"` $\rightarrow$ **Output:** `"aba"`
    
- `s = "aaab"` $\rightarrow$ **Output:** `""` _(Impossible to separate all 'a's)._
    

## Intuition & Logic (The PT Teacher Analogy)

Imagine you are a PT Teacher seating students for an exam. You have 3 seats. You have 2 students from Class 'A' and 1 student from Class 'B'.

- **Rule:** Students from the same class cannot sit next to each other to prevent cheating.
    

**How do you assign seats?**

You must act **Greedily**. The class with the _most_ students is the hardest to accommodate because they require the most alternating seats.

1. Seat a Class 'A' student first. (Seats: `[A, _, _]`)
    
2. You cannot seat another Class 'A' student next to them. You _must_ switch to Class 'B'.
    
3. Seat a Class 'B' student. (Seats: `[A, B, _]`)
    
4. Now you can seat the remaining Class 'A' student. (Seats: `[A, B, A]`)
    

**The Core Rule:** Always try to seat the student belonging to the class with the **maximum remaining frequency**. If you leave the highest-frequency elements for the very end, you will run out of buffer elements to separate them.

## Why use a Max-Heap?

To constantly know which character has the "maximum remaining frequency" at any given moment, we need a data structure that provides the maximum element dynamically as frequencies change.

- **Data Structure:** `Max-Heap of Pairs <Frequency, Character>`
    

### The Execution Flow

1. **Build a Frequency Map:** Count how many times each character appears.
    
2. **Build a Max-Heap:** Push all `(Frequency, Character)` pairs into the Max-Heap.
    
3. **Construct the String:**
    
    - Pop the top character (the most frequent one).
        
    - **Can we place it?** Yes, if the result string is empty OR if the last character in the result string is _not_ this character.
        
    - **If we CAN place it:** Append it to the result. Decrement its frequency. If its frequency is still $> 0$, push it back into the heap.
        
    - **If we CANNOT place it (Rule Violation):**
        
        - We must pick the _second_ most frequent character.
            
        - If the heap is currently empty, it means we only have this one character left, but we can't place it. **Return `""` (Not Possible).**
            
        - Otherwise, pop the second character from the heap. Append it. Decrement its frequency. Push it back if frequency $> 0$.
            
        - _Crucial Step:_ Do not forget to push the original (first) character back into the heap completely untouched, as we couldn't place it this turn!
            

## Pseudo-code: Reorganize String

```cpp
function reorganizeString(s):
    // Step 1: Frequency Map
    freqMap = empty HashMap
    for char in s:
        freqMap[char]++
        
    // Step 2: Max-Heap of Pairs (Frequency, Character)
    maxHeap = empty Max-Heap
    for (char, freq) in freqMap:
        maxHeap.push(Pair(freq, char))
        
    // Step 3: Build the string greedily
    result = ""
    
    while not maxHeap.isEmpty():
        // Get the most frequent character
        p1 = maxHeap.top()
        maxHeap.pop()
        
        // Check if we can place it
        if result.length() == 0 or result.last_char() != p1.char:
            // Place it
            result.append(p1.char)
            p1.freq--
            
            // If there are still copies left, put it back in the heap
            if p1.freq > 0:
                maxHeap.push(p1)
                
        else:
            // We CANNOT place p1 because it matches the previous character.
            // We need the SECOND most frequent character.
            
            if maxHeap.isEmpty():
                // We have no other characters to act as a buffer. 
                return ""
                
            p2 = maxHeap.top()
            maxHeap.pop()
            
            // Place p2 instead
            result.append(p2.char)
            p2.freq--
            
            // Push p2 back if it still has copies
            if p2.freq > 0:
                maxHeap.push(p2)
                
            // IMPORTANT: Push p1 back into the heap UNTOUCHED
            maxHeap.push(p1)
            
    return result
```

## Complexity Analysis

- **Time Complexity:** $O(N \log K)$.
    
    - $N$ is the length of the string `s`.
        
    - $K$ is the number of unique characters (at most 26 for lowercase English letters).
        
    - Building the frequency map takes $O(N)$.
        
    - The `while` loop runs approximately $N$ times. Each push/pop operation on the heap takes $O(\log K)$ time. Since $K \le 26$, this is effectively $O(N)$.
        
- **Space Complexity:** $O(K)$. The Hash Map and the Max-Heap will store at most $K$ unique characters, which is $O(1)$ constant space since $K \le 26$.
    

## Active Recall

**Q: Why do we prioritize placing the character with the highest frequency?**

**A:** If we don't clear out the highest-frequency characters early, we will be left with a large cluster of the same character at the end of the string. Since we have run out of other characters to act as "buffers," we will be forced to place identical characters next to each other, failing the problem's condition.

**Q: In the "else" block (when the most frequent character matches the last placed character), why must we check `if maxHeap.isEmpty()` before grabbing the second character?**

**A:** Because if the heap is empty, there is no "second" character available to act as a buffer. This mathematically proves that it is impossible to reorganize the string (e.g., trying to reorganize `"aaab"`), and we must immediately return an empty string.

**Q: After placing the second most frequent character (`p2`), why is it critical to push the first character (`p1`) back into the heap untouched?**

**A:** We pulled `p1` out of the heap to inspect it, but we couldn't place it because it violated the adjacency rule. Since we didn't use it, its frequency hasn't decreased. We must put it back into the heap so it can be considered for the _next_ position in the string, where it will likely be legally placed after the `p2` buffer.
