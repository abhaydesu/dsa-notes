##  Problem 1: Find the Starting Point of a Cycle

**Problem Statement:** Given a linked list that contains a cycle, return the node where the cycle begins. (LeetCode 142: Linked List Cycle II).

###  Intuition & Mathematical Proof

When the `slow` and `fast` pointers meet, they are inside the cycle. But _where_ does the cycle start? Let's break down the distances traveled by both pointers at the exact moment they meet.

**Variables:**

- $L_1$: Distance (number of nodes) from the `head` to the `entry point` of the cycle.
- $L_2$: Distance from the `entry point` to the `meeting point` where slow and fast intersect.
- $C$: Total length (number of nodes) of the cycle.
- $C - L_2$: The remaining distance from the `meeting point` back to the `entry point`.

**Distance Traveled:**

- **Slow pointer:** Traveled $L_1$ to reach the cycle, then $L_2$ to reach the meeting point.
    - `Distance_Slow` $= L_1 + L_2$
- **Fast pointer:** Traveled $L_1$ to reach the cycle, looped around the cycle $n$ times ($n \times C$), and then traveled $L_2$ to meet the slow pointer.
    - `Distance_Fast` $= L_1 + nC + L_2$

**The Core Equation:**

Since the `fast` pointer moves exactly twice as fast as the `slow` pointer, the distance it traveled is exactly twice the distance of the `slow` pointer in the same amount of time.

$$Distance_{Fast} = 2 \times Distance_{Slow}$$

$$L_1 + nC + L_2 = 2 \times (L_1 + L_2)$$

$$L_1 + nC + L_2 = 2L_1 + 2L_2$$

$$nC = L_1 + L_2$$

$$L_1 = nC - L_2$$

**What does $L_1 = nC - L_2$ mean?**

$L_1$ is the distance from the `head` to the `entry point`.

$nC - L_2$ (which simplifies conceptually to $C - L_2$) is the distance from the `meeting point` to the `entry point`.

_This proves that the distance from the `head` to the `entry point` is exactly the same as the distance from the `meeting point` to the `entry point`._

###  The Algorithm

1. Detect the cycle using standard Slow & Fast pointers.
2. Once they meet, **do not reset both**. Move _only_ the `slow` pointer back to the `head`. Leave the `fast` pointer at the meeting point.
3. Move **both** pointers at the **same speed** (1 step at a time).
4. The exact node where they collide again is the `entry point` of the cycle.

###  Pseudo-code: Starting Point of Cycle
```cpp
function detectCycle(head):
    if head == null or head.next == null:
        return null
        
    slow = head
    fast = head
    has_cycle = false
    
    // Step 1: Detect if a cycle exists
    while fast != null and fast.next != null:
        slow = slow.next
        fast = fast.next.next
        
        if slow == fast:
            has_cycle = true
            break
            
    // If no cycle, return null
    if has_cycle == false:
        return null
        
    // Step 2: Find the starting point
    slow = head // Reset slow to the start
    
    // Move both at the SAME speed until they meet
    while slow != fast:
        slow = slow.next
        fast = fast.next
        
    // Both pointers now point to the entry node of the cycle
    return slow
```

##  Problem 2: Middle of the Linked List

**Problem Statement:** Given the `head` of a singly linked list, return the middle node of the linked list. (LeetCode 876).

###  Intuition (The Race Analogy)

Imagine a straight road that is 8km long.

- You run at 4 km/h (Slow pointer).
- Your friend runs at 8 km/h (Fast pointer).
    If your friend reaches the end of the road (8km) in 1 hour, where will you be in that exact same 1 hour? You will have traveled exactly half the distance (4km). You will be standing exactly in the middle of the road.

**Why use Slow & Fast?**

The naive approach is to traverse the list once to count the total nodes ($N$), and then traverse it again up to $N/2$. This requires **two passes**. Using the Slow & Fast pointer technique finds the middle in a **single pass**.

### Pseudo-code: Middle of the Linked List
```cpp
function middleNode(head):
    slow = head
    fast = head
    
    // Fast moves 2x speed. 
    // When fast reaches the end, slow is exactly at the halfway mark.
    while fast != null and fast.next != null:
        slow = slow.next
        fast = fast.next.next
        
    return slow
```

_(External Note for edge cases: If the linked list has an even number of nodes, e.g., 6 nodes, there are two middle nodes (node 3 and node 4). The pseudo-code above will return the **second** middle node (node 4), which is the standard requirement for LeetCode 876. If a problem asks for the **first** middle node, you initialize `fast = head.next` instead of `head`)._

## Complexity Analysis

**For Both Problems:**

- **Time Complexity:** $O(N)$.
    - _Cycle Start:_ Detecting the cycle takes at most $O(N)$. Moving `slow` back to the head and finding the intersection takes another $O(N)$ operations. Total is strictly linear.
    - _Middle Node:_ `fast` reaches the end in exactly $N/2$ iterations. Strictly linear.
- **Space Complexity:** $O(1)$. We only use two pointers, requiring constant extra memory regardless of the Linked List size.

##  Active Recall

**Q: In the mathematical proof for finding the start of the cycle, what is the physical meaning of the equation $L_1 = C - L_2$?**
**A:** $L_1$ is the distance from the head of the linked list to the start of the cycle. $C - L_2$ is the distance from the point where the slow and fast pointers collided, moving forward to the start of the cycle. The equation proves these two distances are identical.

**Q: Once `slow` and `fast` meet in a cycle, what are the exact next steps to find the node where the cycle begins?**
**A:** Move the `slow` pointer back to the `head` of the linked list. Keep the `fast` pointer at the collision node. Change the `fast` pointer's speed so that both `slow` and `fast` move exactly one step at a time. The node where they collide again is the start of the cycle.

**Q: Why does the "Slow and Fast Pointer" technique find the middle of a linked list more efficiently than the naive counting method?**
**A:** The naive method requires two full passes over the data (one to count total length, one to travel to half the length). The Slow and Fast pointer technique requires only a single pass, as the slow pointer naturally lands on the middle node the moment the fast pointer reaches the end.

**Q: If a linked list has an EVEN number of nodes (e.g., 4 nodes: 1->2->3->4), the standard `middleNode` algorithm (`slow=head`, `fast=head`) returns which node as the middle?**
**A:** It returns the second middle node (Node 3).
