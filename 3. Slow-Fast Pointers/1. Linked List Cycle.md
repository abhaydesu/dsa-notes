## Pseudo-code: Detect a Cycle (LeetCode 141)

```cpp
function hasCycle(head):
    // Edge case: Empty list
    if head == null:
        return false
        
    // Step 1: Both pointers start at the head
    slow = head
    fast = head
    
    // Step 2: Traverse the list
    // WARNING: Must check fast != null AND fast.next != null 
    // to prevent Null Reference Exceptions when moving fast by two steps
    while fast != null and fast.next != null:
        
        // Move slow pointer by 1 step
        slow = slow.next
        
        // Move fast pointer by 2 steps
        fast = fast.next.next
        
        // Step 3: Check for collision
        if slow == fast:
            return true // Cycle detected!
            
    // Step 4: Fast pointer reached the end of the list
    return false // No cycle
```

###  Critical Warning: Preventing Crashes (Null Reference Errors)

When moving the `fast` pointer two steps (`fast.next.next`), you are chaining operations.

If `fast` is `NULL`, calling `fast.next` crashes the program.

If `fast.next` is `NULL` (it's the last node), calling `fast.next.next` crashes the program.

**The Rule for Safely writing the `while` condition:**

You must check every element in the chain _in order_ before calling `.next` on it.

- _Correct:_ `while (fast != null and fast.next != null)`
- _Wrong:_ `while (fast.next != null and fast != null)` $\rightarrow$ Because the computer evaluates left to right. If `fast` is null, evaluating `fast.next` first will crash it.
- _Wrong:_ `while (fast != null and fast.next.next != null)` $\rightarrow$ Skips checking `fast.next`, causing a crash if `fast.next` is null.

_Note: We do not strictly need to check `slow != null` in the while loop condition because `fast` is always ahead of `slow`. If `fast` safely navigates the list, `slow` is guaranteed to be safe behind it._

##  Complexity Analysis

- **Time Complexity:** $O(N)$.
    - If there is no cycle, the `fast` pointer reaches the end in $N/2$ steps.
    - If there is a cycle, the `fast` pointer catches the `slow` pointer in at most one loop of the cycle. Overall, it runs in linear time.
- **Space Complexity:** $O(1)$. We are only using two pointer variables, regardless of the size of the Linked List.
